Troubleshooting Upgrade to Windows XPe

Purpose

This document provides information for recovering from a failure of the Windows XP operating system upgrade.

When to Perform

Use this information to recover from an issue with Windows XPe V1.3 or Software V4.x upgrade.

Failures and Recovery Procedures for V1.3

Note:
  • The tool displays a number of step completion messages in the following format:

    Step 8: Complete. The system has shutdown the instrument software

    These messages provide a record of how far the upgrade has progressed through the current phase. Begin troubleshooting with any incomplete step message such as:

    Step 8: Not Complete. The system has not shutdown the instrument software

  • An overview of the upgrade process can be found in the Software Chapter, Operating Principles Section, OP - Windows NT to XPe Upgrade v1.3.

This is an example of the print outs that occur during the XP Upgrade: NT to XPe Print Outs.PDF

Phase 1 - NT to XPe

Error Description Possible Resolution
Step 3: Establish connection to the instrument. The software uses the IP Address stored in the registry to find the AU. Ensure that the address specified in the registry is the true address of the AU (ping the AU).
Note: Refer to the Software: Pinging AU procedure.
If the instrument pings successfully, then verify that the computer name is unique (important for instruments on PROService or automation).
  1. Select [Start] > Run, and then enter \\192.168.2.4\c$ to connect to the AU.
  2. If unable to connect, then select [Start] > Settings > Control Panel > Network and verify that the computer name is unique.
    • The computer name should be the AU serial number.
    • If the computer name is not unique, change the computer name, restart the PC, and attempt the upgrade again.
Note: If there is conflicting computer name on the network, the XP upgrade does not complete.
Step 6: Confirm that all the data has been sent from the instrument. They system detected unsent critical events on the AU.
  • If there are jammed critical events on the AU, then clear the jammed event.
    Note: Refer to Software: Clearing Jammed Critical Events the procedure.
  • If there are no jammed critical events on the AU, then delete the CommCE.dat file on the AU.
Step 7: Detected that the system is ready for shutdown. The system is ready to reboot; however, the system mode is something other than Ready or Not Ready. Verify the system is no longer running and there are no jammed critical events.
  • If there are jammed critical events on the AU, then clear the jammed event.
    Note: Refer to Software: Clearing Jammed Critical Events the procedure.
  • If there are no jammed critical events on the AU, then delete the CommCE.dat file on the AU.
Step 13: Did not find sufficient space on the instrument hard drive. To copy over the new XP files and have some extra space to do the upgrade, at least 1500 MB must be available on the AU. If more than 1500 MB is not available, then delete files from the hard drive.
Note: Refer to the Software: Deleting Files When Hard Drive Is Full procedure.
Step 17: The system has confirmed OS upgrade to Windows XP on the AU. The software verifies that the AU has successfully upgraded the AU. The AU IP address is now 192.168.2.2.
Caution: If Phase 2 is forced, then the registry commands must be completed or a service call will be required to reset the password and fix Desktop Sharing.
If this step fails, then reboot the AU, give the instrument 5 minutes to complete the XPe upgrade, put back in disk 1 and start the upgrade over.
If the software load fails stating that the instrument is already on XP, then force the phase 2 upgrade by:
  1. Select the [Start] > Run.
  2. Enter \upgrade.exe 2.
  3. Continue with the XP upgrade following the on-screen prompts or the installation instructions (including loading system software).
  4. Complete these final steps to ensure that remote desktop sharing works.
    1. Insert CD 1 of the OS upgrade into the CD Drive.
    2. Select Exit when the window displays.
    3. Select the Windows key, select Run, and then enter CMD.
    4. At the command prompt, enter:
      • D:\psexec.exe \\192.168.2.4 regedit /s C:\AU\SetupAURegistry.reg
      • D:\psexec.exe \\192.168.2.4 NET ACCOUNTS /maxpwage:unlimited
  5. Close the command prompt.
Note:
  • The IP address should be at 2.4. If an error occurs using the IP address at 2.4, then check the registry to confirm the AU IP address.
  • These commands or executable configures the AU to allow remote desktop sharing and sets the password to never expire on the AU.

Phase 2 - NT to XPe

Error Description Possible Resolution
Step 2: Establish connection to the instrument. The system software cannot communicate with the AU. Attempt to ping the AU using the IP address 192.168.2.2 (the original IP address has not been set).
Note: If the system is being upgraded to be part of an integrated platform, then verify that the UCTA network cable is unplugged. The UCTA network adaptor is set to a default of 192.168.2.2 creating a conflict when plugged in.
Steps 11 and 12: Did not find sufficient space on either the instrument or console. A complete backup of the DRW and DRO folders cannot be performed because of insufficient space on the console or AU hard drives.
Note: Each of these sizes is increased by 10% to ensure all files are copied.
Delete files from the hard drive.
Note: Refer to the Software: Deleting Files When Hard Drive Is Full procedure.
After deleting files, restart the process by inserting CD 1.
Step 16: Failed to detect Upgrade CD 2 in CD-Rom Drive

If you select OK and the system asks the question again, then give it a few more seconds. The CD-ROM might still be trying to read the disk.

Phase 3 - NT to XPe

Error Description Possible Resolution
Phase 3 did not begin. The reimage of the PC did not begin correctly.
  1. Power down the PC.
  2. Remove the USB backup device, if there is one.
  3. Restart the PC and continue the upgrade.
  4. If the upgrade boots to an A:\ prompt, then the upgrade process is unable to detect the PC type.
If PC is Then
Blue and Orange dot Type bluedot.bat and select Enter.
DTX no dot Type nodot.bat and select Enter

Verifying DMI pool data.

Log file is at A:\errorlog.log.

Hard drive failure.
  1. Remove any floppy disks or flash drives.
  2. Reboot the PC.
  3. Check whether other devices such as the keyboard or bar code scanner Y-cable are interfering with PC startup.
  4. Reseat the hard drive ribbon and power cable.
  5. If the issue continues, then order a Windows NT hard drive or Windows NT PC.
    Note: As long as Phase 2 completed successfully, the database will be transferred when the XP conversion is performed on the new hard drive.
  6. Install the new hard drive.
  7. Insert Disk 1 to start the upgrade process.
  8. Continue with the XP upgrade following the on-screen prompts or the installation instructions (including loading system software).

Phase 4 - NT to XPe

Error Description Possible Resolution
Step 2: Connected to the instrument at. The system software cannot communicate with the AU. Attempt to ping the AU using the IP address 192.168.2.2 (the original IP address has not been set).
Step 12: Restored instrument location to: The upgrade process sends commands to the AU updating all the network adapters to the original IP address of the AU. If the system is being upgraded to be part of an integrated platform, then verify that the UCTA network cable is unplugged. The UCTA network adaptor is set to a default of 192.168.2.2 creating a conflict when plugged in.
Step 15: Restored Windows computer network settings. The upgrade process updates the second network connection (PROService RMS) to default. The software attempts to restore the NIC address. If this fails, the IP addresses be at the default settings. Verify that the computer name is unique (important for instruments on PROService or automation).
  1. Verify all connections to the back of the console and reconfigure the IP addresses.
  2. Select [Start] > Settings > Control Panel > Network and verify that the computer name is unique.
    • The computer name should be the AU serial number.
    • If the computer name is not unique, change the computer name.
  3. Restart the PC and attempt the upgrade again.

Phase 5 - NT to XPe

Error Description Possible Resolution
No troubleshooting is associated with this phase.
