Troubleshooting AU and UI Communication Loss

Purpose

This document provides information for troubleshooting communication loss between the analytical unit and the user interface.

When to Perform

Perform troubleshooting when these errors occur.

Error When
Connection to the instrument is unavailable. Attempting to initialize or use some of the UI functions.
No communications with the AU. Attempting to initialize.
Cannot find specific.ini on the instrument. Launching the UI.
Socket Connect Failed (Event Log message). In the UI, communication is lost
Idle Timer Expired. No Communication Received from instrument. Launching the UI.
The instrument status at the top left corner of the user interface is red with no text, is stuck configuring parameters, or does not transition into the Ready or Not Ready mode. Launching the UI.

Common Causes

The most common causes of AU communication loss are:
  • AU software has a problem.
  • AU hard drive has an issue.
  • Network hardware is disconnected or broken.
  • AU has lost power.

Troubleshooting Procedures

Table 91: Windows XP System with Software 5.2 and below
Procedure Action Steps
Communicate with the AU Communicate with the analytical unit using Remote Desktop Sharing.
  1. Select Start > Programs  > Administrative Tools > Remote Desktop Sharing to AU PC.

    If there is no connection available, then proceed to Ping the AU troubleshooting procedure.

    Note:
    • Refer to the Software: Using Desktop Sharing Between Console PC and AU procedure. In desktop sharing, the default AU IP address is 192.168.2.4.
    • If the AU software is not loaded yet in a new installation, then the AU address is 192.168.2.2 and the default share will not connect. Instead select Start > Programs > Accessories > Communications > Remote Desktop Sharing. Connect to the AU at address 192.168.2.2, user name: user, and password: tech.
  2. In the connection to the AU, right-click on the AuObj.exe icon (small Y) on the bottom right corner of the desktop.
  3. Select Exit from the menu.
  4. Double-click on the AuObj.exe shortcut (large Y) on the left edge of the Windows desktop.
  5. If the machine control program launches incompletely (remains as a blank gray window) or does not launch, then:
    • Ensure that the instrument pressure comes up to a minimum of 32 psi and that the air bleed valve operates.
      Note: Adequate pressure is required for the Machine Control program to launch fully. A pressure monitor icon is located near the clock at the lower right corner of the AU display. Also check for failure of the air bleed valve or air pressure sensor.
    • Press [Ctrl]+[Alt]+[Del]. Select Task Manager from the windows security popup. End the AuObj.exe process, and then start AuObj.exe again (large Y-shaped icon).
  6. If the machine control program launches, then select the Toss or Touch ALL & Toss options when the system initialization window is displayed on top of the Machine Control window.
    Note:
    • Select Wait to allow more time to select options.
    • Select Continue when selections are complete.


  7. If the AUObj.exe machine control program launches, but there are jammed critical events, then clear jammed communications.
    Note: Refer to the Software: Clearing Jammed Critical Events procedure.
  8. If machine control program freezes or exits (crashes) when started, do the following.
    1. If the error posted is Error from CheckOutHardware Bad MCC board = 0 Error Code =21 (MCC=0), then check that:
      • Two main cover interlock switches, and the SPU closed switch are engaged (MCC PCBs and fans have power).
      • MCC power switch on the Power Distribution PCB is on and 24 V is on the three cover switches.
      • Main power supply has power (three 24-V outputs) at the test points on the front edge of the main power distribution module.
      • CPU CMOS settings on the AU CPU PCB are correct.
        Note: Refer to the Config - CMOS Setup document.
      • Swap the MCC0 PCB with another MCC PCB. It might be defective.
    2. Rename the AU folder and reload the AU software.
      1. Right-click and exit the auobj, tmon, and pmon programs or icons near the clock at the bottom right corner of the display.
        Note: It might be necessary to use Task Manager to end these programs (and others) to allow the AU folder to be renamed.
      2. Browse to the C:\ drive on the AU and rename the AU folder.
      3. Browse to the C:\AUinstall folder and select setup.exe to reload the AU software (the AU reboots).
      4. Close the Not Commissioned and other error messages following the AU reboot.
      5. Copy and paste the specific.ini file from the renamed AU folder into the AU folder created by the software installation.
      6. Double-click on the AuObj.exe shortcut (large Y) on the left edge of the Windows desktop to launch the auobj.exe program.
    3. Check for corrupt AU NVRAM by simulating it.
      1. Open the C:\AU\specific.in file on the AU using Wordpad.
      2. Change simulate NVRAM =no to =yes.
      3. Exit Wordpad and select to Save when exiting (there is no substrate supply when simulated).
      4. Launch the AUObj.exe program (large Y).
      • If simulating NVRAM is successful, then
        1. Exit the AUObj.exe machine control program (right-click the small Y icon and select Exit).
        2. Change simulate NVRAM =yes to =no to undo the simulation in specific.ini.
        3. Exit Wordpad and select to Save when exiting.
        4. Record the TotalTestSeconds and TestNumber using the NVMEditor program.
          Note: Refer to the Software: Modifying Run Time and Test Counts from Database procedure.
        5. Select Start  > Run, type auobj.exe /clean, and then select Enter to erase the NVRAM.
        6. Launch the AUObj.exe machine control program (large Y).
        7. Restore the TotalTestSeconds and TestNumber using the NVMEditor program.
          Note: Refer to the Software: Modifying Run Time and Test Counts from Database procedure.
        8. Load two new bottles of substrate, and initialize with remap selected to restore the instrument supplies memory.
      • If simulating NVRAM is not successful,
        1. Undo the simulation in specific.ini (change simulate NVRAM =yes to =no).
        2. Select Start > Run and enter auobj.exe to launch the machine control program.
          Note: If the machine control launches without error, then the AU desktop shortcut might be corrupt. Replace the desktop shortcut and the auobj.exe shortcut located in the instrument startup folder.
    4. Check communication to the sample probe RF level sense PCB.
      Note: Lack of communication to the sample probe RF level sense PCB can halt the launch of the machine control program.
      1. Confirm connection of the RF level sense PCB and sample pipettor I/F PCB ribbon cables.
      2. Confirm that 5 V local is present on the sample pipettor I/F PCB and on the RF level sense PCB.
Ping the AU Ping the analytical unit to check for communication between the AU and the console PC.
Note: Refer to the Software: Pinging AU procedure.
  1. On the console, select [Windows] > Start > Run.
  2. Enter cmd on the Open line, and select OK.
  3. In the CMD window, enter ping 192.168.2.4, and press [Enter].
    Note:
    • The instrument IP address is normally 192.168.2.2 for a new AU, and 192.168.2.4 for an installed AU.
    • The console PC IP address is normally 192.168.2.1 for a new PC and 192.168.2.3 for an installed PC.
    • If not successful at 2.4 or 2.2, try pinging 2.1 through 2.10.
  4. Verify that the PC receives a reply from the AU.
    • A No Reply error message indicates that:
      • The connected port on the AU has an unexpected IP address, but the connection to the AU network hub is OK.
      • The network cable is disconnected from the AU CPU PCB or is connected to the wrong port on the AU CPU PCB.
    • A Destination Host Unreachable error message indicates that:
      • An incorrect IP address was entered (misspelled).
      • The network cable is connected to the wrong port on the back of the PC or the back of the AU.
      • The network connection on the PC is near the mouse connector. The other network ports on the PC are for the RMS and LAS and do not work for the AU connection.
      • The network cable between the PC and the AU is disconnected.
      • The AU network hub has no power.
    Note:
    • If for some reason, possibly during an initial installation, the AU and PC get the same IP address, then there is a network conflict and the network port is disabled. To resolve the conflict, change the PC IP address to 2.1, reboot the instrument and the PC, then ping addresses 1 to10 again. Refer to Configuring Network Settings in the Peripherals: Replacing Console PC or PC Hard Drive procedure.
    • The rear of the DxI instrument can have two network connectors. The connectors are identified as PC and UCTA. The UCTA port does connect to the AU network hub and has an incompatible IP address. If unsure of the port, then try both, or connect the PC to the spare port on the underside of the SPU, or connect directly to the AU hub.
Check network connections Check the network connections and hardware.
  1. Confirm that the network cable is connected to the port near the keyboard connector on the rear of the console PC.
  2. Verify that the network cable is plugged into the correct port (labeled PC) on the rear of the AU.
    Note: Newer DxIs have two network ports on the back of the instrument. Confirm that the network cable connecting the PC to the AU is not plugged into the port labeled UCTA. The UCTA cable connects to the integrated system network hub.
  3. Check the network hub behind the upper left card cage. Confirm that a green LED is lit for the power, PC, and CPU connections.
    Note:
    • The top port (4 or 5) is normally for the PC cable from the back of the AU. The next port is for the CPU PCB cable. The next port is a spare cable going to the bottom of the SPU that normally is not active.
    • If the PC cable is disconnected, the LED for the PC connection goes out. Disconnecting and connecting the PC cable helps identify the connection.
    • The network cable connected to the AU CPU PCB can be dislodged while servicing the sample pump.


Connect the monitor to the AU Connect the monitor, keyboard, and mouse to the AU.
  1. Connect a monitor to the AU monitor extension cable located behind the upper left card cage. Confirm that Windows has launched.
  2. Select Start > Settings > Network Connections.
  3. In the Network Connections window, right-click on the Local Area Connection that has the status Connected or Limited or no connectivity.
  4. Select Properties.
  5. In the General tab, select Internet Protocol (TCP/IP) > Properties.
  6. Select the Use the following IP address option.
  7. Change the IP address to 192.168.2.4 and enter subnet mask 255.255.255.0.
  8. Select OK > No to the TCP/IP pop-up Close, and No to the Restart option.
  9. In the Network Connections window, right-click on Local Area Connection 2, and then set the IP address to 134.217.96.188.
    Note:
    • You might have to cycle the instrument power off and on to enable the keyboard and mouse function.
    • Local Area Connection 2 is used only for integrated systems.
  10. If Windows is not present on the AU, then for a:
    • HDD boot error: Check the 5 V DC and 12-V DC power to the AU hard drive and AU CPU PCB.
    • Blank display: Reboot the AU. If there is still no display, check the voltages on the CPU Power Distribution PCB test points, and remove connectors or other PCBs (COMC, DAQC) from the upper left card cage. These can affect the CPU PCB boot. Possibly replace the CPU PCB.
  11. If the AU Windows boot halts with any of these errors:
    • Press F1 to resume.
    • Exception error: Explorer.exe
    • Error loading shell32 - Invalid access to memory location.
    • Debug Assertion Failed: Tcontrol.exe - Line 214.
    • Error from CheckOutHardware Bad MCC board = 0 Error Code =21. (Open main cover switches, SPU closed switch, or loss of 24-V DC power to the MCC PCBs can cause MCC0 errors.)
    The AU CPU CMOS settings might be incorrect. Confirm all the CPU PCB CMOS settings. Expect to see Halt on - No Errors and many other incorrect settings.
    Note: Refer to the Config - CMOS Setup document.
    If the CMOS has reset to the defaults, then schedule CPU PCB replacement. The battery on the CPU PCB is weak, and the CMOS might reset again when AU power is lost.
Check Windows settings
  1. Select Start > Settings > Control Panel > Security Center > Windows Firewall > General and confirm that the Windows Firewall is Off.
    Note: The firewall blocks messages between the AU and the PC so that the UI appears not to communicate.
  2. Select Start > Settings > Control Panel > User Accounts.
  3. Select user > Change my password.
  4. Type in the current Windows password: tech, then type tech for the new password and the confirmed new password. Select Change password.
    Note:
    • The current password should be tech, but the operator might have changed this password. To change the password, the current password must be known. To recover from an unknown password, you might have to replace or reimage the PC hard drive.
    • For Windows XP PCs, the instrument replies to a ping and the AU desktop can be shared using Desktop Sharing. However, in order for the UI software to communicate with the AU, the Windows PC password must be set to tech.
    • The tech password configuration also applies to the AU with the added symptom of XP desktop sharing failing to log in. Refer to the Ref - Password Quick Reference document for details.
  5. Reboot the PC to restart the software.

Connect the monitor to the AU Connect the monitor, keyboard, and mouse to the AU.
  1. Turn off the AU.
  2. Connect the monitor, keyboard, and mouse to the AU extension cable located behind the upper left card cage.
  3. Reboot the AU and confirm that Windows has launched.
  4. Check IP addresses on the AU.
    1. To show the network port status, press Windows key, type network connections, select Settings, and click on View Network Connections.
      Note: There are only two network connections on the AU side. If connections are swapped, correctly reconnect the network cables on the CPU PCB.
      • Local Network Connection is the AU connection.
      • Local Nework Connection 2 is the UCTA connection.
    2. Verify the IP addresses and settings.
      • Right click on Local Area Connection, choose Properties, select Internet Protocol Version 4 (TCP/IPv4) and choose Properties.
        • IP address is 192.168.2.4
        • Subnet Mask is 255.255.255.0
      • Right click on Local Area Connection 2, choose Properties, select Internet Protocol Version 4 (TCP/IPv4) and choose Properties.
        • IP address is 134.217.96.188
        • Subnet Mask is 255.255.255.0
    3. Change the network IP addresses if needed.
      • Right click on Local Area Connection, choose Properties, select Internet Protocol Version 4 (TCP/IPv4) and choose Properties.
        • Enter the AU IP address 192.168.2.4 and the Subnet Mask 255.255.255.0
        • Enter the UCTA IP address 134.217.96.188 and the Subnet Mask 255.255.255.0
        Note: If this is an integrated DxI, then change the Local Area Connect 2 IP address to the following:
        • DxI 1 IP 134.217.96.188
        • DxI 2 IP 134.217.96.189
        • DxI 3 IP 134.217.96.190
        • DxI 4 IP 134.217.96.191
      • Click OK to save the change.
      • Click Close to exit.
  5. If Windows is not present on the AU, then for a:
    • HDD boot error: Check the 5 V DC and 12-V DC power to the AU hard drive and AU CPU PCB.
    • Blank display: Reboot the AU. If there is still no display, check the voltages on the CPU Power Distribution PCB test points, and remove connectors or other PCBs (COMC, DAQC) from the upper left card cage. These can affect the CPU PCB boot. Possibly replace the CPU PCB.
  6. If the AU Windows boot halts with any of these errors:
    • Press F1 to resume.
    • Exception error: Explorer.exe or Explorer Module
    • Error loading shell32 - Invalid access to memory location.
    • Debug Assertion Failed: Tcontrol.exe or SysTemperature Module - Line 214.
    • Error from CheckOutHardware Bad MCC board = 0 Error Code =21. (Open main cover switches, SPU closed switch, or loss of 24-V DC power to the MCC PCBs can cause MCC0 errors.)

    The AU CPU CMOS settings might be incorrect. Confirm all the CPU PCB CMOS settings. Expect to see Halt on - No Errors and many other incorrect settings. Refer to the Config - CMOS Setup document.

Check Windows settings
Check Security Settings.
Note: Windows Firewall must be turned off in order for the UI software to communicate with the AU.
  1. Press Windows key, select the Control Panel icon or type control panel and open the program.
  2. Open Windows Firewall program and verify Windows Firewall state is off.
    Note: If the firewall is off, then both Private networks and Guest or public networks have a red security image icon with an X inside the icon.
  3. If Windows Firewall is turned on, then click on Turn Windows Firewall on or off on the left side of the Windows Firewall box.
    Note: If the firewall is on, then both Private networks and Guest or public networks have a green security image icon with a check mark inside the icon.
  4. Check on Turn off Windows Firewall for both Private networks and Guest or public networks, and select Ok.
Check User Accounts Settings.
Note: The default account is user and the account password is tech. If password was changed, then the UI won't communicate with the AU.
  1. Press Windows key, select the Control Panel icon or type control panel and open the program.
  2. Open User Accounts program and select Make changes to my account in PC settings on the right hand side.
  3. Select Users > Change your password.
    Note:
    • The current password should be tech, but the operator might have changed this password. To change the password, the current password must be known. To recover from an unknown password, you might have to replace or reimage the PC hard drive.
    • For Windows 8 PCs, the instrument replies to a ping and the AU desktop can be shared using Remote Desktop Connection. However, in order for the UI software to communicate with the AU, the Windows PC password must be set to tech.
    • The tech password configuration also applies to the AU with the added symptom of Windows 8 desktop sharing failing to log in. Refer to the Ref - Password Quick Reference document for details.
  4. Type in the Current password: tech, and click Next.
  5. Type in the New password: tech, and Reenter password: tech, and Password hint: default, and click Next.
  6. Click Finish to save the changes.
  7. Press Windows key and click on desktop icon to get back to User Accounts box and click X on the upper right corner to exit.
  8. Reboot the PC to restart the software.
    Note: When rebooting the Privacy & Security compliant Windows 8 or Windows 10 PC, you must enter security password "Access2Admin" when prompted to launch Windows.
