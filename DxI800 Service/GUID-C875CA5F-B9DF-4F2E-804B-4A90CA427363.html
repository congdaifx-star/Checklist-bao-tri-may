Troubleshooting Communication Data

RS-232 Message Structure

This table describes the major components, ASCII characters, and structure of the RS-232 messages between the DxI and the connection unit.

ASCII Characters Description Example
<STX>1 The <STX> character starts all messages. A single digit (usually 1) always follow <STX> to indicate replicate transmissions (2 to 7, which are rarely necessary). <STX>1<0x83>8828146990<US>1NNB7<ETX>
AA<ETX> The <ETX> character ends all messages. A 2-digit checksum (hexadecimal) always precedes <ETX>. <STX>1<0x83>8828146990<US>1NNB7<ETX>
<ACK> The <ACK> character acknowledges successful receipt of messages. The recipient sends this single-character acknowledgment of each message after confirming the checksum of the received message. Track: <STX>1<0x83>8828146990<US>1NNB7<ETX>

DxI: <ACK>

DxI: <STX>1<0xC3>125<ETX>

Track: <ACK>

<US> The <US> character terminates a variable-length field in some messages. <STX>1<0x83>8828146990<US> 1NNB7<ETX>
<0x83> The <0x83> character identifies the Add Tube Command message from the connection unit. A sample ID and <US>xNN always follows <0x83>, where x equals the code for the type of tube. The tube-type codes are:
  • 1 = 13x100 tube
  • 2 = 13x75 tube
  • 5 = Auto-aliquot tube
<STX>1<0x83>8828146990<US>1NN B7<ETX>

<STX>1<0x83>8828146990<US>2NN B8<ETX>

<STX>1<0x83>8828146990<US>5NN BA<ETX>

Note: The NN before the checksum indicates that the tube is not capped and the tube was not sampled from another analyzer. The DxI rejects anything other than NN.
<0xC3> The <0xC3> character identifies the Add Tube Response message from the DxI. An acceptance code (one digit) always follows <0xC3>, indicating whether DxI accepts or rejects the tube. The acceptance codes are:
  • 1 = Accepts tube
  • 2 = Invalid data
  • 3 = Unsupported tube type
  • 4 = Capped tubes not supported
  • 5 = Tube sampled from previous analyzer
  • 6 = Reset queue command is pending
  • 7 = Queue is full or out-of-sequence
  • 8 = DxI is not ready, paused, or in diagnostics
  • 9 = DxI LAS mode is offline
<STX>1<0xC3>1 25<ETX>
Note: Only code 1 accepts the tube into the queue for aspirating, all other codes are rejections. Codes 2, 3, 4, 5, and 9 cause an alarm at the connection keypad.
<0x84> The <0x84> character identifies the Get Tube Command message from the DxI. The checksum always follows <0x84> because there is no other information to send. <STX>1<0x84> B5<ETX>
Note: This command directs the connection unit to scan the tube at the aspiration BCR.
<0xC4> The <0xC4> character identifies the Get Tube Response message from the connection unit. A status code (one digit) always follows <0xC4> and the sample ID (if read). The status codes are:
  • 1 = Bar code reads OK. Sample ID follows.
  • 2 = The queue is empty (no tube to scan).
  • 4 = Connection unit cannot read the sample ID.
<STX>1<0xC4>18828146990 3D<ETX>

<STX>1<0xC4>2 27<ETX>

<STX>1<0xC4>4 29<ETX>

<0x85> The <0x85> character identifies the Release Tube Command message from the DxI. DxI<US>xxv always follows <0x85>, where xx = a status code (two digits) and v = the volume (in µL) of aliquot accepted from the released tube. The status codes are:
  • 00 = Rescan the tube (do not release it).
  • 01 = Accept aliquot.
  • 02 = Sample ID is invalid.
  • 03 = Sample ID is not in the DxI software queue.
  • 04 = Could not verify sample ID. Tests canceled.
  • 05 = Tests canceled. No tests ordered.
  • 06 = Sample pipettor detected clot.
  • 07 = Sample pipettor detected no fluid.
  • 08 = Sample pipettor detected QNS.
  • 09 = Sample pipettor detected other error.
  • 10 = DxI is in Paused or Not Ready mode.
  • 11 = DxI LAS is in offline mode.
<STX>1<0x85>DxI<US>000 6A<ETX>

<STX>1<0x85>DxI<US>01100 CC<ETX> (100 µL accepted)

<STX>1<0x85>DxI<US>080 72<ETX>

<STX>1<0x85>DxI<US>100 6B<ETX>

Note: Except for code 00, this command directs the connection unit to:
  1. Release the tube from the aspiration BCR.
  2. Let the next tube in the queue take its place.
  3. Scan the new tube at the aspiration BCR.
<0xC5> The <0x85> character identifies the Release Tube Response message from the connection unit. A status code (one digit) and the sample ID of the new tube at the aspiration BCR (if read) always follow <0x85>. The status codes are:
  • 1 = Bar code reads OK. Sample ID follows.

    2 = The queue is empty (no new tube to scan).

    4 = The connection unit cannot read the sample ID.

<STX>1<0xC5>18828155690 3B<ETX>

<STX>1<0xC5>2 28<ETX>

<STX>1<0xC5>4 2A<ETX>

Note: The code 4 response causes the DxI to use code 00 in the Release Tube Command to make the connection unit rescan the same tube instead of releasing it.

Example of Serial Communication

This example is an RS-232 communication sequence that occurs while processing two samples through the connection unit spur.

Note: Track in this table refers to the connection unit.
From Message (ASCII code) Description / Comments
Track: <STX>1<0x83>8828146990<US>1NNB7<ETX> Add Tube Command announces the arrival of the first tube at the query BCR.
DxI: <ACK> Acknowledges the command from track.
DxI: <STX>1<0xC3>125<ETX> Add Tube Response indicates accept the tube into the queue for the aspiration BCR.
Track: <ACK> Acknowledges the response from the DxI. Track lets the tube pass into the queue for scanning and aspiration at the aspiration BCR.
DxI: <STX>1<0x84>B5<ETX> Get Tube Command generates the pre-aspiration scan at the aspiration BCR (because the queue was empty when the tube was added).
Note: Except for the first tube that arrives when the queue is empty, it is the Release Tube Command that generates the pre-aspiration scan.
Track: <ACK> Acknowledges the command from DxI. Track scans the tube when it reaches the aspiration BCR.
Track: <STX>1<0xC4>188281469903D<ETX> Get Tube Response reports aspiration BCR read OK for ID 8828146990.
DxI: <ACK> Acknowledges the response from Track. DxI aspirates the sample.
DxI: <STX>1<0x84>B5<ETX> Get Tube Command generates the post-aspiration scan to verify ID.
Track: <ACK> Acknowledges the command from DxI. Track rescans tube at the aspiration BCR.
Track: <STX>1<0x83>8828156390<US>1NNB2<ETX> Add Tube Command announces arrival of a new tube at the Query BCR.
Note: This command cuts in whenever new tubes arrive at the query BCR.
DxI: <ACK> Acknowledges the command from Track.
DxI: <STX>1<0xC3>125<ETX> Add Tube Response indicates the new tube is acceptable for the Queue.
Track: <ACK> Acknowledges the response from DxI. Track lets the new tube pass into the queue.
Track: <STX>1<0xC4>188281469903D<ETX> Get Tube Response reports post-aspiration BCR reads OK for ID 8828146990 (first tube).
DxI: <ACK> Acknowledges the response from Track. DxI verifies ID match of the pre- and post- aspiration scans before allowing the tests to begin.
DxI: <STX>1<0x85>DxI<US>0190A4<ETX> Release Tube Command reports the ID match is verified and 90 µL of sample is accepted from the released tube.
Track: <ACK> Acknowledges the command from DxI. Track releases the first tube from the aspiration BCR and then scans the new tube that moves in from the queue.
Track: <STX>1<0xC5>1882815639039<ETX> Release Tube Response reports aspiration BCR reads OK for ID 8828156390 (new tube).
DxI: <ACK> Acknowledges the response from Track. DxI aspirates the sample.
DxI: <STX>1<0x84>B5<ETX> Get Tube Command generates the post-aspiration scan to verify ID.
Track: <ACK> Acknowledges the command from DxI. Track rescans tube at the aspiration BCR.
Track: <STX>1<0xC4>1882815639038<ETX> Get Tube Response reports post-aspiration BCR reads OK for ID 8828156390.
DxI: <ACK> Acknowledges the response from Track. DxI verifies ID match of the pre- and post- aspiration scans before allowing the tests to begin.
DxI: <STX>1<0x85>DxI<US>0190A4<ETX> Release Tube Command reports ID match verified and 90 µL of sample accepted from the released tube.
Track: <ACK> Acknowledges the command from DxI. Track releases the tube from the aspiration BCR and then senses that there are no more tubes in the queue.
Track: <STX>1<0xC5>228<ETX> Release Tube Response reports the queue is empty.
DxI: <ACK> Acknowledges the response from Track.
