Capturing RF Noise Data During Troubleshooting

This procedure describes how to capture RF noise data generated during the sample aliquot from the LAS track.

This procedure is part of troubleshooting excessive RF noise from the connection unit track that has been found to interfere with DxI level-sensing on LAS track samples.
Note: Refer to the LAS: RF Level Sense and Sampling Problems document for more information.

Perform the steps in this procedure to capture RF noise data from the sample probe.

Note: Troubleshoot other possible causes before checking the RF noise.
  1. Pause the LAS sample tube loading.
    1. On the PrepLink Console, select Setup > Instrument Loading .
    2. Select the correct CONN-X Loading Paused option (X = 1,2,3, or 4).
      The DxI instrument connection units are labeled CONN-1 through CONN-4, according to how many DxI instruments are connected to the LAS.
    3. Before proceeding, verify that the selected DxI instrument has completed processing all samples.
  2. Enable Debug Logging to capture data from the sample pipettor.

    For Windows XP System with Software 5.2 and below:

    1. Select Start > Programs > Administrative Tools > Remote Desktop Connection to AU PC.
      Note: Refer to the Software: Using Desktop Sharing Between Console PC and AU procedure.
    2. Open the Specific.ini file (in the C:\AU directory), and then perform a search for [SamplePipettor].
    3. Find the Enable Debug Logging=no entry in the [SamplePipettor] section.
    4. Change the =no to =yes, then select File > Save.
    5. Right-click on the AUObj icon (small Y at the lower right corner of the screen), and then select Exit.
    6. Select the AUobj.exe icon (large Y on the left edge of the AU desktop). This action starts a new Debug.txt file in the C:\AU directory, erasing any previous Debug.txt file.

    For Windows 8 System with Software 5.3.1 and above:

    Note: DxI Software 5.3.1 is compatible with Windows XP console PC. If the software was installed on the Windows XP console PC, then follow the Windows XP section to enable debug logging.
    1. Press Windows key, select Remote Desktop Connection icon or type remote and open the Remote Desktop Connection program.
      Note: Refer to the Software: Using Desktop Sharing Between Console PC and AU procedure.
    2. Open the Specific.ini file (in the C:\AU directory), and then perform a search for [SamplePipettor].
    3. Find the Enable Debug Logging=no entry in the [SamplePipettor] section.
    4. Change the =no to =yes, then select File > Save.
    5. Shut down the AU Object program.
      • Right click on the task bar and select Task Manager.
      • In the Task Manager box, click on Processes, select AUobj Module, and click on End Task in the bottom corner of the box.
    6. Select the AUobj.exe icon (large Y on the left edge of the AU desktop). This action starts a new Debug.txt file in the C:\AU directory, erasing any previous Debug.txt file.
  3. Perform the LAS RF Level Sense Test.
    1. From the Main Menu, select Diagnostics > Device Diagnostics > RF Level Sense  > LAS.
    2. Run a dry test.
      1. Select 20 repetitions for Dry Test and LAS Autoaliquot Tube for Container Type.
        Caution: If a gel tube is used in the dry test or the selected option for container type does not match the actual container type, the sample probe can be damaged.
      2. Confirm that the carrier and tube are in the aspiration position. Select Load a Carrier  > OK > Start Test.
      3. Select the Print Report at End of Test option.
      4. When the test is complete, select Release Carrier.
    3. Run a wet test.
      1. Select 20 repetitions for Wet Test and LAS Autoaliquot Tube for Container Type.
        Caution: If a gel tube is used in the dry test or the selected option for container type does not match the actual container type, the sample probe can be damaged.
      2. Fill the auto-aliquot tube with 200 µL of wash buffer.
      3. Select the Print Report at End of Test option.
      4. Confirm that the carrier and tube are in the aspiration position. Select Load a Carrier  > OK > Start Test.
      5. When the test is complete, select Release Carrier.
    4. Verify that the failure count is zero for both the dry test and the wet test runs. If failures occur, perform repairs and repeat tests.
  4. Move the Debug.txt file to a local PC for printing or sharing.
    1. Return to the remote connection to the AU, and locate the Debug.txt file in the C:\AU directory
    2. Select the Debug.txt file, select Edit > Copy, and then Edit > Paste.
      This action creates a copy of Debug.txt file in the C:\AU directory.
      Note: The Debug.txt file itself cannot be transferred because it is still in use by the instrument software. Therefore, it is necessary to make a copy of it.
    3. Copy and paste the copy of Debug.txt file in the C:\AU directory into the C:\ drive on the PC.
    4. Move the file from the console PC to the laptop PC, using the USB backup drive.
    5. Rename the file to include information about the source and time of the data capture.
  5. Disable Debug Logging for the sample pipettor.

    For Windows XP System with Software 5.2 and below:

    1. In the remote connection to the AU, open the specific.ini file, and then perform a search for [SamplePipettor].
    2. Find the Enable Debug Logging=yes entry, which is the final line under [SamplePipettor].
    3. Change the =yes to =no, and then select File > Save.
    4. Right-click on the AUObj icon (small Y at the lower right corner of the screen), and then select Exit.
    5. Select the AUobj.exe icon (large Y on the left edge of the AU desktop).
      Note: This action starts the machine control program with Debug Logging disabled.

    For Windows 8 System with Software 5.3.1 and above:

    Note: DxI Software 5.3.1 is compatible with Windows XP console PC. If the software was installed on the Windows XP console PC, then follow the Windows XP section to disable debug logging.
    1. In the remote connection to the AU, open the specific.ini file, and then perform a search for [SamplePipettor].
    2. Find the Enable Debug Logging=yes entry, which is the final line under [SamplePipettor].
    3. Change the =yes to =no, and then select File > Save.
    4. Shut down the AU Object program.
      • Right click on the task bar and select Task Manager.
      • In the Task Manager box, click on Processes, select AUobj Module, and click on End Task in the bottom corner of the box.
    5. Select the AUobj.exe icon (large Y on the left edge of the AU desktop).
      Note: This action starts the machine control program with Debug Logging disabled.
  6. Reset the connection unit.
    Caution: If the connection unit is not reset to normal mode following usage of the 50 and 51 codes for manually loading tubes, the connection unit will not operate correctly.
    1. Remove the access panel from the rear of the connection unit.
    2. Locate the green power switch inside the connection unit (on the lower left).
    3. Power off the connection unit for 15 seconds, and then power on the connection unit.
    4. Press the [Auto / Manual] key on the connection keypad twice, to return to auto mode.
    5. Press the [Auto / Manual] key on the track keypad twice, to return to auto mode.
    6. Reinstall the access panel on the connection unit.
  7. Resume the LAS sample tube loading.
    1. On the PrepLink Console, select Setup > Instrument Loading tab.
    2. Clear the CONN-X Loading Paused check box.
      The DxI instrument connection units are labeled CONN-1 through CONN-4, according to the number of DxI instruments connected to the LAS.
    3. Observe while the DxI instrument runs a minimum of ten samples from the LAS. Confirm that all tubes are processed correctly through the connection unit and that all samples are aspirated and run correctly by the DxI instrument.
      Note: If captive tubes were released from the connection unit, then errors will show in the event log, as expected for tubes that had processed beyond the query BCR before release.
  8. Analyze the data for the sample pipettor RF noise count.
    1. Locate the copy of Debug.txt in the directory on the PC, and then double-click on it to open it.
    2. Select Edit > Find, enter Maximum, and then select Find Next.
    3. Record the maximum, and then record the minimum (one line above maximum).
    4. Subtract the minimum from the maximum to get the RF noise count.
      Note: Typical RF noise counts are around 10. Problem systems have had counts above 50.
    5. Select Find Next, and then repeat to record RF noise counts for all replicates.
    6. If any of the RF noise counts are higher than 50, then excessive RF noise is an issue and requires further investigation.
