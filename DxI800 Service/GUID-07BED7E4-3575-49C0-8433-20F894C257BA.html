Software V4.2.1 Expected Behavior and Windows XP

Purpose

This document provides details of some new behaviors seen in software version 4.2.1.

LAS Flexible Reserve

In some cases, customers completed the upgrade to software version 4.2.1 and the Flexible Reserve Volume Feature is not working correctly on the LAS. Reflex test requests are going into Work Pending instead of being run as set up in the reflex configuration. For more information on Reserve Volume, refer to the Instrument: Reserve Volume - Flexible and Standard operating principles document.

Pack Detection - Two Step Assays

An issue exists with reagent pack process monitoring primarily on two step assays. This issue has been in all 4.X versions of software, but was first discovered during the Limited Distribution of version 4.2.1. For further details on how this process monitoring works, refer to the Software: Process Monitoring - Pressure Checking Operating Principles document.
  • With software version 4.1 through version 4.2.1 if a pipettor is flagged unusable because of a reagent pack monitoring error, any two step assays that have been started on that pipettor complete without process monitoring and give a test result. This result is not be flagged as having been completed on a pipettor that may be compromised.
  • It is important that all test results from a pipettor that has been flagged unusable for reagent pack monitoring errors be reviewed.
  • This issue is resolved in software version 4.3.

Tape Back Up Errors

During Limited Distribution, a number of tape backup errors were observed. Along with backup errors, some generic BAssertEvent errors were caused by the backup issue. The following outlines the issues and resolution:
  • Backup errors can be caused by faulty tapes, faulty tape drives, or occasional XPe compatibility issues with tape drives and the NT backup program being used.
  • In software version 4.3 the BAssertEvent errors will more clearly define what the backup issue is.
  • To resolve issues with the backup tapes or drives the USB backup device can be sent to the customer and installed by the customer. Refer to the customer procedure in the Access Applications database "Installing the USB Flash Drive."

Database Mismatch

This error is a benign software error that occurs on systems with software 4.1 or greater that are connected to Automation.

Dual Gantry Slippage

For systems in the Dual Gantry configuration a confusing scenario exists when a slippage error occurs.
  • A sample pipettor slippage error will result in the event log message, "Rack intake paused due to Dual Gantry fault" and no racks can be loaded even though the system stays in the Ready mode.
  • A system in a stand alone or LAS configuration will recover from the slippage error and the system will continue to process racks.
  • The dual gantry configuration message tells us the rack intake is "paused" but does not explain the recovery.
  • To recover the system must be re-initialized.
