Software V2.0 Release Notes

Confidentiality

Software release notes are Confidential and should not be shared with customers.

Purpose

This document provides details regarding the most important new features and enhancements, workarounds, corrected issues, and issues remaining in DxI software version 2.0.

This release of software corrects software bugs and improves operator ease of use.

Notes and Cautions

These release notes apply to the changes from Version 1.4 to Version 2.0 software.

Caution:
  • If the duck-bill valve, wash collar, and aspirate probe MODs have not been completed, then the customer cannot complete the update from V1.3 (or higher) to V2.0 software.
  • If updating from V1.0 to V2.0, then the customer cannot install the software.
    • A service visit is required because all open MODs must be completed and Precess Monitoring must be calibrated.
  • Before installing V2.0 software, the new wash collar, aspirate probes, and duck-bill valve must be installed.
  • If installing the software over V1.4 or lower, then recalibrate and run all assays and run QC. Verify that quality control is within customer specifications.
  • If installing the software over V1.4.1 or V1.4.2, then run all levels of QC on all assays. Verify that quality control is within customer specifications.

Reference Documents

Installation instructions are available for this release of software and must be used. Check this service manual for any required Software Version 2.0. MODs.

New Features and Enhancements of V2.0 Software

Subject Change
Changes Included from Software V1.4.1 and V1.4.2 Changed the mix timing and mix speed in the wash wheel to accommodate the HIV assay. This change affects all assays and requires the recalibration of all assays. This change is the only change in V1.4.1 software from V1.4 software.
Changed the allowable dark counts to include zero. This change is the only functional change in V1.4.2 software from V1.4.1 software.
Obsoleted MODs Corrected the reagent carriage auto-seek function to check for slippage errors and correct them. This change obsoletes the need for MOD 6304.
Changed the substrate back draw from 700 to 750 (and moved from subsystem.ini to specific.ini) to accommodate various substrate tubing lengths and diameters. This substrate back draw works for all current probe configurations. This change obsoletes the need for MOD 6309.
Changed the algorithm for determining the process-monitoring baseline for samples to correct for baseline drift. This change obsoletes the need for MOD 6311.
Corrected the substrate bubble detect threshold. This change obsoletes the need for MOD 6316.
Operator Features Implemented the Reserve Volume feature for SVs (sample vessels). This feature supports auto-reflex testing without reloading the primary sample tube. The feature can be enabled or disabled on a system-wide basis and on a rack ID by rack ID basis. Depending on the requested test list and configured reserve volume, the total sample might fit in one or more SVs.
Added clot as a source and filter in the Work Pending screen.
Now, the system can run the Daily Clean, Special Clean, and Utility Routine when less than four pipettors are enabled.
Changed the logo on the Main Menu screen.
Manufacturing and Service Enhancements Now when the manufacturing alignments are not done, the system allows one motor axis to be disabled while still adjusting the other axis.
Changed the pipettor to wash tower alignment to be a two-step process, one for x and one for z, to increase alignment accuracy.
Decreased the time it takes to build the RV map when entering diagnostics from 1 minute 45 seconds to 35 seconds.
Changed the pick-and-place auto-aligner to support the new and old pick-and-place alignment tools. The auto-aligner provides much better accuracy and precision for the x alignments. A new algorithm for the z alignment will be implemented in a future 2004 software release.
Robustness and Reliability Enhancements Changed the temperature zone limits to 70 °C for heating thermistors and 42 °C for cooling thermistors.
Added a drawback of fluid in the sample probe after dispensing into the SV to reduce the possibility of dripping.
To help prevent sticky ejectors, now the bulk vessel feeder upper and lower vessel ejectors are exercised when the utility assay runs.
To help prevent sticky grippers, now the reagent gripper is exercised once per hour when the instrument is in Ready mode.
This software now supports the new configuration of the bulk vessel hopper. When a lower ejector sensor is added, the output of the hopper is increased. The software automatically detects the presence of this sensor.
Changed the system behavior to not start the run if the incubation temperature zones are out of spec. A message Instrument warming up is displayed as the Ready mode subtext while the instrument is equilibrating.
Changed the software to improve the wetting of the duck-bill valve.
To help prevent the bulk vessel feeder from getting behind demand, changed the empty sample vessel count from two to twelve vessels.
Changed the bulk feeder vessel ejector timing to reduce the potential for false vessel ejector jam messages. Separated the time limits for ejector extension and retraction, and increased the retraction time limit from 450 to 650 msec.
Changed the timeout for filling the wash buffer reservoir. Increased the timeout 25% to reduce the likelihood of false upper reservoir sensor failure messages.
Improved Event Log Messages When the LIS host sends a request for an assay that is not supported by DxI, the system now adds the name of the requested test to the Assay Not Found event log message.
Added more detail to the bar code failure messages sent by the automation track.
Changed the event log message WashWheel in wrong position to WashWheel detected a missed advance when the cause is software, not hardware.
Added an event log message stating that the operation cannot be completed when the system is running a clean routine and the user attempts to load a rack via the Routine or Stat SPU buttons.
LIS Added a new feature to send fatally flagged results to the LIS when a registry key is set. Add the DWord element “LIS Send Cancel” with a value of 1 to the registry key “Beckman\NexStep\Console\System Setup” to enable this feature.

Workarounds

This version of software has no workarounds for specific issues.

Identified and Corrected Issues

These issues were addressed in this release. Over 450 SPRs were closed in this software release.

Issue Corrected or Change Made (Version 1.2) Notes
Wash Arm error Corrected the problem with the wash wheel where the software reported an occasional phantom arm movement error.
Racks did not run Corrected a problem where racks loaded during the utility assay did not run.
Vessel Already in Collet error Corrected several conditions that could cause a vessel already in collet message in the event log.
Liquid waste container expected even when connected to waste drain Corrected the problem where the system expected liquid waste containers on the system even when the external drain option was selected. Users can now use these drawers for storage when the external drain option is selected.
Reagent pipettor matching SD calculations Changed the standard deviation calculations in the pipettor matching and hot spot screens to use ‘n-1’ rather than ‘n’ to match the values obtained by Excel.
Daily and Special Clean Corrected the ordering of Citranox and Contrad for both Daily Clean and Special Clean.
SVs might be aliquoted Corrected the problem where, under certain conditions, SVs were aliquoted but not started and the tests ended up in Work Pending. This problem affected both the SPU and the track.
Leaving solid waste door open for more than 40 minutes caused software crash. Corrected the issue of software crashes when the user left the solid waste door open for longer than 40 minutes.
W command implementation Corrected the implementation of the sequencer W command to run with the same parameters as Acess and Access 2.
QNS caused database inconsistency Corrected the problem where a QNS on a QC sample with multiple tubes on the same rack caused a database inconsistency.
Utility routine sometimes started during a run Corrected the problem where occasionally the utility routine started unexpectedly in the middle of a run.
Sample wheel moves at incorrect time Corrected a rare problem where the sample wheel attempted to move when the sample pipettor was down in a vessel.
System crashes Identified and corrected many system crash conditions.

Known Issues Remaining

These issues are to be corrected in a future software release:
  • In the Diagnostics Mechanics screen, the display of encoder counts can be misleading. If the encoder value is any value other than zero when at home, the next “move to position” value adds this home offset to the displayed value. The stored alignment value is correct in specific.ini. For example, if the value displayed at home is 4 and the move to position value displayed is 125, the actual move was 125 minus 4 or 121.
  • The Diagnostics volumetric tests crash the instrument software if the weighed vessels are placed in the wrong positions on the sample wheel. The volumetric tests function properly if the vessels are placed in the correct positions.
  • The reagent storage module now monitors the three Peltiers for differences in duty cycle. If the duty cycle between the Peltiers differs by more than 20%, the system writes an event to the event log periodically The difference of duty cycles for reagent plate x and y is outside of limit. This might be a true Peltier failure or an early indication of a future failure.
  • Leaving the Communications Test Dialog open for a long time (more than 8 hours) can cause an instrument software crash.
