Troubleshooting LAS Event/Error/Failure

Purpose

This reference document describes LAS events in the DxI Event Log and other known error messages with LAX and dual-NIC adapters.

When to Use

Use this document when troubleshooting LAS events or other failures associated with DxIs attached to LAS. For DxI instruments connected to the Dynamic LAS systems, refer to LAS: Enabling Logging of the Dynamic Connection for DxI Instruments Connected to LAS Systems For Troubleshooting procedure.

LAS Events in the DxI Event Log

This table describes the most common LAS events in the DxI Event Log.

Note:
  • Queue = The space between the query BCR and the aspiration BCR where the tubes wait to be aspirated after being identified and accepted at the query BCR.
  • For the locations of these components, refer to the connection unit module diagram in the LAS: DxI Connection Unit Operating Principles document.
DxI Event Description Usual Causes
LAS connector unit is paused The connection unit experiences a failed scan attempt on a tube at the aspiration BCR, and reports this event to the DxI. The DxI posts this event plus one of two more events, depending on which scan attempt failed (pre- or post- aspiration):
  • If the pre-aspiration scan failed, then the DxI generates an LAS tube was not at aspiration point in time event.

    If the post-aspiration scan failed, then the DxI generates an LAS sample tube bar code failed to verify event.

  • Problems reading tube IDs at the aspiration BCR because of poor hardware alignments on the connection unit.
  • Excessively busy line computer traffic.
LAS tube was not at aspiration point in time DxI service for this tube is postponed until the next 18-second timing cycle, because the DxI reads the tube as arriving too late to the aspiration position.
Note: A DxI software bug also causes this event when a ShortWash sample immediately follows a LongWash sample. This event is determined by whether the aspiration volume is above or below 200 µL.

Example:

First LAS tube: Has 220 µL of sample aspirated. Sample probe gets a LongWash after dispense.

Second LAS tube: Has 190 µL of sample aspirated. Sample probe gets a ShortWash after dispense.

Third LAS tube: Current cycle is missed and sampling is delayed an extra 18 seconds. Event message inappropriately blames this tube for being late to the aspiration point.

  • Tube movement to position impeded.
  • LAS Connector Unit is paused event on pre-aspiration scan.
  • DxI bug: When LAS sample aspirations go above then below 200 µL from tube to tube.
LAS sample tube bar code failed to verify The pre- and post-aspiration scans of the sample ID do not match or the post-aspiration scan fails on the first attempt. The Expired sample detected during sample vessel discard event follows, indicating the sample that was just dispensed to the SV will not be used (all tests are immediately canceled).
  • LAS connection unit is paused event on post-aspiration scan.
  • Sample ID misread on post-aspiration scan.
Expired sample detected during sample vessel discard An LAS sample that was just dispensed to an SV was designated as expired immediately (all tests were canceled) because of the preceding LAS sample tube bar code failed to verify event. Programming is retained in Work Pending, but the sample aliquot (SV) is discarded. LAS sample tube bar code failed to verify event.
LAS tube exited the queue without any tests ordered for the sample The DxI did not receive the test requests from the LIS before the tube arrived at the aspiration BCR, or had to cancel the tests because of a QNS or a ... bar code failed to verify", or the DxI was in Paused or Not Ready mode when the tube arrived at the aspiration BCR (Dynamic LAS). If the LIS receives the programming, it retains the programming in Work Pending.
  • No programming from LIS.
  • LAS ... bar code failed to verify event.
  • DxI is in Paused or Not Ready mode (Dynamic LAS).
LAS queue is out-of-sequence The sequence of sample IDs seen at the aspiration BCR does not match the sequence seen at the query BCR. DxI tracks sample IDs in a software queue as they are added when received at the query BCR and subtracted when released from the aspiration BCR. In this sequence condition, the DxI processes tubes that are in the queue, but does not allow any new tubes into the queue until the queue is empty.
  • Problems reading bar code at the aspiration position.
  • A tube was removed manually from the queue.
LAS tube not accepted. Queue out-of-sequence An Add Tube Command was rejected because the queue did not empty following an LAS queue is out-of-sequence error. This event does not normally require operator intervention because the DxI continues processing the tubes in the queue until the queue empties, and then automatically resumes accepting tubes into the queue. An Add Tube request occurred before the queue was empty following an LAS queue is out-of-sequence event.
LAS tube is missing from the queue A tube that was accepted into the queue was not seen at the aspiration BCR before the queue was declared empty by the connection unit. DxI tracks sample IDs in a software queue as they are added at the query BCR and subtracted when released from the aspiration BCR.
  • A tube was removed manually from the queue, or a tube was released from the connection unit without the knowledge of the DxI.
  • Tube stuck in the queue because of an obstruction.
Unknown LAS tube at aspiration bar code reader A sample ID read at the aspiration BCR did not match any sample ID that was added at the query BCR. DxI tracks sample IDs in a software queue as they are added at the query BCR and subtracted when released from the aspiration BCR (or when the connection unit declares the queue is empty).
If preceded by LAS tube is missing from the queue, then this error was caused by this scenario:
  1. A puck (tube in carrier) enters the queue.
  2. The puck gets stuck and cannot move to the aspiration BCR.
  3. The connection unit declares the queue is empty.
  4. The DxI still has the sample ID in its software queue so it reports the tube is missing and clears the software queue.
  5. A new puck enters the queue and dislodges the stuck puck, which moves to the aspiration BCR.
  6. The connection unit sends the sample ID of the tube, which is not in the DxI software queue.
  • Stuck puck (path through queue is partially obstructed).
  • Sample ID was misread at one of the two bar code readers.
  • A tube was inserted manually into the queue and the DxI did not add it at the query BCR.
SPU initialization required, LAS available An error was detected with the SPU, but samples can be loaded and run from the LAS. The SPU remains non-operational until the DxI is initialized again. SPU errors
System is not ready to aspirate samples from the track (Dynamic LAS) An instrument condition or configuration caused the DxI status to change from OK to Not OK. This occurs when any one of ten subsystems change states from a 1 to a 0 as shown in the event details. In Dynamic LAS mode, tubes do not sort to a DxI with a Not OK status.

For a detailed description of the Instrument Status Notification message, refer to the TCP/IP message descriptions in the LAS: Dynamic LAS Operating Principles document.

The cause is identified in the event details, marked with a 0.
Timeout occurred while waiting for response from or Write timeout sending message to the LAS connector unit The DxI LAS communication software has exited and requires restarting. The lightning bolt does not appear on the Preplink for this DxI. Cannot enable the system.

The DxI sent a command to the DxI connection unit, but the response did not arrive in time. The DxI goes into a state where every 30 seconds the CommTest command is sent to the connection unit. When the connection unit sends a response, normal operation resumes. The connection unit might be in the wrong mode or turned off.

  • Reboot the PC and then check the connection unit and reboot the AU if the problem continues.
    Note: When rebooting the Privacy & Security compliant Windows 8 or Windows 10 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

  • Reboot the connection unit to clear the manual puck loading codes.

Other DxI Errors with LAS or Dual NIC

This table lists failure symptoms, causes, and remedial actions for known LAS and Dual NIC errors.

Symptom Cause Remedial Action
The DxI UI fails to launch, and displays this error: BNexGenUIApp.cpp ($ Revision: 1.47 $) Line:1218 An error occurred in the Workgroup Communications: Unknown error Our consoles use Windows NT Service Pack 4, which does not fully support the Intel(R) PRO 1000 (Dual NIC) adapter services software. Therefore, it is important to disable the services immediately after installing the Dual NIC driver to prevent the services from being used. Just the action of starting and stopping the services can cause this error when the console is rebooted the next time.

To view the services settings, select Start > Settings > Control Panel > Services, and then select Intel(R) NMS.

Recovery may require deleting the Dual NIC adapters and repeating the installation steps in Mod 6693:
  1. Start the Intel(R) NMS Services (...Startup > Manual > OK > Start > Close).
  2. Delete adapters (2) and (3) (...Network > Adapter, highlight adapter, and then select Remove ...).
  3. Perform these sections of the Mod 6693 procedure:
    • Loading the NIC Driver
    • Configuring IP Addresses
    • Disabling Intel(R) NMS Service
This message displays when trying to access the Dual NIC Network >> Adapter properties: Intel(R) PROSet ll PRO Set failed to initialize. Please restart the system or re-install the adapter software drivers. This is normal and expected behavior for the original type DTx console because the Control Panel > Services for Intel(R) NMS are disabled (and must remain disabled to avoid a ...Workgroup Communications: Unknown error.)
Note: The message displays when Network  > Adapter  > Properties is selected for adapters 3 or 2, and also when Control Panel > Intel(R) PROSet ll is selected.
To view or change the settings for the Dual NIC adapters, select Network > Protocols  > Properties (not Network  > Adapter  > Properties), then select the adapter from the menu.
Unable to connect to instrument... during software load or UI launch.

And: NT's Event Viewer shows 7001 and 7002 events, indicating illegal or duplicate Computer Names are detected on a network.

Multiple DxIs on the dynamic LAS network are in conflict because they have the same computer name in their network settings. This is because all consoles have a default name of CONSOLE_SETUP_PC and the network requires unique names for each console. Select Start > Settings > Control Panel > Network > Identification > Change, enter the DxI serial number as the computer name, and then select OK. Restart the PC.
pcAnywhere A Telephony resource is temporarily unavailable. This could mean a short wait is necessary or that a non-TAPI application is using the Device.

Followed by:

Error initializing modem! Please ensure that the modem is turned on and connected properly.

The modem card was not detected by the console PC during boot up (perhaps due to a poor connection in its new PC slot following Mod 6693). Shut down the PC, reseat the modem card in its slot, and then restart the PC.
Observe the PC during boot-up: If the PC locks up on the Windows NT logo screen, then:
  1. Remove the Dual NIC.
  2. Put the modem and serial cards in their original slots.
  3. Restart the PC.
  4. Try again to install the Dual NIC.
pcAnywhere There are no modems installed. Please install a modem through control panel, or modify this items properties

Only four COM ports show on the Control Panel >> Ports settings screen (should be five)

The modem driver was not enabled during boot up.

One of the serial card ports may have sequestered COM3 which is required by the modem: Select Start  > Settings > Control Panel > Cyber PCI 20X, and then confrim that the two expansion serial ports are using COM 4 and COM 5.

The modem may have lost its driver. Select Start  > Settings > Control Panel > Modem, and confirm that US Robotics ... is listed and associated with COM3.

If one of the Cyber PCI 20X ports are using COM3, then select Settings > Advanced, and change the port to be COM5.

To reload the modem driver, select Start > Programs > Windows Explorer, navigate to the C:\Install\modem folder, and then double-click on Setup.exe.

Motion failure - Z Axis event while attempting Volume Check for the sample pipettor. Current software drives the sample pipettor z-motor in the wrong direction for the LAS gantry during volume check. The software needs to check which gantry type is installed to apply the appropriate polarity. Do not use the sample pipettor volume check on LAS systems until have the latest version of software that corrects this problem.

DxI Duplicate Tests Run for Samples on DxA Automation

Some DxI samples are getting duplicate DxI tests on tubes loaded on DxA automation.

Symptom Cause Remedial Action
Some sample tubes routed to the DxI from the DxA automation line are getting an unexpected test repeated. Both test results are unique but are not a result of a reflex test. The duplicate tests may be at least several minutes apart because the tube may be re-routed back to the DxI for the 2nd test. The issue likely occurs because the Remisol gets an out of sequence message from the DxI which causes it to request the test again and ask the DxA to route it back to the DxI. Occurrence rates may vary from several samples per day up to 50 or more. Disable the "DTS Aspiration Finished" message from the DxA console.
  1. Navigate to System Configuration > LIS Configuration from the DxA console.
  2. Uncheck the "DTS Aspiration Finished" box on the screen.
  3. Go back to the System Configuration screen and select "Activate Draft".
    Note: If the account is using the Remisol Dashboard for tracking metrics and if they are using the 'DTS Aspiration Finished' message for the tracking, then they can switch to using the 'DTS Aspiration Started' message instead. If they are not using the dashboard for tracking or if the Remisol/LIS doesn't need those messages, they could disable both the DTS Aspiration Started and Finished messages.
