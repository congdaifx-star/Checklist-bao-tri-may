Carryover Test

This procedure describes how to perform and interpret the manual carryover test.

Table 34: Carryover Test Guidelines
Perform When
Carryover Test - Software V2.4 or lower
  • Replacing a sample probe
  • Installing a new system
  • Troubleshooting assay performance issues
  • Performing PMA or PMB
Troubleshoot Sample Probe Carryover - Software V2.4 or lower
Note: Refer to the Tests: Sample Probe Carryover (Isolate Carryover) procedure.
Troubleshooting a suspect sample probe after running Carryover Test.
Automated Carryover - Software V4.0 or higher
Note: Refer to the Tests: Automated Carryover Test procedure.
  • Replacing a sample probe
  • Installing a new system
  • Troubleshooting assay performance issues
  • Performing PMA or PMB
Carryover can occur when sample or reagent probes are not washed correctly or when the contents of the RV are splashed onto the substrate probe. These issues can be caused by:
  • Damaged or defective probes.
  • Incorrect probe to wash tower alignments.
  • Faulty wash tower function.
Before performing this procedure:
  • Confirm the cleanliness of the sample and reagent modules.
  • Confirm the alignments of the sample and reagent pipettors to each position.
  • Perform the correct Carryover Test.
  • Print and analyze the results.
  • If the carryover test fails, then determine the root cause, perform repairs, and repeat the Carryover Test.
Note: This test detects carryover on sample, reagent, and substrate probes, but not on aspirate probes. Perform HS System Check to verify the integrity of the aspirate probes. Refer to theTests - Performing HS System Checks procedure.

This procedure uses service assay test AP25 (910). For details regarding the APF, refer to the Tests: Service Tests document.

The Pass/Fail criteria for the Carryover Test are the same with Wash Buffer I or Wash Buffer II; however, the baseline RLU may be lower when running the Carryover Test with Wash Buffer I.

  1. Before the Carryover Test, confirm that:
    • All pipettor probes are clean.
    • Probe to wash tower alignments are correct.
    • Wash towers are functional.
    • Dark counts are acceptable.
    • Carryover is not occurring on the aspirate probes
    • Substrate is not contaminated.
    1. Open the upper left front cover, bypass the interlock switch, and initialize the instrument.
    2. Run a Special Clean maintenance rack and observe during the run to confirm that:
      • Each probe is centered while in the wash tower (no contact with inner walls).
      • All probes are sprayed with wash tower fluids.
      • The vacuum pumps drain each wash tower completely.
    3. Remove the interlock switch bypass and close all the covers.
    4. Select Device Diagnostics > Luminometer > Dark Count Check, select the Print Report at End of Test option, and then select Start Test.
    5. Interpret the Dark Count Check results:
      • Carousel positions with significantly higher RLUs than other positions can indicate probe drips or a torn duck-bill valve.
      • A clean carousel has low RLUs and low variability among all positions.
      • The manufacturing and service specification for dark count RLUs in this screen is < 400.
      • The instrument will post a dark count error to the event log if the RLU is > 600
    6. Run a full System Check, and confirm that it passes all criteria.
  2. Obtain a baseline and determine a pass/fail cutoff for the carryover test.
    1. Obtain a rack configured for 2-mL cups or 3-mL containers.
    2. Select Menu > Sample Manager  > New Request > Patient/QC Requests, and then enter the Rack ID.
    3. Select More Options > Request Service Assay, and then enter a Sample ID for cup 1 (example: 2031 for rack 203 position 1).
    4. Select OK.
    5. Select AP25 three times (three replicates).
    6. Pipette 500 µL of wash buffer into cup 1.
    7. Load the rack onto the SPU.
    8. Calculate the pass/fail cutoff from the baseline cup results:
      • All three replicates of the baseline cup must be <9000 RLU.
      • The median (middle value) of the three replicates = wash buffer baseline.
      • Pass/fail cutoff = wash buffer baseline + 17,500 RLU.
      Note: Baseline replicates >9000 RLU might indicate contaminated wash buffer.
  3. Program sample racks to detect carryover
    1. Obtain sample racks for 2-mL cups or 3-mL containers.
      Note:
      • DxI 800: Eight racks
      • DxI 600: Four racks
    2. Select Sample Manager > New Request > Patient/QC Requests to start a new rack, and then repeat these steps until all racks are programmed.
      1. Enter the Rack ID.
      2. Select More Options > Request Service Assay, then select one of the pipettors. Select Pipettor 1 for all the cups in the first rack, Pipettor 2 for all the cups in the second rack. If this instrument is a DxI 800, then continue programming cups for Pipettor 3 and Pipettor 4.
      3. Enter a descriptive Sample ID, and then select OK (example: 50711 for rack 507 cup 1 using pipettor 1, 50721 for cup 2 using pipettor 1, 50731 for cup 3 using pipettor 1).
        Note: Each cup must have a unique sample ID.
      4. Request one replicate of AP25 for cups 1 and 3.
      5. Request three replicates of AP25 for cups 2 and 4.
      • All cups in a rack are programmed to run on the same pipettor.
      • Each of the pipettors has two racks programmed to run on them.
      • All cups in the racks have unique sample IDs.
    3. Place cups in positions 1 and 3 (only) of each rack, and then pipette 300 µL of NEAT System Check (undiluted) into each cup.
      Note: Before placing the cups in positions 2 and 4, fill all cups in positions 1 and 3 to avoid contamination from dripping or splashing System Check into them.
    4. Place cups in positions 2 and 4 of each rack, then pipette precisely 500 µL of wash buffer into all cups 2 and 4.
      Note: Wash buffer volume is a critical variable. Use precise pipetting technique and new cups for repeat runs.
    5. Load the racks onto the SPU.
  4. Use the Performance macro to evaluate the results of the test.
    1. Select and save the results.
      1. From the Main Menu, select Test Results > Filter.
      2. Configure the filter to capture all the desired data points. Select the test results by placing the cursor on the first data point, pressing the [Shift] key, and then selecting the last desired test result.
      3. Save the data.
        Caution: If using an external USB drive to collect data, the external USB memory shared between the DxI console PC and other systems can introduce a virus.
        • To save the data to a USB drive:
          1. Run virus scan on any suspect USB device. See USB Drive Malware Scan and Removal for more information.
          2. Insert a flash drive into a USB port of the console PC.
          3. Select Copy To Disk > Current Selection. Select the desired drive from the drop-down menu, and then select OK.
          4. When finished, remove the USB flash drive.
    2. Analyze the results using the Performance macro.
      1. Select Performance Macro.xls and save the Excel file to your PC Desktop.

        Note: If the file opens and displays the warning BLOCKED CONTENT: The ActiveX content in this file is blocked, select Learn More to open the Microsoft support topic about how ActiveX controls are disabled by default in Microsoft 365 and Office 2024. Follow the steps in that topic for enabling ActiveX controls in the Trust Center for Excel.

        Note: The file will also display the warning SECURITY WARNING: Macros have been disabled. Select Enable Content to start the Performance Macro file.

      2. Select the type of test to analyze.
      3. Select Select Data File (*.csv) to open File Explorer and select the data file. Within a few seconds, the macro will analyze the test results and produce reports and charts.
        • If prompted, enter the instrument serial number and the substrate RLU. Acceptance criteria for individual tests might be different between Access systems and DxI systems. The macro uses the serial number to identify the limits to apply. Instruments that have an Instance Number in the Serial Number field require you to manually enter the serial number.
        • If the error This is not an XXX run is displayed, the test results file contains insufficient or incorrect data.
        Tip: To test the macro, you can use one of the following sample test result files.
        • dTestdAP Test File.csv
        • HS Test File.csv

      4. Remove the USB backup drive or the floppy disk from the service laptop.
  5. If the Performance macro was not used to evaluate the results of the carryover test, then analyze the results of the carryover test using a manually determined pass/fail cutoff.
    1. Select Sample Manager > Test Result > More Options > Configure Screen, and then select Pipettor and RLU for display.
    2. Select Filter and select the All Samples Loaded Between... option. Select Rack ID as the first Sort Order and select Comp.Time as the second Sort Order (ascending), and then select OK.
    3. Select a time range that includes all the results, and then select OK.
    4. Highlight all the results from all the racks (including the baseline rack), and then select Print > Report.
    5. Select Test Results Report from the drop-down menu, and then select Current Selection > OK.
    6. Analyze the results.
      The carryover test passes if none of the wash buffer results (cups 2 and 4) have an RLU greater than the pass/fail cutoff (baseline + 17500).
  6. If the test did not pass, then mark all results that exceed the pass/fail cutoff on the printout, and troubleshoot the failed results. Refer to the Tests: Carryover Test Troubleshooting document.
