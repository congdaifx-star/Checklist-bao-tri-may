Software V4.4 Release Notes

Purpose

This document provides details of the most significant features and enhancements in DxI software version 4.4.

Confidentiality

Software release notes are confidential and should not be shared with customers.

Obsoleted Mods

Once this version of software is installed on an instrument, these Mods are no longer applicable:
  • Mod 10317 - Software 4.3.

CAPA and CF fixes

These CAPA and CF fixes are included in software version 4.4:
  • CAPA 13919 HAVAb On-board Dilutions (PCA 13919): Issue was discovered internally: HAV Ab assay run with the on-board dilution feature (dHAV Ab) on UniCel DxI systems can report a potentially incorrect interpretation (non-reactive, equivocal, reactive) when results are below the reportable range of the assay.  The quantitative results are reported correctly as <68 mIU/mL.
  • CAPA 14427 Default Sample Type Units (PCA 14427): Issue was discovered internally: Changes to the default sample type while running software version 4.3 are not properly saved to the database. As a result of the changes not being properly saved to the database, a test result could be reported with ranges or a unit of measure corresponding to the previously saved sample type setting.  Ranges can include reference ranges, critical ranges, and LIS ranges defined on the DxI.
  • CAPA 15033 SPU Jam draw from wrong sample rack (PCA 15033): A unique SPU processing scenario which can cause results to be associated with the wrong sample IDs. A new event log is created that stops SPU processing.
  • CAPA 16219 DxI Reagent Pack Process Monitoring of HIV Combo Assay: Updates the reagent pack monitoring seeding filter acceptance for well 1 from 1.6 to 5.0 due to the high viscosity of HIVCo Well 1 to prevent false "Reagent pack monitoring failed to initialize" errors.
  • CAPA 17479 the temperature control system was not running and the instrument provided no errors. A new event log "Temperature Controller Failure" is created when a fatal temperature error is reported, and the instrument goes to Not Ready requiring the instrument software to be restarted. System initialization from the console screen is not permitted in this error mode.

Enhancements - Database

Improvement Notes
Improved Consistency Check Find and fix more inconsistencies.
Improved Database Tools New tool to reset critical event count to zero. Abort in progress reps and abort in progress curves are numbered now so that engineers perform them in the correct order.
Database Maintenance available from the user interface Select PC Admin > Database Maintenance > Yes. The console should restart on its own and begin the database maintenance on restart.

Enhancements - Event Logs

Improvement Notes
New Event Log type: Diagnostic

Some messages are now diagnostic events and not visible in the default Event Log screen.

To view, select Filter > Diagnostic.

Defaults to not show diagnostic when exiting and reentering the Event Log screen.
Improved Event Log saving features
  1. Save Event Logs in UI: Ctrl + Shift + Home. Events are exported to the C root directly.
  2. Backup folder contains terse and verbose created during each backup.
  3. EventsTestUD program allows saving of XML, terse, and verbose.
Improved Event Log titles and details. More possible causes, better information in details, reclassify 42 event severity levels, remove "slippage" terminology, use one-based counting.
Significant new messages:
  • Wash buffer transfer pump: Motion failure
  • SPU on-load pusher: Motion issue
  • SPU on-load pusher: Abnormal rack count
  • Motion error was detected while homing: X. Where X is the device name
  • Temperature controller failure
  • Excessive motion error: X. Where X is the device name
Significant Improved Messages
  • LAS tube out of sequence. Changed to diagnostic. The DxI attempts recovery automatically.
  • Pick-and-place messages. Pick-and-place errors now list the interacting device.
  • Possible motion or sensor failure: X. Where X is the device name. Previous message: MCC failed to input capture.
  • No substrate bottles are present. Previous message: Substrate selector valve out of position.
  • Processing stopped unexpectedly, so Utility routine required. Previous message: Probes are dirty, run the utility routine.
  • Reagent gripper errors: Lists pack information, encoder counts, expected motor position, gripper state, and more possible causes.
  • Reagent pipettor ultrasonics failure: Pip X. Where X is the pipettor number. Previous message: Ultrasonics general failure.
  • Dispense probe plate and aspirate probe plate messages now contain details on whether vessels are present beneath the mixer spinners.

Enhancements - Module

Improvement Notes
Reagent Storage New x-alignment at the pipettor nests.

Corrected the problem of an AU crash when an interlock switch opens during the reagent storage exerciser.

SPU SPU is busy message no long occurs. Software tries to home the SPU, so that the door does not lock during SPU jams or other operations. If the software does not work, then select Diagnostics > Unlock SPU to unlock the SPU.
Incubator Pick-and-Place Resolved the issue where the Incubator pick-and-place slams repeatedly on the wash wheel, if the wash wheel is out of position.
Pick-and-Place (all) Prevented passenger exchange errors.
Sample Wheel If an SV remains on the sample wheel after a reagent pipettor unexpected height error, the instrument might not go to Running after the next initialization. This resolution discards the SV.
Ultrasonics All new instruments now have the low voltage ultrasonics set to 62 in manufacturing. Previously, new instruments were set to 50 and 62. Software V4.4 does not change the voltages in current instruments (62, 45, and 50 voltages remain the same).

Improvement Notes
Calibration expiration dates Sends the actual calibration expiration date (not the cal lot expiration).
System Check pass or fail status Fixes System Check pass or fail status issues in languages other than English.
Quality Control Sends QC setup information every 24 hours and at PC reboot. In V4.3 and below, QC setup data are sent only at PC reboot.
Prevent AU crash after invalid object access on vessel pointer during RMS data collection Gathers information from another location.
Send correct prefix for qualitative calibration level name Changes from S to C.
Prevent RMS socket errors on console startup Initializes socket subsystem correctly properly. The previous bug prevented data from being sent to the CIA service.
Send system configuration data every 12 hours Previously, system configuration was sent only during console reboot and instrument initialization.
Corrected pipettor 2 PCF value for PipettorMatching in CIA log file Corrected pipettor 2 PCF value for PipettorMatching in CIA log file

Enhancements - UI

Improvement Notes
Fixes missing QC tiles and disables the request of tests that are not part of the control Whenever a control rep is generated, the system ensures that a tile is created.

New behavior that accompanies the software fix only allows users to program QC replicates for assays that are included in the QC setup.

Example: RBC control is configured for only assay RBC2, but the customer wants to run FOL2 on this control. The customer will have to delete the RBC2 from the QC Control Setup (because RBC2 and FOL2 are different sample types), and then add FOL2 or create a control setup.

Speeds up database queries and user interface functions with indexing.

Faster processing at these screens:

  • User Interface launch
  • Reagent Pack and Substrate Loading
  • Sample Manager In Progress
  • Event Log
Allows diagnostic copy to disk while in running mode. Allows diagnostic copy to disk while in running mode. The Test Results screen copy to disk still requires the instrument to be in the Ready or Not Ready mode.
Automatic rerun New optional feature (defaults to off): Work pending automatically reruns tests with the result flags AEX, QNS, QSD, QSS< QSB, SYS, RLU, TRI, TRS, TRW, or CLT, if sufficient reserve volume is available. Service assays and calibrations do not rerun. To turn on the feature, select Work Pending > Options, and then select the Rerun cancelled tests option.

This feature is not available on integrated instruments (the check box is grayed out) because the DxC has similar automatic rerun behavior. The DxC software should be selected to requery in the Setup >> Host Communications. The "Requery" box should be set to blue which indicates on.

Fixes USB flash drives virus To prevent viruses from being transferred from USB drives to the DxI console, Windows no longer automatically runs autolaunch.exe programs on USB flash drives.
Adds new supply wait reasons to help user determine why DxI cannot run. New supply wait items:
  • Close Solid Waste Door
  • Initialize System
  • Pipettor Matching
  • Pressure Sensor Curve
  • Wash Buffer Flow Calibration
  • Calibrate Drawback (substrate)
  • Prime Fluidics (Wash Buffer Bubble Detector or Dispense and Aspirate Probe 1)
Fixes manual programming of sample type In previous versions of the software, if the sample type is changed to a value other than the default, then the test is requested, the test will be assigned the default sample type (not the manually programmed sample type).
Sample tube bar code disagrees with rack programming If the sample tube bar code in a QC programmed rack does not match the QC (example: a patient tube), then the test will not run. This prevents the patient sample from being run as QC. An event log is created Sample IDs entered manually and read on the bar code do not match. No tests will be started. To disable this feature, perform the QC bar code mismatch procedure. Refer to the Software: Configuring Console PC to Disable QC Mismatch Behavior procedure.
Calibration curves over 365 days will be deleted Registry key HKLM\Software\Beckman\NexStep\Console\System Setup\AutoDeleteOldCurves is set to 365 by default to delete curves over 365 days. The key can be set to zero, if all curves need to be saved.
Pop-up message titles will be slightly larger in font. Windows XP made the pop-up titles smaller. Software V4.4 restores the original font size to help with visibility, particularly with Asian characters.
Software version shows on screens and printed reports. Helpful information for investigations is available easily now.
Removed duplicate pipettor columns in test results copy to disk in non-English languages. This software bug previously caused issues when using macros to process service assay data.
Option to have LIS transmit extra information. Turning on a registry key starts the LIS sending: RLUs, pipettor number, lot number and serial number, and dilution lot number and dilution serial number. Do not turn on this feature, unless the LIS is prepared to handle the data. Significant cost can be associated with updating an LIS to accept these new data.
QC Compare screen now shows correct SD SD now shows in terms of the user-defined precision for that assay.
QC control unit corrections when units change Control replicates display in the units they were originally generated in. The QC mean, SD, and CV are calculated correctly in the currently configured assay unit.

Previously, the QC calculated mean and standard deviation results were incorrect after the units were changed for an assay.  The unit change made points appear to be out of the control range when they were not (or the reverse). Any report containing values with different units had errors.

Results with only critical range high flags or only critical range low flags are now displayed in bold red text. Previously, these results were only in bold red if flagged for values outside of the reference range ORH or ORL.
Print all digits of the manual dilution factor on the Patient Report. Previously, only two digits of the manual dilution factor were printed on the Patient Report. If the sample was diluted by a factor greater than 99, the incorrect dilution factor displayed on the report.
On-board dilutions: Reference and critical range flags suppressed when results are OVR or lower than reportable Reference and critical range flags are suppressed for on-board dilution results over the maximum reportable range or under the reportable range.
New Wash Probes button This button was intended for customer maintenance until limited distribution users of V4.4 software observed buffer droplets discharged out of the dispense probes when selecting the new Refill button of this feature. No reaction vessels are under the probes at this time and any buffer in the wash wheel could cause issues. Do not use the Refill option at this time. Instead, prime the dispense probes until further information is available.

Expected Behavior

These behaviors are expected with 4.4 software.

Component Expected Behavior Notes
QC Copy to Disk Save data pop-up appears in the upper left rather than the middle of the screen. A work item was created to fix this issue in future software.
QC Request The control names are now ordered in alphabetical order. This affects some customers that like to program L3 followed by L1 by checking both boxes at the same time when they request QC. Previously, this screen sorted the QC lots chronologically (in the order the applications specialist or customer entered them).

File a CF if the customer complains about this behavior.

A work item was created to fix this issue in future software.

Workaround options:
  1. Request the QC levels one at a time to obtain the correct order.
  2. Consider using barcoded QC.
  3. Create new QCs that have names in alphabetical order to obtain L3 before L1 in the sort order. Current software does not allow QC lots to be renamed.
Peri-pump and Vacuum Pumps screen has risk for fluid overflow when accessed immediately after instrument initialization. Select Digital Devices > Peristaltic Pump and Vacuum Pumps within 30 seconds of initialization. The vacuum pumps are auto-checked for vacuum on and are running. If the user turns on the peristaltic pumps, within 30 seconds the vacuum pumps turn off and the peristaltic pumps continue to run causing a wash buffer overflow. This issue has been verified to occur on V2.3 and V4.2.1 software.
Disabling pipettors can cause "MFC Asserted" pop-up.
Scenario 1 - The following actions must occur in order:
  1. A reagent pipettor detects five consecutive pressure monitoring errors setting the flag indicating the need to recalibrate the pressure sensor in the specific.ini file. The system also disables the pipettor.
  2. The user manually disables the pipettor.
  3. The user reboots the instrument.

The AU tries to tell the UI about the need for calibration and looks for the additional information to add to the event. Since the pipettor is disabled, the functionality is not available causing the AU to crash.

Preventing the issue - Recalibrate the sensor before shutting down. Abstain from disabling the pipettor before shutting down.

Recovery - Edit the specific.ini file manually and reset the flag indicating the need to recalibrate the sensor (SensorCalibrated=Yes).

Restart the AU and recalibrate the sensor.

Scenario 2 (more likely) - The following has to happen in the order listed:
  1. The user disables a pipettor.
  2. The user reboots the AU.
  3. The user tries to enable or disable any pipettor.
    Note: The pipettors do not have to be the same number.

This causes the AU to crash, since the disabled pipettor is not initialized completely and cannot provide needed functionality when queried.

Preventing the issue - Enable and disable pipettors before rebooting the AU. Refrain from disabling pipettors and rebooting.
Recovery - Once the AU has crashed due to a disabled pipettor being enabled, restart the AU. Repeat for all disabled pipettors (or do all at once):
  1. Restart the AU.
  2. Check for other disabled pipettors:
    Note: If a hardware error is preventing the pipettor from enabling (pump, valve, pressure sensor, failure to wash, or ultrasonic error), then leave the pipettor disabled until that error can be resolved. After the error is resolved, the AU might assert when the pipettor is enabled. Restart the AU to resolve.
    • If all pipettors are enabled, then the issue is resolved.
    • If one or more pipettors are disabled, then
      1. Enable those pipettors.
        Note: An MFC Asserted message occurs.
      2. Restart the AU again.
      3. The issue is resolved.
Event 0x9B0017 - Excessive sample pump backlash detected in Spanish lists the substrate pump incorrectly. The event 0x9B0017 - Excessive sample pump backlash detected is translated to Spanish version as Desajuste escesivo de bomba se sustrato detectado which guides you to a problem in the substrate pump. Troubleshoot the sample pump if this error is received.
