Software: Troubleshooting Windows XP and Software 5.3.1 and Higher

Purpose

This document provide troubleshooting steps for Windows XP system and system software 5.3.1 and higher.
Note: Software 5.3.1 has new drivers for all device motors. If it is installed, software can not be reverted back to previous version.
Table 97: Troubleshooting Fail to Loading System Software and Launching User Interface
Error Action Steps Note
AUobject program fails to launch after upgrading the software.
Simulate the NVRAM through specifici.ini file.
  1. Remote Desktop sharing to the AU side.
  2. Navigate to the C:/AU folder.
  3. Open the specific.ini file in Notepad program.
  4. Search for "SimulateNVM" and change from No to Yes.
  5. Save the change and close Notepad.
  6. Launch AUobject program.
This occurs when software is not properly upgraded or installed and the NVRAM has been not simulated in the specific.ini.

Software 5.3.1 and above no longer use the NVRAM PCB and requires the NVRAM to be simulated.

Critical message jams after upgrading the software. Clear the jammed messages. Refer to Software: Database - Clearing Jammed Critical Events procedure. This occurs when:
  • The instrument attempts to send a message with an event ID smaller than what the database expects. The database does not accept a critical event message from the instrument that has an event ID lower than the ID of the last event received.
  • An illegal supply can be an onboard reagent from an assay that was deleted from the database by a software or APF update.
System software fails to install with " Communication failed between the PC and instrument. Contact your local service representative for assistance" message error. Change the Console PC name to "Console_PC" if the PC name is different other than "Console_PC."
  1. Press Windows key, select Settings > Control Panel > System.
  2. On System Properties pop-up box, select Computer Name tab > Change.
  3. On Computer Name Changes pop-up box, enter Console_PC to Computer name column.
  4. Select OK > Yes.
  5. Select OK to "You must restart this computer for the changes to take effect" message.
  6. Enter Console_PC to Computer description and select OK.
  7. Select Yes to restart the console PC.
  8. Reload system software.

If software still fails with the same error, then:

  1. Check the Computer Name in Command Prompt program.
    1. Press Windows key, and then select Run to open a dialog box on the console.
    2. Enter CMD and select OK.
    3. Type net user and hit Enter.
    4. Check the computer name is correct.
      • Correct name: "User accounts for \\Console_PC."
  2. If the computer name is incorrect (example: 601115_PC), then go and change the registry settings. There may be more registry settings require to be changed.
    1. Press Windows key, and then select Run to open a dialog box on the console.
    2. Enter regedit, and select OK.
    3. On the left hand side box of the Registry Editor, scroll the divider bar up to the top.
    4. Click on Computer > Edit > Find.
    5. Enter 601115_PC in the Find what box and click Find Next.
    6. Keep clicking on F3 key to search for the followings and modify their Data fields to Console_PC:
      • LOGONSERVER (path: Computer\HKEY_USERS\S-1-5-21-....\Volatile Environment).
      • ComputerName (path:Computer\HKEY_LOCALMACHINE\SYSTEM\ControlSet001 or ControlSet002\Control\ComputerName\ActiveComputerName)
      • ComputerName (path: Computer\HKEY_LOCALMACHINE\SYSTEM\ControlSet001 or ControlSet002\Services\Eventlog)
    7. Reload system software.
If the error still exits, then:
  • Repeat Step 2 and press F3 key to search through the entire registry for the incorrect computer name.
  • Change the all incorrect console PC names to Console_PC.
  • Reload software.
This error occurs when:
  • The software installer was looking for a specific computer name such as Console_PC in the registry but found an incorrect name (example: 601115_PC).
  • The console PC's computer name had changed, but the Windows registry was not updated properly.
System software fails to install with "TCP/IP" not found error.
Ping the console PC and AU to confirm communication issue. The default network IP address for the console PC is 192.168.2.3. The default IP address for AU is 192.168.2.4.
  1. Press Windows key, and then select Run to open a dialog box on the console.
  2. Enter CMD and select OK.
  3. Type ping 192.168.2.3 for console PC and press Enter.
  4. Type ping 192.168.2.4 for AU and press Enter.
  5. If there is no reply, then check the IP address in Network Connections and change the IP address if needed.
Check and change network IP addresses.
  1. Check and change the network IP address on console PC.
    • Press the Windows key, select Settings > Control Panel > Network Connections.
    • Right click on Local Area Connection, choose Properties, select Internet Protocol (TCP/IP) and choose Properties.
    • Verify these settings and change as needed. If changing the IP address, ensure to click Ok to save.
      • IP address: 192.168.2.3
      • Subnet Mask: 255.255.255.0
  2. Check and change the network IP address on AU.
    • From the console PC, remote desktop to AU side. Refer to Software: Using Desktop Sharing Between Console PC and AU procedure.
    • If remote desktop fails, then connect the monitor, mouse, and keyboard to the AU side to change the IP address.
    • Press the Windows key, select Settings > Control Panel > Network Connections.
    • Right click on Local Area Connection, choose Properties, select Internet Protocol (TCP/IP) and choose Properties.
    • Verify these settings and change as needed. If changing the IP address, ensure to click Ok to save.
      • IP address: 192.168.2.4
      • Subnet Mask: 255.255.255.0
  3. Ping the both console PC and AU to confirm communication issue is fixed.
  4. Reload system software.

If the console PC and AU IP addresses are correct, then check and change IP addresses in the registry:

  1. Press Windows key, and then select Run to open a dialog box on the console.
  2. Enter regedit, and select OK.
  3. On the left hand side box of the Registry Editor, scroll the divider bar up to the top.
  4. Browse to HKEY_LOCAL_MACHINE > SOFTWARE > Beckman > NexStep.
  5. On the right hand side of the Registry Editor pop-up box, verify the PrimaryConsoleIPAddress is 192.168.2.3

    If not, then right click on PrimaryConsoleIPAddress > Modify > enter 192.168.2.3 > OK.

  6. Select Workgroup folder under the NexStep folder and verify the AuIp is 192.168.2.4

    If not, then right click on the AuIp > Modify > enter 192.168.2.4 > OK.

  7. Exit Registry Editor program.
  8. Reload system software.

If the error still exits, then reimage the console PC and reload software.

Software fails to transfer to either the AU or PC due to incorrect assigned IP addresses on the network connections or Windows registry.

System software fails to launch or load with "The specified Account Already Exists" error.

User interface fails to launch after restoring the database (restoring the eventbase and nexstepbase folders from the immediate backup) with the following errors:
  • User interface fails to launch with Event Log or Event Base database error.
  • User interface fails to launch after installing with "Factory Dictionary Branch" or dictionary error.
Delete and uninstall all system software files.
  1. Delete NexGen folder in Local Disk (C:) drive.
    1. Press Windows key, select Programs > Windows Explorer.
    2. Navigate to C:\ NexGen and delete the NexGen folder.
  2. Delete NexStep folder in Regedit application.
    1. Press Windows key, and then select Run to open a dialog box on the console.
    2. Enter regedit, and select OK.
    3. Navigate to HKEYLOCALMACHINE\ Software\Beckman\ Nexstep and delete the Nexstep folder.
  3. Uninstall DxI Installer in Windows XP Add or Remove Programs.
    1. Press Windows key, select Settings > Control Panel.
    2. Select Add or Remove Programs > DxI Installer > Remove> Yes.
    3. Restart the console PC.
  4. Uninstall AU Installer in Windows XP Add or Remove Programs.
    1. Remote Desktop Sharing to the AU side.
    2. Press Windows key, select Settings > Control Panel.
    3. Select Add or Remove Programs > AU Installer > Remove> Yes.
  5. Create a new AU folder on the AU side.
    1. Remote Desktop Sharing to the AU side.
    2. Navigate to the C:\AU and rename the AU folder to AUold.
    3. Right click and select New > Folder to create a new AU folder.
    4. Copy the specific.ini file from the AUold folder into the new AU folder.
  6. Reload system software.
These can occur when software was not update all the files properly. Use Task Manger to end process any programs using the database if not able to delete the "NexGen" folder. Refer to Software: Using Task Manager procedure.
Table 98: Troubleshooting Software 5.3.1 Potential Bugs and Random Errors
Error Action Steps Note
Pipettor failed to wash Turn off instrument and turn it back on. This error occurs when failing initializing the instrument with repeating failed to wash errors across all pipettors.
CPU usage is too high

Nothing needs to be done. The event is normal. Reorganizing the database probably won't affect anything. Do not use the "Database Maintenance" button in the UI as it won't do anything helpful and may not complete in a reasonable amount of time.

If the system is available for a checkup-hour then:

  1. Check that Auto Delete is enabled.
    1. Configure >> PC Admin >> Auto Delete Setup (Access2Support).
    2. Check mark Patient, QC, and Reagents.
    3. Commonly set 14 days for patient 30 or 60 for QC.
  2. Run a consistency check (Exit if not complete in 10 minutes). Refer to Software: Database - Performing Database Consistency Check (DxI and Access2) procedure.
  3. Use DbTest application to clear in progress samples. Refer to Software: Database - Clearing In-Progress Samples (DxI and Access2) procedure.
  4. Use Fast or Poet database application to clear in-progress samples. Refer to Software: Database - Clearing In-Progress Samples (DxI and Access2) procedure.
  5. Repeat step 4, edit the Query search to SELECT* FROM BPtRepResultExtent WHERE m_eTestState < 10 , execute the Query, and then
    1. Edit each result's TestState value to 11 and store the changes.
The "CPU usage is too high" warning message in the Event Log. The "CPU usage is too high" warning message was added to the diagnostic events in the most recent software (5.3.1). It is most likely to occur when the system does the database maintenance and database size management along with the daily backup. Running database processes normally causes the CPU % usage to be high. It doesn't mean that there is a problem. The 100% CPU usage from the database server application does not stop other processes from running. It is not going to affect analytical unit operation. If it is happening other than during backup, then it might be an indication of the database getting very large or that there is a problem in the database.
Unknown handler (Bulkfeeder II) Reload the USB driver on the AU side.
  1. Remote Desktop Sharing to the AU side.
  2. Select My Computer > AU_PC (C:) > Windows > System 32 > DRVStore, and then double-click DPInst.exe.
  3. Relaunch the AUObject program when complete.
This error occurs when failing initializing the instrument with unknown handler errors.
