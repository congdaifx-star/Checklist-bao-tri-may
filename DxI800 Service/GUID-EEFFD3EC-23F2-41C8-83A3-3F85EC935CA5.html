DxI Software V5.3.1 Release Notes

Purpose
  • This document provides details of the significant features for DxI software version 5.3.1.
Confidentiality
  • Software release notes are confidential and should not be shared with customers.
Background
  • This information is only for version 5.3.1 software
  • Version 5.3.1 is compatible with Windows 8e or Windows XPe operating systems
  • Version 5.3.1 is not compatible with Windows NT operating system
  • General distribution of 5.3.1 for fielded instruments is only planned at US Government accounts and will be completed as Mod 11825
  • No general distribution is planned for fielded instruments at non US Government accounts
  • Upon regulatory clearance from all required geographies, 5.3.1 will ship with new instruments from manufacturing
    • The new "mini" Windows 8e console will be released with software version 5.3.1.
  • Software version 5.3.1 will replace the currently released version at the manufacturing cut-in date and will be available to order through finished goods
Feature Overview
  • Incorporates all features of software version 5.3.0. Version 5.3.0 was only distributed to one external customer
  • Corrected a console PC lockup bug that was only observed on software version 5.3.0 for integrated DxIs
  • A 30 second delay was added to the user interface startup to ensure the LIS serial port is functional before the software attempts to use it
  • CIA service version 2.1 was added which is required for the next version of PROService that will release and also allows for command central to not require a KVM box
  • Corrected a false substrate process monitoring error which was only observed on internal 5.3.0 instruments
Expected Behavior
  • Turning the wash tower peri pumps on in the peristaltic and vacuum pumps diagnostic screen may intermittently cause the pipettor to disabled with a failed to wash error when attempting to prime or run after exiting the diagnostic screen. Initializing will not resolve, the AUObj.exe program must be restarted if this occurs. This behavior was also present and duplicated on previous software versions (5.1).
  • Rapidly clicking the mouse or pressing function buttons while in the reagent storage subsystem screen may cause the AUObj.exe program to assert. Restart the AU to resolve. This behavior was also present and duplicated on previous software versions (5.1).
