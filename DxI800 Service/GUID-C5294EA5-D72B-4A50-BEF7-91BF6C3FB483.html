Software V1.2 Release Notes

Confidentiality

Software release notes are Confidential.

Notes

These release notes apply to the change from versions 1.0 and 1.0.1 to version 1.2 software.

Also included are the release notes for the changes from version 1.0 to version 1.0.1 software.

Purpose

This release of software is released to correct software bugs and improve operator ease of use.

Reference Documents

Installation instructions are available for this release of software and must be used to install this version of software. Other pertinent documents are referenced in Mod 6228.

New Features and Enhancements of Versions 1.0, 1.01, and 1.2 Software

New Feature Details
Release of APF Version 1.10.6. APF includes the ‘Y’ command change for Progesterone, the Dil-BhCG mixing changes, addition of Toxo-IgG, Rubella-IgG, BNPTriag, GI19-9Ag, BR15-3Ag, Grav400 maintenance assay, and addition of the blood virus assays. This change obsoletes the need for Service MOD 6220.
Adds support for blood virus assays. Changes were made in the wash wheel area that require a mandatory realignment of some devices.

This change obsoletes the need for Service MOD 6223.

Refer to Service Mod 6228 for the mandatory procedures to perform after installing this software.

The wash buffer transfer peri-pump runs with the same amount of run current as the waste peri-pump. This change obsoletes the need for Service MOD 6208 (V1.0.1).
Changes the pipettor matching algorithm to match to the pipettor that delivers the smallest volume rather than the second smallest. This change ensures that all pipettors remain the Hi Res region of the pump stroke after the pipettor matching adjustment. It is not necessary to repeat pipettor matching because of this change. Pipettor matching verify is unaffected by this change (V1.0.1).
The AU main dialog and the console About Box allow longer version numbers to be displayed. This release uses 1.486.1.6 on the console and 2.486.1.6 on the AU (V1.0.1).
Changes the sample probe plunge depth in the wash tower to improve wash efficiency (V1.0.1). Obsoletes Mod 6215.
Changes the reagent probe plunge depth in the wash tower to improve wash efficiency. This change obsoletes the need for Service MOD 6215 (V1.0.1).
Changes the substrate backdraw volume and rate to support process monitoring for both the early and newest substrate probe tubing lengths. This change obsoletes the need for Service MOD 6221 (V1.0.1).
Adds support for lab automation (sample pipettor out the back). The DxI software works with Power Processor Version 3.0 software to support the use of the automation track and sampling from the rear of the instrument. If the user has a slow LIS connection, the LIS wait timeout should be changed from 60 to 90 seconds.
Adds a Complete Initialization check box to the system initialization dialog. This option can be used to initialize the system if the hardware connection to MCC board is reset (e.g., the main covers were opened) without rebooting the AU computer.
Adds the capability to disable process monitoring during prime fluidics. This change allows the user to do priming even when the subsystem is dry.
Adds an event log message when system initialization is complete. This message reports both successful and unsuccessful attempts.
Sample pipettor dispensing checks for short dispenses (QSD flag) in addition to obstructions (CLT flag).
Changes process monitoring for the wash towers to disable a pipettor if there are three consecutive failures for vacuum or internal washing.
The system purges the condensate from the air accumulator to the solid waste bin. This purge occurs following the utility routine, but no more frequently than every 8 hours.
Adds three new tube types were to support the Japanese market.

Workarounds

The recommended workarounds for specific issues remaining in this version of software.

Issue Workaround
If priming is requested when there is no substrate, the system can lock up. Make sure there are sufficient supplies before requesting priming.
Some tests can appear to be in-process forever in the Test Results screen. This issue can be ignored, as it does not prevent other runs.

Identified and Corrected Issues

Issue Corrected or Change Made (Version 1.0.1) Notes
Opening the main covers caused the AU to crash.
Loading a rack backwards resulted in '???' being displayed permanently in Sample Manager. The '???' message is removed when the rack is unloaded from the presentation area.
Loading a rack without a tube type assigned caused a loss of communication (crash) of the AU.
Too many false QNS level sense errors in SVs. Changed the sample tolerance height.
Reagent pack mixing times not identical to the mixing times in Access 2. Changed DxI mixing timing to mimic Access 2
Pressure monitoring was too sensitive. Modified acceptance criteria to accept a wider range of pressures. This change obsoletes the need for Service MOD 6219.
The AU and PC could use different APF versions at startup. This change obsoletes the need for Service MOD 6206.
Occasionally, an APF update caused the console to crash. Fixed a correction that was inherited from Access 2.
If the Manufacturing Cleanup procedure failed, the system was left in an unusable status and no errors were reported although the cleanup continued to run.
The MCC reset signal in the firmware (V7.0A) sometimes changed state of the adjacent bits, resulting in motors that did not home. This issue has not been seen with Version 4.5 firmware, but changes were made to support both versions of firmware.
Removed the word DRAFT from the Help files.
Increased the reliability of process monitoring. Added a backlash correction to the Lo Res region of the pump stroke.
Issue Corrected (Version 1.2) Notes
Opening the main covers caused the substrate select valve to change erroneously to the bottle that was not in use. Neither in-use light was lit. Now, the system correctly recovers to the correct bottle and valve position when the main covers are opened.
The rack load sensor, when covered with a rack, created a grinding noise.
The RLU value placed an NCR flag on all maintenance assay results.
Opening the solid waste door during a run caused the system to stop initiating new tests and discarding empty reagent packs or used RVs. The solid waste door must be closed in order for the system to resume processing tests.
Jams occurred due to slow action of the vessel ejector cylinder. Increased the transit time of the vessel ejector. This change obsoletes the need for Service MOD 6225.
Test racks with undefined tube types remained in the Sample Manager screen.
The Work Pending screen performance was poor. This change necessitated changing the statistics on the screen from sample-based to test-based.
All the Multiple Host Query LIS test requests could not be handled, in some instances. Fewer test requests miss being attached to loaded sample tubes and end up in Work Pending.
In certain instances, some tests showed an inaccurate, fixed completion time when new tests were started in the middle of End of Run Utility.
Excessive number of duplicated Bulk Supply Level event messages. Reduced the number of duplicate events posted. Low and Replenished Bulk Supply messages changed from Warning (yellow) level to Informational (gray) level.
Tests sometimes remained in progress even after instrument initialization, during which all sample vessels in the sample wheel were discarded. This correction helps reduce the possibility of this occurring.
The curves for Dil-hCG2 and HBsAGBlk assays were not detected correctly when they were being run. If run simultaneously with TBhCG2 or HBsAGCtl calibrators in the absence of a valid TBhCG2 or HBsAGCtl curve, these tests go to Supply Wait
The process monitoring calibration routine incorrectly performed math calculations. This change allows more calibrations to succeed than previous software versions.
The wash pick-and-place device could be positioned incorrectly by up to 2.6%. Software using incorrect positioning tables caused this issue.
The sample pipettor was moving too far down into the 16-mm tubes that were loaded into automation or SPU sample racks. Move the sample probe height in 16-mm tubes to a slightly higher position.

Known Issues Remaining in This Version

These issues remain to be corrected in a future software release:
  • Editing an existing rack through the Sample Manager screen can show the wrong rack ID with the expected sample tube information. Only the rack ID is incorrect and can be ignored.
  • Leaving the Communications Test Dialog open for a long time (more than 8 hours) can cause an instrument software crash.
