Software V2.1 and 2.1.1 Release Notes

Purpose

This document provides details regarding important new features, enhancements, workarounds (where applicable), corrected issues, and issues remaining in DxI software version 2.1.1.

Note: These release notes apply to the changes from Version 2.0.1 through Version 2.1.1 software.

Confidentiality

Software release notes are confidential and should not be shared with customers.

Prerequisites

Prerequisites for updating and installing version 2.1.1 software.

If updating from software version Then Required Actions
prior to 2.0 before installing this software, install the wash collar (MOD 6495), aspirate probes, and duck-bill valve (MOD 6312).
1.0 the software is not customer installable. A service visit is required because all open MODs must be completed.
1.2 or 1.3 (or higher) the software is not customer installable. A service call is required because Process Monitoring must be calibrated and MOD 6495 and MOD 6312 must be completed.
If installing over software version Then And
1.4 or lower install this software recalibrate and run all assays and run QC. Verify that quality control is within customer specifications.
1.4.1 or 1.4.2 install this software run all levels of QC on all assays. Verify that quality control is within customer specifications.
2.0 or 2.0.1 the software is customer installable.

Reference Documents

Installation instructions are available for this release of software and must be used. Critical information is contained in the instructions. Failure to perform the installation correctly can result in down time in the future.

Enhancements

Note: Users must perform the new substrate back-draw auto-calibration on the substrate (in the priming screen) otherwise the instrument will not schedule tests. The AU will aliquot the samples, but it will not run them. Once the calibration is done, the run starts automatically. This change obsoletes the need for MOD 6309.
These enhancements and improvements were incorporated into this software version:
  • Added translations (English, French, German, Italian, Japanese, Spanish).
  • Added a new LIS registry switch allowing duplicate test orders to be ignored.
  • Added ability to load patient racks along with Daily Clean rack. The patient rack is aliquotted when the Daily Clean is done aliquoting. Alternatively, the patient rack can be loaded as soon as the Daily Clean is done aliquoting. In both cases, the patient tests start after the daily clean finishes.
  • Manually entered tubes no longer take precedence over bar coded tubes. When both a bar code and a manually entered sample ID are present (and different), the tube is flagged with a fatal flag and identified in the exceptions screen.
  • A volumetric check for Sample Pipettor is available for manufacturing that parks the RVs on the sample wheel.
  • Added ability to print patient name (if available) in continuous sample report.
  • System software now prevents loading APFs from another platform.
  • Changed rack Id sort order in test request from alphabetic to numeric.
  • Added 0.5-mL pediatric sample tube, an 11.5 mm x 66 mm (3.5-mL) tube, and a 15.3 mm x 92 mm (5-mL) tube. This change obsoletes the need for MOD 6462, MOD 6463 and MOD 6480.

Corrections

Note: Fixes in this release render MOD 6481 obsolete.
These issues were addressed in this release:
  • Fixed issue where aliquoting took 18 seconds instead of 9.
  • If the process monitoring is not calibrated, the system, while staying in the ready mode (blue Icon), is put in an internal state preventing the start of a test until the process monitoring is calibrated in diagnostics mode. The diagnostic calibration is no longer prevented by a disabled device.
  • Now confirmatory and screens must be run from the same tube. If a user wishes to reflex a confirmatory from a screen, the reserve volume must be enabled and provide enough sample to run the tests.
  • Wash and dispense arm scripts were adjusted to match the motion of assays (Utility, Daily, Special, etc).
  • Fixed continuous sample report pagination.
  • Refilling RV supply now resumes from Pause mode to Run mode.
  • Improved inverted RV detection when loading sample wheel.
  • Improved ESV preloading for track operations.
  • Improved AutoAlignPnP tool spring compression steps for greater precision.
  • Improved precision of volumetric checks.
  • Improved pipettor selection in the Supplies Setup screen. The instrument transitions to the Not Ready mode if a system initialization is required to re-enable the pipettor.
  • Many assert and Dr. Watson issues (crashes) avoided in favor of more graceful error handling.
  • Many reliability improvements.
  • Improved software filtering of air pressure check to prevent false errors.
  • Process monitoring can be disabled during priming.
  • Removed “Assay not found” message when an LIS request is made for an assay that is not available.
  • Dispense arm run current changed to 1.2 amps. Run hold time of dispense arm changed to 500 msec immediately before the move to place vessels. Run hold time reset to 250 msec after this move completes.
  • Increased SPU pusher motor current to reduce stall on interlock.
  • Improved the ability of pick-and-place to detect Z slippage during failed picks.
  • Implemented error recovery for aspirate, dispense, and eject plates failures.
  • Replaced reagent pipettor message: "aspiration monitor detects failure" with "possible obstruction".

Issues Not Corrected in this Version

These issues have not been corrected with the release of this software version but MAY be corrected in a future release.
  • Leaving the Communications Test Dialog open for a long time (more than 8 hours) mcan cause an instrument software crash.
  • The Diagnostics volumetric tests crash the instrument software if the weighed vessels are placed in the wrong positions on the sample wheel. The volumetric tests function properly if the vessels are placed in the correct positions. Higher impact to instrument manufacturing, low risk to field.
  • In the Diagnostics Mechanics screen, the display of encoder counts can be misleading. If the encoder value is anything other than zero when at home, then the next “move to position” value adds this home offset to the displayed value. The stored alignment value is correct in specific.ini. For example, if the value displayed at home is 4 and the move to position value displayed is 125, then the actual move was 125 minus 4, or 121.
