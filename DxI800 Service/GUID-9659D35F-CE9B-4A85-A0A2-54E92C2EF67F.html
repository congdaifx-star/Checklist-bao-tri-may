Software: Troubleshooting Windows 8 and Software 5.3.1 and Higher

Purpose

This document provide troubleshooting steps for Windows 8 system and system software 5.3.1 and higher.

Table 99: Troubleshooting Windows 8 and Software Related Messages
Error Action Steps Notes
Recurring "timing"errors or errors indicating a delay in scheduling or processing of samples on the instrument Enable multi core processing on the AU.
  • Open a remote desktop session to the AU.
  • Press the Windows key, type msconfig, and double click the msconfig.exe program to open it.
  • Select the "Boot" tab and then select the "Advanced Options" button.
  • Uncheck the "Number of processors" box, select OK, Apply, and OK.
  • Reboot the AU to enable the changes (you may be prompted to reboot when msconfig closes.
    • Open the Command Prompt icon
    • Type shutdown /r and press enter to reboot the AU
    • Close the remote desktop connection to the AU and verify the instrument initializes to ready.
Enabling multi core processing could reduce the number of these type of errors observed but may not resolve all errors. Multi core processing is enabled on Windows XP instruments. This procedure is for the DxI AU only. Enabling multi core processing on the PC will adversely affect PC performance.
CPU usage is too high error messages at 3AM or other specific times of the day. Delete Windows scheduled tasks on the AU
  • Open a remote desktop connection to the AU.
  • Press the Windows key on the keyboard.
  • Open the File Explorer icon.
  • Right click on Computer, select Manage, and then select Task Scheduler.
  • Scroll to the bottom of the Task Scheduler Summary page to see the Active Tasks.
  • Double click on a task to open it and see the details.
  • Select Delete from the menu on the right and then press OK.
  • Scroll to the top and select Task Scheduler from the top left of the Window.
  • Repeat the process for any other task to be deleted.
  • The Refresh button can be selected at any time to update the remaining tasks to be deleted. The tasks are not removed from view on the window until the Refresh button is selected.
The Windows 8 AU hard drive has scheduled tasks that are enabled on the image. The tasks can be deleted to prevent errors that occur at specific times of the day. The most common CPU usage error occurs at 3AM. All, or some of the scheduled tasks can be deleted. There are approximately 35 scheduled tasks that can be deleted.
Loss of PROService connection after instrument has already been enrolled.

Verify the CIA Service is running and change the computer settings to restart the service if it fails.

  • Starting or verifying the CIA Service is running
    • Press the Windows key, type "services" and open View Local Services in the settings search.
    • Find the CIA Service and check the status column.
    • If the status is "Running" no further actions are required.
    • If the status is blank, right click on CIA Service, and select Start. The status column should change to Running.
    • Verify PROService connection.
  • Changing computer settings to restart the CIA Service if it fails.
    • Press the Windows key, type "services" and open View Local Services in the settings search.
    • Right click on CIA Service and choose properties.
    • Click on the Recovery tab, select the drop down arrow for "First failure" and choose Restart the Service. Repeat for "Second failure".
    • Select Apply and then OK.

The CIA service is supposed to automatically launch when the PC is powered on but occasionally it doesn't start or it may stop running without notice.

Table 100: Troubleshooting Fail to Loading System Software and Launching User Interface
Error Action Steps Note
AUobject program fails to launch after an upgrade from Windows XP System to Windows 8 System.
Simulate the NVRAM through specifici.ini file.
  1. Remote Desktop sharing to the AU side.
  2. Navigate to theC:/AU folder.
  3. Open the specific.ini file in Notepad program.
  4. Search for "SimulateNVM" and change from No to Yes.
  5. Save the change and close Notepad.
  6. Launch AUobject program.
This occurs when software is not properly installed and the NVRAM has been not simulated in the specific.ini.

Software 5.3.1 and above no longer use the NVRAM PCB and requires the NVRAM to be simulated.

Critical message jams after an upgrade from Windows XP System to Windows 8 System. Clear the jammed messages. Refer to Software: Database - Clearing Jammed Critical Events procedure. This occurs when
  • The instrument attempts to send a message with an event ID smaller than what the database expects. The database does not accept a critical event message from the instrument that has an event ID lower than the ID of the last event received.
  • An illegal supply can be an onboard reagent from an assay that was deleted from the database by a software or APF update.
User interface exited after rebooting console PC with "kernel" error.
Uninstall the virtual connection that block communication between the PC and AU.
  1. Go to Device Manager and uninstall "microsoft kernel" or "virtual kernel" network connection.
    1. Press the Windows key, select Control Panel > Device Manager.
    2. Open Network Ports, right click on Microsoft Kernel Network and select uninstall.
  2. Relaunch user interface.
If error still exists, then
  1. Unplug other network cables on the console PC rather than the AU connection.
  2. Reboot the console PC.
    Note: When rebooting the Privacy & Security compliant Windows 8 or Windows 10 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

If there is no "microsoft kernel" or "virtual kernel" network connection found in Device Manager then uninstall all network cards in Device Manager and relaunch user interface.

  1. Press the Windows key, select Control Panel > Device Manager.
  2. Open Network Ports, right click on each individual network ports and select uninstall.
  3. Restart the console PC.
    Note: When rebooting the Privacy & Security compliant Windows 8 or Windows 10 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

  4. Go to each network connection and rename them in the correct order with correct assign IP address.
    • Network connection1, enter 192.168.2.3 for IP address, and 255.255.255.0 for subnet mask.
    • Network connection2, enter 172.16.1.30 for IP address, 255.255.255.0 for subnet mask, and172.16.1.1 for default gateway.
    • Network connection3, enter 134.217.96.184 for IP address, and 255.255.255.0 for subnet mask.
  5. Relaunch user interface.

Uninstall the network port/ports require rebooting the console PC to reinstall the port/ports.

If uninstalling all network ports, it is important to identify the ports in the correct order to rename the ports and reassign the IP addresses to the ports. Use the ethernet cable to plug into to each port to identify the port order. Refer to Console PC Connector Identification (DxI and Access2) document for more information.

System software fails to launch or load with "The specified Account Already Exists" error.
Delete and uninstall all system software files.
  1. Delete NexGen folder in Local Disk (C:) drive.
    1. Press Windows key and select File Explorer icon or type file explorer and open the program.
    2. Navigate to C:\ NexGen and delete the NexGen folder.
  2. Delete NexStep folder in Regedit application.
    1. Press Windows key and type regedit and open the program.
    2. Navigate to HKEYLOCALMACHINE\ Software\Beckman\ Nexstep and delete the Nexstep folder.
  3. Uninstall DxI Installer in Windows 8 Programs and Features.
    1. Press Windows key and open the control panel icon.
    2. Select Programs and Features > DxI nstaller > Uninstall > Yes.
    3. Restart the console PC.
      Note: When rebooting the Privacy & Security compliant Windows 8 or Windows 10 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

  4. Create a new AU folder on the AU side.
    1. Remote Desktop Sharing to the AU side.
    2. Navigate to the C:\AU and rename the AU folder to AUold.
    3. Create a new AU folder.
    4. Copy the specific.ini file from the AUold folder into the new AU folder.
  5. Reload system software.
Use Task Manger to end process any programs using the database if not able to delete the "NexGen" folder. Refer to Software: Using Task Manager procedure. This can occur if the software was not properly installed.
System software fails to install with "TCP/IP" not found error.
Ping the console PC and AU to confirm communication issue. The default network IP address for the console PC is 192.168.2.3. The default IP address for AU is 192.168.2.4.
  1. Press the Windows key, open Command prompt program.
  2. Type ping 192.168.2.3 for console PC and press Enter.
  3. Type ping 192.168.2.4 for AU and press Enter.
  4. If there is no reply, then check the IP address in Network Connections and change the IP address if needed.
Check and change network IP addresses.
  1. Check and change the network IP address on console PC.
    • Press the Windows key, type network connections, select Settings, and click onView Network Connections.
    • Right click on Local Area Connection, choose Properties, select Internet Protocol Version 4 (TCP/IPv4) and choose Properties.
    • Verify these settings and change as needed. If changing the IP address, ensure to click Apply and Ok to save.
      • IP address: 192.168.2.3
      • Subnet Mask: 255.255.255.0
  2. Check and change the network IP address on AU.
    • From the console PC, remote desktop to AU side. Refer to Software: Using Desktop Sharing Between Console PC and AU procedure.
    • If remote desktop fails, then connect the monitor, mouse, and keyboard to the AU side to change the IP address.
    • Press the Windows key, type network connections, select Settings, and click onView Network Connections.
    • Right click on Local Area Connection, choose Properties, select Internet Protocol Version 4 (TCP/IPv4) and choose Properties.
    • Verify these settings and change as needed. If changing the IP address, ensure to click Apply and Ok to save.
      • IP address: 192.168.2.4
      • Subnet Mask: 255.255.255.0
  3. Ping the both console PC and AU to confirm communication issue is fixed.
  4. Reload system software.

If the console PC and AU IP addresses are correct, then check and change IP addresses in the registry:

  1. Press Windows key, type regedit, and open the program.
  2. Browse to HKEY_LOCAL_MACHINE > SOFTWARE > Beckman > NexStep.
  3. On the right hand side of the Registry Editor pop-up box, verify the PrimaryConsoleIPAddress is 192.168.2.3

    If not, then right click on PrimaryConsoleIPAddress > Modify > enter 192.168.2.3 > OK.

  4. Select Workgroup folder under the NexStep folder and verify the AuIp is 192.168.2.4

    If not, then right click on the AuIp > Modify > enter 192.168.2.4 > OK.

  5. Exit Registry Editor program.
  6. Reload system software.

If the error still exits, then reimage the console PC and reload software.

Software fails to transfer to either the AU or PC due to incorrect assigned IP addresses on the network connections or Windows registry.
System software fails to install with " Communication failed between the PC and instrument. Contact your local service representative for assistance" message error. Change the Console PC name to "Console_PC" if the PC name is different other than "Console_PC."
  1. Press Windows key, select Control Panel icon or type control panel and open the program.
  2. Double click on System, select Change settings on the middle left side of the System pop-up box.
  3. On the System Properties pop-up box, select Computer name tab and click on the Change option.
  4. Enter Console_PC as the Computer Name.
  5. Click OK to save the change, select Yes to "Do you want to use this computer name?" prompted message, and select OK to "You must restart your computer to apply these changes" prompted message.
  6. On the System Properties pop-up box, change the Computer description to match the computer name, and select Apply > Restart Now to restart the PC.
    Note: When rebooting the Privacy & Security compliant Windows 8 or Windows 10 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

  7. Reload system software.

If the error still exits, then reimage the console PC and reload software.

This error occurs when the software installer was looking for a specific computer name such as Console_PC in registry but found an incorrect name (example: 601115_PC). Remember to change the PC name (example: 60115_PC) back to avoid any communication conflicting issue.
"Duplication network cards detected and select the network card from the following list" and fail to load software or fail to launch user interface.

Uninstall all network cards in Device Manager and reload software.

  1. Press the Windows key, select Control Panel > Device Manager.
  2. Open Network Ports, right click on each individual network ports and select uninstall.
  3. Restart the console PC.
    Note: When rebooting the Privacy & Security compliant Windows 8 or Windows 10 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

  4. Go to each network connection and rename them in the correct order with correct assign IP address.
    • Network connection1, enter 192.168.2.3 for IP address, and 255.255.255.0 for subnet mask.
    • Network connection2, enter 172.16.1.30 for IP address, 255.255.255.0 for subnet mask, and172.16.1.1 for default gateway.
    • Network connection3, enter 134.217.96.184 for IP address, and 255.255.255.0 for subnet mask.
  5. Reload software.

If the duplication network still exists, then reimage the console PC and reload software.

This error occurs because Windows detects there is another network connection with same IP address or name in the network.

Uninstall the network port/ports require rebooting the console PC to reinstall the port/ports.

If uninstalling all network ports, it is important to identify the ports in the correct order to rename the ports and reassign the IP addresses to the ports. Use the ethernet cable to plug into to each port to identify the port order. Refer to Console PC Connector Identification (DxI and Access2) document for more information.

Table 101: Troubleshooting Software 5.3.1 Potential Bugs and Random Errors
Error Action Steps Note
Pipettor failed to wash Turn off instrument and turn it back on. This error occurs when failing initializing the instrument with repeating failed to wash errors across all pipettors.
CPU usage is too high

Nothing needs to be done. The event is normal. Reorganizing the database probably won't affect anything. Do not use the "Database Maintenance" button in the UI as it won't do anything helpful and may not complete in a reasonable amount of time.

If the system is available for a checkup-hour then:

  1. Check that Auto Delete is enabled.
    1. Configure >> PC Admin >> Auto Delete Setup (Access2Support).
    2. Check mark Patient, QC, and Reagents.
    3. Commonly set 14 days for patient 30 or 60 for QC.
  2. Run a consistency check (Exit if not complete in 10 minutes). Refer to Software: Database - Performing Database Consistency Check (DxI and Access2) procedure.
  3. Use DbTest application to clear in progress samples. Refer to Software: Database - Clearing In-Progress Samples (DxI and Access2) procedure.
  4. Use Fast or Poet database application to clear in-progress samples. Refer to Software: Database - Clearing In-Progress Samples (DxI and Access2) procedure.
  5. Repeat step 4, edit the Query search to SELECT* FROM BPtRepResultExtent WHERE m_eTestState < 10 , execute the Query, and then
    1. Edit each result's TestState value to 11 and store the changes.
The "CPU usage is too high" warning message in the Event Log. The "CPU usage is too high" warning message was added to the diagnostic events in the most recent software (5.3.1). It is most likely to occur when the system does the database maintenance and database size management along with the daily backup. Running database processes normally causes the CPU % usage to be high. It doesn't mean that there is a problem. The 100% CPU usage from the database server application does not stop other processes from running. It is not going to affect analytical unit operation. If it is happening other than during backup, then it might be an indication of the database getting very large or that there is a problem in the database.
Unknown handler (Bulkfeeder II) Reload the USB driver on the AU side.
  1. Remote Desktop Sharing to the AU side.
  2. Select Computer > Local Disk (C:) or AU_PC (C:) > Windows > System 32 > DRVStore, and then double-click DPInst.exe.
  3. Relaunch the AUObject program when complete.
This error occurs when failing initializing the instrument with unknown handler errors.
Backup fails with the "system cannot find the file specified" or file not found errors.

Check the USB flash (E:) drive to ensure its name is properly named "BACKUPDRIVE."

  1. Press Windows key and select File Explorer icon.
  2. Navigate to Computer to see the USB flash (E:) drive. The drive name has to be "BACKUPDRIVE."
  3. If the (E:) drive has different name other than "BACKUPDRIVE," then rename the drive to "BACKUPDRIVE."
    • Right click on (E:) drive and select rename.
    • Enter "BACKUPDRIVE."
      Note: If the USB flash cannot be renamed or is write-protected, then replace the drive.
  4. Perform immediate backup. Refer to Software: Creating Immediate Backup (Tape or USB) procedure.

If the USB flash drive name is correct, but it was plugged into the console PC after the user interface was launched, then

  1. Exit the user interface.
    • Press [Alt] + [F4], and then enter the password Access2Support and hit [Enter].
  2. Relaunch the user interface and perform immediate backup. Refer to Software: Creating Immediate Backup (Tape or USB) procedure.

Check the USB flash drive to ensure its drive letter is correct. The default USB flash drive letter is (E:).

  1. Press Windows key, select File Explorer icon. Press Windows key, select File Explorer
  2. Navigate to Computer and check all the drive letters to ensure they are assigned correctly.

    The followings are the default drive letters for the Windows 8 console PC.

    • The console PC hard drive letter is (C:) drive.
    • The CD-ROM or DVD drive letter is (D:) drive.
    • The USB flash drive letter is (E:).
  3. Change the USB flash drive letter and CD drive letter if they are swapped or incorrect (example: USB flash drive letter is (D:) and CD drive letter is (E:)).
    • Press Windows key, select Control Panel > Administrator Tool > Computer Management.
    • In the Computer Management box, select Storage > Disk Management.
    • Select the CD drive in the upper left box or the bottom left box, then right click and select Change Drive Letter and Paths... > Change.
    • In the Change Drive Letter or Path box, select Assign the following drive letter's letter drop box > F > OK > Yes.
    • Select the USB flash drive in the upper left box or the bottom left box, then right click and select Change Drive Letter and Paths... > Change.
    • In the Change Drive Letter or Path box, select Assign the following drive letter's letter drop box > E > OK > Yes.
    • Go back and change the CD drive to D.
      Note: Change the CD drive to D will prevent APF fails to load issue.
  4. Perform the immediate backup. Refer to Software: Creating Immediate Backup (Tape or USB) procedure.
This error can occur if the USB flash is not recognized by the user interface or named correctly. The error can also occur if the (E:)drive and (D:) drive are swapped. This happens more frequently on the Windows 8 console PC because the USB CD drive is an external device and sometimes it is installed after the USB flash drive.
APF fails to load or update with "Wrong drive" , "APF disk does not contain valid APF information" or "APF disk not recognized" errors. Check the CD drive to ensure its drive letter is correct. The default CD drive letter is (D:).
  1. Press Windows key, select File Explorer icon. Press Windows key, select File Explorer
  2. Navigate to Computer and check all the drive letters to ensure they are assigned correctly.

    The followings are the default drive letters for the Windows 8 console PC.

    • The console PC hard drive letter is (C:) drive.
    • The CD-ROM or DVD drive letter is (D:) drive.
    • The USB flash drive letter is (E:).
  3. Change the CD drive letter and USB flash drive letter if they are swapped or incorrect (example: USB flash drive letter is (D:) and CD drive letter is (E:)).
    • Press Windows key, select Control Panel > Administrator Tool > Computer Management.
    • In the Computer Management box, select Storage > Disk Management.
    • Select the CD drive in the upper left box or the bottom left box, then right click and select Change Drive Letter and Paths... > Change.
    • In the Change Drive Letter or Path box, select Assign the following drive letter's letter drop box > F > OK > Yes.
    • Select the USB flash drive in the upper left box or the bottom left box, then right click and select Change Drive Letter and Paths... > Change.
    • In the Change Drive Letter or Path box, select Assign the following drive letter's letter drop box > E > OK > Yes.
    • Go back and change the CD drive to D.
      Note: Change the CD drive to D will prevent APF fails to load issue.
  4. Check the APF Load Path to ensure it is assigned to the correct drive. Refer to Software: Changing File Paths on Console PC (DxI and Access 2) procedure.
    Note: The default APF Load Path is assigned to D: drive.
  5. If the load path is incorrect, then modify the load path to D: drive. Refer to Software: Changing File Paths on Console PC (DxI and Access 2) procedure.
  6. Reload or update the APF.

If APF fails to load because of the version issue, then refer to Software: Installing Previous APF Version procedure.

This can occur if the (E:) drive and (D:) drive are swapped. This happens more frequently on the Windows 8 console PC because the USB CD drive is an external device and sometimes it is installed after the USB flash drive. This can also occur if the APF Load Path is assigned to the wrong drive.
User interface is not displayed as a full screen. Adjust or change the screen resolution. Refer to Step 11. of the Instrument: Windows 8 Console PC and AU Navigation procedure. This can occur if the screen resolution adjustment was not performed.
User interface is abnormal (has missing or misaligned display icons). Adjust or change the display setting. Refer to Step 11. of the Instrument: Windows 8 Console PC and AU Navigation procedure. This can occur if the display text or other items were not to default setting. This affects the user interface's supplies screen and alignment screen. It may affect other screens.
The monitor displays blank areas at the top and bottom of the user interface. Adjust or change the display scale in Intel HD Graphics card installed in the Windows 8 console PC. Refer to Step 11. of the Instrument: Windows 8 Console PC and AU Navigation procedure. This can occur if the Intel HD Graphics card was not set properly.
