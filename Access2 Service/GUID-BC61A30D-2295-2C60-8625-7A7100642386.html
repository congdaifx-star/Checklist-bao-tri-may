Software Version 3.4

Access 2 Software Release Notes Version 3.4

Intended Use

For Internal Use Only - Sensitive data intended for use within BCI and normally shared with employees. There may be an occasional need to distribute this data outside the company with Management approval.

Scope

Software version 3.4 is based on the previous release 3.3 code base and will support both XP and NT consoles.

DxC 600i platforms will require a separate software release and is outside the scope for v3.3.

PCA Corrective Action

Software version 3.4 was recalled via PCA 14932-2.

  • During Limited Distribution, through customer feedback, it was confirmed that this software version has a potential to cause communication errors between the instrument and the console computer. If the communication error occurs, the system halts any samples in-process and test results will not be reported.
  • Mod 11259 was released to remove 3.4 software.

Software 3.4 Implementation

Software 3.4 was installed on a limited number of instruments in 2013. The software version was removed from these instruments via Mod 11259 in 2013.

Software Details

These are the details of 3.4 features and improvements.
Component Improvement Details

CAPA 14932 - Pack Monitoring

The pressure monitor in the Main Pipettor will sense whether sufficient reagent is dispensed for testing. Reagent pack monitoring can detect unexpected levels of reagent in the pack, thereby avoiding errors due to improper pack loading.

New instrument pressure monitoring features:
  • If sufficient reagent is not dispensed from a reagent pack, then test replicates will be flagged with QSD and events will be reported in the event log.
  • If the system detects a pattern of reagent pack monitoring failures, then the main pipettor may set to disable or the pack may be rejected.
New columns are located in Diagnostic Copy to Disk file:
  • reps remaining in the pack.
  • number of dispense failures.
The new section "BO_Packs_Dispense_Record" is located at the end of Diagnostic Copy to Disk file and contains:
  • Pack barcode.
  • POET ID of test replicate (allows tracking to Sample ID).
  • assay number.
  • well number of reagent pack.
  • volume of reagent dispense.
  • pressure data.

For more detailed information, refer to Theory of Operation - Pack Monitoring.

Diagnostic Copy To Disk

The Diagnostic Copy to Disk csv file will use the User Interface Test Results value for RLU, calibrated result, user result, unadjusted result, and adjusted result. Previously RLU values over 1,000,000 were rounded to 6 significant places in the Diagnostic Copy to Disk.

Pack mixing commands

Create new V and I command for reagent pack mixing. These pack mix commands are for support of future assays.
  • V command - 2 second mix designed to re-suspend settled microparticles.
  • I Command - 6 second mix designed to re-suspend settled microparticles.

Quality Control Screens

  1. Whenever a control rep is generated, the system will now ensure that a tile is created.
  2. New behavior that accompanies the software fix only allow users to program QC replicates for assays included in the QC setup.
  3. Example: RBC control is configured for only assay RBC2 but the customer wants to run FOL2 on this control. They will have to delete the RBC2 from the QC Control Setup (because RBC2 and FOL2 are different sample types), then add FOL2 or create a new control setup entirely.
  4. The Levey Jennings charts displayed on the QC Chart and Data screen will use more precise data (to more decimal points) to calculate the y-axis standard deviation coordinates. This prevents rounding errors which previously caused y-axis coordinates to display incorrectly.

Thermal

Updated temperature data storage for assays started during the utility assay - ensures that the Access 2 records the case temperature once each 36 seconds for each running replicate.

Create new events when user attempts to install a DxI APF on an Access 2 instrument or attempts to install a non-thermal APF on an instrument upgraded to the thermal APF. Previous version of software will assert rather than creating an event in the event log.

Updates for compatibility APF framework changes required for DxI. Does not affect Access 2 behavior.

Volume Checks

The Dispense Probe 3 volume check will now include an operation to remove belt backlash, similar to the Dispense Probe 2 volume check.

New and Updated Events

Reagent Pack Monitoring events:
  • Reagent pack monitoring reset after repeated measurements outside limits
  • Reagent pack monitoring device failure
  • Unable to initialize system due to disabled main pipettor
  • Reagent pack monitoring detected insufficient reagent
  • Pressure during reagent dispensing was not as expected
  • Reagent dispense monitoring reset due to drift from original measurements
  • Reagent pack volume set to zero after repeated monitoring failures
  • Main pipettor disabled after repeated dispensing failures
APF issues events:
  • APF update attempt with a disk from another system failed
  • APF update attempt with a disk from a previous revision failed
Updated Events - added the word Main before Pipettor:
  • Main Pipettor X-Axis Motion Error
  • Main Pipettor Motion Error - Front Panel Open
  • Main Pipettor Motion Error

Updated Event details: Vacuum Under Limit Error|Vacuum Under Limit

LIS Vendor Document Update

The LIS Vendor document is updated to state that patient ID is a required field. Refer to version 387264J or higher .
