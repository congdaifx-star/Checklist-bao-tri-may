Software Version 1.4.5

Access 2 Software Release Notes Version 1.4.5

Intended Use

For Internal Use Only - Sensitive data intended for use within BCI and normally shared with employees. There may be an occasional need to distribute this data outside the company with Management approval.

Scope

These release notes apply to upgrades from version 1.4.1 software to version 1.4.5 software. Version 1.4.4 was only sent to a short list of approximately 6 customers for an early release of CK-MB but that version did have several software changes and the release notes for that version have been combined with version 1.4.5 release notes.

1.4.2: There were no release notes associated with version 1.4.2 as there were only Help System changes and an APF change to add two assays.

1.4.3: There were no release notes associated with version 1.4.3 as there was only one correction made to resolve an issue uncovered by version 1.4.2.

Additions or Enhancements

  • Removed the "Pop-up" window informing the user that no new tests had been requested. This message typically appeared when an operator loaded a rack of new samples onto a running system and the LIS had not yet responded with a test list. The operator can now walk away from the system after pressing Run when loading on the fly.
  • Added support for the new CK-MB assay, test #163.
  • Help System modified for updates to US and International assay manuals.

Corrections

  • Corrected an issue whereby a short- or no sample pick up condition could result when using pour off tubes with specific assays (PSA, Total T4, Thyroid Uptake, Dil-hCG, CKMB & CK-MB (old & new formulation)). This was caused by a premature triggering of the fluid level detection mechanism and was corrected by increasing the air gap by 5ul.
  • Corrected a condition whereby a correct result could be reported to the LIS host but the same result to the continuous sample report or Access 2 database was marked as cancelled, with no actual result, following a system error. This was caused by a rare timing issue and has been corrected by not suppressing calculated results after a vessel has passed the luminometer, regardless of system error or user intervention.
  • Corrected a condition whereby the system, through direct user intervention, could attempt to perform a calibration across two different lots of reagent and report the calibration associated with the latter reagent lot. This has been corrected by preventing any in-progress calibrations from being altered.
  • Corrected an issue whereby a correct QC value could be stored as part of the wrong QC lot if a QC lot number change was made in the Test Request screen. This resulted if the system had multiple QC lots configured with the same QC name and the user selected a particular QC lot and then changed to another lot with the same QC name. This has been corrected by properly updating the database if the QC lot is changed in test request.
  • Corrected a condition whereby a user incorrectly reported the RLU of a test instead of repeating the test due to a "NCR" flag. This was addressed by changing the format to remove the RLU field of several screens and reports. The RLU field is still available on the continuous sample report and in the test results screen.
  • Corrected a condition in which there was inconsistency in the presentation of results when comparing the QC copy to disk and Test Results copy to disk to other reports and screens, the copy to disk functions were inconsistent and have been corrected.
  • Corrected a condition whereby a user could "un-omit" a QC point that had been automatically omitted by the system due to a Fatal or OVR flag. The user could "un-omit" these points causing invalid data to be calculated into the QC information. The fix prevents the user from un-checking the omit point box.

Contact

Contact your local support organization with any questions or concerns.
