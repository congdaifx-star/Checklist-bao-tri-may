Software Version 1.1

The primary focus of software version 1.1 is correction of issues related to the LIS function.

Confidential

Software release notes are to be considered Beckman Coulter, Inc. company confidential and treated as such.

Background

Included in release are issues identified at Early Look customers related to consistency of behavior between the Access 2 and the Base Access product. Several of these issues are the result of the Base Access product not performing as per the Base Access LIS Vendor Information Specification. However, in order to meet the requirement of plug and play compatibility between the Access 2 and the Base Access LIS connection, the Access 2 specifications and software are being updated to match the Base Access implementation with regard to several identified issues.

Reference Documentation

Refer to the Access 2 LIS Vendor Information document in the on-line Help system as necessary for specific field references. Also refer to the LIS Information Update documentation included with the software upgrade kit.

Issues Identified and Corrected

The following nine issues with descriptions have been addressed in this release.

  1. Issue: Access 2 will reject LIS test order records which do not contain a priority code, Base Access will apply a default priority of routine to any test order record which does not contain a priority code. Resolution: Update the Access 2 LIS software to accept test order records which do not specify a priority code.
  2. Issue: Access 2 will reject LIS test order records which do not identify a specimen type, Base Access will apply a default specimen type of serum to any test order record which does not identify type. Resolution: Update the Access 2 LIS software to accept test order records which do not specify a specimen type and do not already contain a test list. When no specimen type is specified the request will default to that of the first test in the list.
  3. Issue: Queries from racks containing more than one sample may result in the some responses not being attached to samples and some responses not stored in the database. No indication of failure is sent to the LIS in these conditions. Resolution: Modify the Access 2 LIS software to reliably attach the responses to samples and properly store the responses in the database.
  4. Issue: The instrument ID is not sent in LIS header record if the customer unloads and clears the rack prior to the system sending the results to the host. Resolution: Modify the Access 2 LIS software to include instrument ID with all results using the references available in the database.
  5. Issue: Test orders downloaded successfully via host query will not requery the host is the sample tube is reloaded within one hour of the original query. Resolution: Modify the Access 2 LIS software to allow a requery of a sample after 5 minutes from the original query but only if the sample tube does not already contain a test list.
  6. Issue: The LIS will reject all test order records using Action Code ‘N’ with a "Sample already exists" response if the sample exists in the database. This will cause all host query responses which use Action Code ‘N’ to be rejected. Resolution: Modify the Access 2 LIS Server to accept an ‘N’ in the Action Code in test order records if either the sample ID does not exist in the system or the sample ID exists but does not have a test list.
  7. Issue: The Access 2 only accepts case sensitive test codes sent by the LIS Host (e.g. Ferritin is accepted, FERRITIN is rejected). This specification is consistent with the Base Access LIS Vendor Information Specification. However, Base Access implementation accepts case insensitive test codes. Resolution: Modify the Access 2 LIS software to accept case insensitive test codes in test order records.
  8. Issue: The Access 2 requires the Action Code field to be present in test order records. This specification is consistent with the Base Access LIS Vendor Information Specification. However, Base Access implementation accepts test order records which do not contain an Action Code and applies a default of "A" for add. Resolution: Modify the Access 2 LIS software to accept test order records which do not contain an action code and apply the default of "A" for add.
  9. Issue: The Access 2 LIS Vendor Information Specification defines use of delimiters in LIS messages. The Access 2 implementation will reject any message that does not use the delimiters as specified. Base Access will allow the LIS header record to redefine delimiters as any of the valid characters, as specified in ASTM E1394-97 to be used. This issue has not been shown to have any commercial impact. However, addressing this issue will help to mitigate the risk of impacting plug and play compatibility between Base Access and Access 2. Resolution: Modify the Access 2 LIS software to allow the LIS header record to redefine delimiters to any valid character, as specified in ASTM E1394-97.
