Promoting Client Using Previous Backup

This document provides instructions for restoring the database when promoting a client to the role of server. For additional assistance, links to instructions for performing specific tasks are included.

The restore procedures are written to cover specific restore scenarios. Use this restore procedure only for restoring the database onto a PC that was a client.

Do not use this procedure if the backup immediately preceded this restore. In that case, refer to the procedure that uses an immediate backup for restoration. If you are uncertain which restore procedure to follow, contact your local support office.

Use this type of restore to move the database, because of catastrophic failure, from the server PC to a promoted client PC using a previous backup.

Note: Using a previous backup to restore, causes the loss of reagents, substrate, and waste bag because the backup was performed at an earlier point in time and no supply updates have been recorded since.

A brief overview of the process that occurs during a Promote Client Restore:

  • Prepare the future server (LIS and UPS connections) and identify IP address.
  • Copy backup snapshot onto PC hard drive.
  • Restore server settings.
  • Reconfigure client settings.
  • Physically clear supplies for every Access 2 system in the workgroup.
  • Logically clear supplies for the Access 2 workgroup.
Note: To prevent unexpected results, read each step completely before executing any instructions in that step.
  1. Identify the IP addresses of the new server combination.
    This information is necessary to ensure communication between the AU and the PC of the new server combination and between the clients and the server.
    Note: The server is identified as the only system in the workgroup where the date and time can be changed.
    1. To turn off all AUs (instruments) and PCs (consoles) in the workgroup:
      Note: Shut down all clients first.
      • Power down the AU (instrument).
      • Perform PC shut down from PC Admin. From the Main Menu, select Configure > PC Admin > Shut Down PC to exit the software in preparation for shutting down the PC. If the system is the server, a window is displayed, instructing the user to shut down all client PCs before shutting down the server.
      • After the instrument software has shut down, power off the PC.
    2. Disconnect the LIS from the previous server PC, and reconnect the LIS to COM port 2 of the multi-com cable on the future server.
    3. To make proper electrical connections to the UPS, refer to the connection diagram and installation instructions for Access 2 (Access 2 Peripheral Connection Diagram).
    4. Power on the PC of the future server. Press and hold the [Ctrl] key to prevent the user interface from launching when the Windows NT logo bitmap is displayed until the Windows NT task bar is displayed.
      Note: The touch screen software might also be prevented from launching.
    5. Select Start  > Programs > Access2 > Restore Utility.
    6. Select Modify PC Specific Registry. A dialog is displayed containing:
      • Current Console IP address (the IP address of the console you are working from)
      • Workgroup Server IP address (the PC the backup was performed on - the previous server)
      • Instrument IP address (the IP address of the AU connected to the PC you are working from)
    7. Record these IP addresses and retain them for use later.
    8. Select OK > Exit.
  2. Copy the backup snapshot onto the PC hard drive, and prepare for server and client restore.
    1. Insert the most recent backup tape into the client PC that will become the new server.
    2. Launch the NT Backup Utilities by selecting Start > Run, typing ntbackup, and then selecting OK.
    3. Display (or maximize) the Backup - [Tapes] screen from the lower left corner of the display, if necessary.
    4. Select the correct set from the right pane by selecting the box to the left of the set.
    5. Select the Restore button (toolbar, top left) to open the Restore Information window. Accept all defaults on the popup window, and select OK.
    6. A Restore Status window is displayed. When prompted with Confirm File Replace message, select Yes to All. The information from the previous server is copied onto this PC.
    7. When the Restore Status window displays the message The operation was successfully completed, select OK.
    8. Select Operations  > Exit to exit the Backup Utility.
      Note: Exiting the Backup Utility can take a few minutes while the tape rewinds (depending on database size).
  3. Reconfigure the IP addresses for communication to occur between the remaining clients and the new server.
    1. Still at the new server, select Start > Programs > Access2 > Restore Utility.
    2. Select Restore Registry and Database > Yes. A check mark in the adjacent box indicates completion.
    3. Select Modify PC Specific Registry to display a dialog containing:
      • Current Console IP address (the PC you are sitting at)
      • Workgroup Server IP address (the PC the backup was performed on - the previous server)
      • Instrument IP address (the AU connected to the PC that the backup was performed on - the previous server)
    4. Retrieve the IP addresses retained from the Identifying IP Addresses step. Use the addresses to make the necessary changes to the IP addresses.
      Note: The following are examples only and actual IP addresses can vary.

      Example:

      • Current Console IP: 192.198.2.5
      • Workgroup Server IP: 192.168.2.3
      • Instrument IP: 192.168.2.4

      Change to

      • Current Console IP: no change
      • Workgroup Server IP: 192.168.2.5
      • Instrument IP: 192.168.2.6

      After making the necessary changes, select OK.

    5. Power on the AU that is connected to this console, and wait 1 to 2 minutes before proceeding.
    6. In the Restore Utilities window, select Clear Instrument Critical Messages. A check mark in the adjacent box indicates completion.
      Note: The Database Management function is necessary when using a previous backup and will be used later in this procedure.
    7. Reboot the AU.
    8. Select Exit.
    9. Reboot the PC, and allow the user interface to launch.
  4. Change the IP address on each client PC to ensure communication to the server and the database. Repeat this step for each client in the workgroup.
    1. Move to the first client PC in the workgroup, and power it on. Press and hold the [Ctrl] key to prevent the user interface from launching when the Windows NT logo bitmap is displayed until the Windows NT task bar is displayed.
      Note: The touch screen software might also be prevented from launching.
    2. Select Start  > Programs > Access2 > Restore Utility.
    3. Select Modify PC Specific Registry to display a dialog containing:
      • Current Console IP address (the PC you are sitting at - do not change)
      • Workgroup Server IP address (the IP address of the previous server - requires a change)
      • Instrument IP address (the AU connected to the PC that you are sitting at - do not change)
    4. Change the Workgroup Server IP address on this client.
    5. After making the necessary change, select OK.
    6. Power on the AU that is connected to this console, and wait 1 to 2 minutes before proceeding. If the system does not initialize, reboot the AU after completing the next step.
    7. In the Restore Utilities window, select Clear Instrument Critical Messages (you can make this selection during initialization). A check mark in the adjacent box indicates completion.
    8. Select Exit.
    9. Reboot the PC, and allow the user interface to launch.
    10. Repeat this step for the remaining clients in the workgroup.
  5. Remove all reagent packs from the reagent carousel of each AU in the workgroup. Do not attempt to process any samples, including system check.
    This system (or workgroup) has been restored, but is not ready to process samples because the database is restored to a previous point in time and the reagent counts reflect that earlier time.
    Note: Perform these steps on all systems in the workgroup. You can start with any system.
    1. In the Mechanics screen, select Sample carousel.
    2. Manually remove any sample racks on the carousel.
    3. Select Reagent carousel, and manually remove any reagent packs on the carousel.
    4. Perform a visual inspection of all removed packs, and discard all punctured reagent packs. Any packs that have not been punctured can be reloaded later.
    5. Record the reagent name, lot number, and serial number for use during the Database Maintenance function.
    6. Initialize the system, if necessary.
    7. Load a new substrate bottle and change the waste bag.
    8. Repeat this step for all remaining systems in the workgroup.
  6. Return the database to a consistent state. Exit the user interface on all clients before performing this step.
    1. To exit the user interface at the server, select [Alt] + [F4], type (password) Access2Support (case-sensitive).
    2. Select Start  > Programs > Access2 > Restore Utility.
    3. In the Restore Utilities window, select Database Maintenance.
    4. In the Database Maintenance window, select Correct inconsistent records and unload packs/racks logically.
    5. In the Database Maintenance window, locate the Possible Unpunctured Reagent Packs list that includes reagents that were unpunctured at the time of the previous backup. Use this list and the list created from the visual inspection of the reagent packs in the previous step to identify packs that were punctured during the time between the last backup and this restore.
    6. In the Database Maintenance window, select any packs on the list that have been punctured, and then select Delete Selected Reagent
    7. Select Close > Exit, and then reboot the server PC.
    8. Reload any packs that are unpunctured.
    9. The system or workgroup is ready to process tests.
