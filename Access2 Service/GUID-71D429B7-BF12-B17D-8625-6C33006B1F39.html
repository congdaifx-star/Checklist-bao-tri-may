Software Version 1.4.1

Access 2 Software Release Notes Version 1.4.1

Intended Use

For Internal Use Only - Sensitive data intended for use within BCI and normally shared with employees. There may be an occasional need to distribute this data outside the company with Management approval.

Scope

These release notes apply to upgrades from Version 1.4 software to Version 1.4.1 software. There were a number of significant changes made to the software in the 1.1 - 1.4 releases, which are described in the Version 1.1 - 1.4 release notes but are not further described here in the Version 1.4.1 release notes. Version 1.1-1.4 software had some bug fixes and those release notes should be reviewed as well.

Additions or enhancements to this release

The DbTest application was modified in order to use the new database repair functionality. By selecting Consistency Check button the database consistency check will run. Additionally, if the Fix Problems box is checked, some inconsistencies will be repaired. The database will be opened in local mode, therefore this functionality is only available on the server computer. When a repairable inconsistency is encountered on an object it is fixed and a detailed message is written into a log file (C:\NexStep\Pc\DbRepair.log) . This log can be used by Software Development for further troubleshooting if necessary.

Problems corrected in this release

Issue: A problem was corrected that caused the instrument to fail to complete the scanning of a rack. The problem was caused by an error in the serial port configuration of the instrument. A script file containing the fix for the rack scanning lockup is uploaded to the instrument during the installation.

The use of Access2 1.4 Supplemental Service CD is no longer required to correct this problem.

Issue: A problem was corrected which prevented the latest event descriptor updates (new event log messages) from being loaded into the database. This problem was caused by an error in the algorithm, which determined the date/time of the last event descriptor update. The algorithm of loading event descriptors was modified to properly handle all dates variations.

The use of Access2 1.4 Supplemental Service CD during installation is no longer required to correct this problem.

Issue: Results transmitted to a Host LIS system will be in English, even if the user interface is set to another language. In Result records, the fluid type and interpretation of result were being sent in the same language as the user interface. All comments sent to the LIS Host were also in the local language. With this change, these fields will always be sent in English, regardless of whether language for the user interface is set to English or another language.

Issue: A problem was corrected, that made it impossible to exit the Patient ID field of the Test Request screen under certain conditions. The specific steps to reproduce this problem were as follows:
  1. Access 2 receives a patient ID from the LIS Host, which contains leading or trailing spaces .
  2. The sample associated with that patient ID is added to a rack.
  3. The rack is loaded onto the system.
  4. The cursor is placed in the patient ID edit box
  5. The user tries to exit that edit box - the user interface would pop up a dialog stating “You cannot change the patient ID. The rack is loaded.” and not allow the user to exit that edit box or exit the screen.

or

  1. Access 2 receives a patient ID from the LIS Host, which contains leading or trailing spaces .
  2. The sample associated with that patient ID is added to a rack.
  3. The rack is loaded onto the system.
  4. One or more tests are added to the sample.
  5. The tests are started on the system.
  6. The cursor is placed in the patient ID edit box
  7. The user tries to exit that edit box - the user interface would pop up a dialog stating “Unable to change Patient I.D. Tests are in progress.” and not allow the user to exit that edit box or exit the screen.

This problem was due to the patient ID edit box trimming the leading and trailing spaces from the patient ID prior to exiting the field. This caused the software to incorrectly determine that patient ID had been changed by the user.

Access 2 will still allow the LIS Host to send patient IDs with leading or trailing spaces, but will ignore the spaces when exiting the patient ID field of the Test Request screen.

Issue: A problem was corrected where that Access 2 was incorrectly handling improperly formatted birth dates from the LIS. Improperly formatted birth dates received through LIS would cause an exception during the calculation or upload of a result (see examples below). We now identify and exclude all improperly formatted birth dates. When an improperly formatted birth date is received, the birth date field is set to unknown and an informational message is sent back to the LIS Host. Additionally, an entry is created in the Event Log detailing the birth date as it was transmitted.

Some LIS Hosts that had no patient birth date information to send would instead send garbage characters such as ??/??/?? instead of a blank field. Other identifiable improperly formatted birth dates contained switched month and days such as 30/04/2001. We now accept only properly formatted birth dates from January 2, 0100 to the present time. No future birth dates are allowed.
