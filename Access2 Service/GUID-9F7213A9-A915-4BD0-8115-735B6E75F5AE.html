Replacing Console PC

This procedure describes how to replace the Access 2 console PC.

Perform this procedure when the PC needs to be replaced.

Note: The PC hard drive might be recoverable, if the failure is an OS corruption (last known good menu, or blue screen), and not a hardware failure (HDD boot error). The procedures below might be an option for repairing a PC hard drive.
  • Re-image Windows 8 Console PC
  • Re-image Windows 10 Console PC
Note: The hard drive of the Privacy & Security compliant Windows 8 or Windows 10 console PC cannot be changed separately from the PC itself. The hard drive & motherboard are paired with a unique encryption key and will not function if separated. You must replace the console PC for P&S console failures.
Note: When rebooting the Privacy & Security compliant Windows 8 or Windows 10 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

  1. Replace the console PC.
    Note: Refer to the Console PC Connector Identification (DxI and Access2).
    Note: If replacing an older PC model with a Windows 10 PC, follow Installing Access2 Enhanced Instrument procedure Step 8e for mounting the combination Monitor with PC and PC bracket to the monitor arm.
    1. Replace the PC with the new PC, making all necessary connections.
      • Power cord
      • Monitor
      • Hand held bar code scanner, keyboard, and mouse
      • Touch screen and LIS serial connections
      • Network connection to AU/Hub
      • USB backup drive (if present)
    2. If the database will be restored using file transfer, then restore the database now.
      Note: Refer to the Software: Database - Restoring Console PC Database Using File Transfer (DxI and Access 2) procedure.
  2. Start a CMD session to identify the AU IP address.
    This step confirms the instrument IP address and that the instrument is communicating with the PC. Both items are required for software installation to proceed. If the AU is assumed to be operating normally with the normal 192.168.2.4 IP address, then this step can be skipped.
    1. Power on the PC so that it boots up to the Windows desktop, and then power on the instrument attached to this PC, if it is not powered on.
    2. Isolate this PC and AU pair by one of these methods:
      • Connecting the PC directly to its AU using a yellow crossover cable.
      • Powering off any other PC and AU pairs connected to the network hub.
      • Disconnecting any other PC and AU pairs from the network hub.
    3. At the Windows Desktop, press the Windows key and open Command Prompt or type command prompt to open the program.
    4. At the C:> prompt, type ping 192.168.2.x (where x=2, 4, 6, 8...), and then select Enter. Receiving a reply to the ping from the PC identifies the AU IP address.
      Note: The most likely address for a server AU is 192.168.2.4. This PC without user interface software is at 192.168.2.1.
    5. If the AU does not reply, then check these items and ping the AU again.
      • The IP address is typed correctly.
      • The network connections are correct and secure.
      • Reboot the AU.
    6. Record the IP address of the AU. You will refer to the address later.
  3. Install the software and restore the database.
    Important: Verify the Console PC's "Date&Time" setting is set to correct local time and "Time Zone" setting is set to Coordinated Universal Time and that it does not observe Daylight Savings. If they are incorrect, customers may lose onboard samples to early expiration time and Access 2 will not get any UI messages.
    Select the correct option.
    • (Option 1) Load software onto the new Server PC hard drive and restore the Server PC from backup.
      Note: Only the server PC requires the database be restored.
      1. Restore all network connections.
      2. Power on all PCs and AUs in the work group.
      3. On the server PC, ping the server AU.
        Note: The normal setup is server AU at 192.168.2.4, client PC at 2.5, and client AU 2.6. The server PC is 192.168.2.1 at this point and 2.3 or 2.7 after loading software.
      4. Load software into the server PC, entering the server AU IP address when prompted. When finished, select the option to restart the PC.
        Note: During the software installation process, change the default AU IP address from 192.168.2.2 to the IP address of the AU that was identified in the CMD session (normally 192.168.2.4).
      5. Allow the system to transition to Ready or Not Ready, and then remove the Access 2 System Software CD from the PC.
        Note: If the APF loading prompt is displayed, select Cancel. The APF is included in the database backup.
      6. Restore the database.
        • If the database is on a backup tape or USB backup drive, then restore the database from the backup. Refer to the Restoring PC Using Immediate Backup procedure, or the Restoring PC Using Previous Backup procedure.
        • If the database has been transferred directly from the old hard drive earlier in this procedure, then proceed to the next step.
      7. If after restoring the database, the user interface launches but does not communicate with the analytical unit (red status: No message, Not Ready, Configuring Parameters, or Initializing), then clear jammed critical events.
        Note: Refer to the Database - Clearing Jammed Critical Events procedure.
        Note: For loss of supply and calibration information, confirm that the database restore is complete and that the instrument IP address is correct. Refer to the Changing AU IP Address procedure.
      8. If the software version of the restored database is lower than the version installed on the server PC, then reload the software to upgrade the version after restoring the database from backup.
      9. Restore the network connections to any other PCs and AUs in the workgroup, power them on, and allow them to initialize to the Ready state.
      10. If after restoring the server PC, the client PC user interface is stuck in a red state (no message, Not Ready, or Initializing), then continue through these steps until the issue is resolved:
        1. Reboot the client AU.
        2. On the server PC, reorganize the database.
          Note: Refer to the Software: Database - Reorganizing Database procedure.
        3. On the client PC, clear the instrument critical messages. Press the Windows key, type restore, and select Restore Utility > Clear Instrument Critical Messages. Reboot the client AU. Load a new waste bag and new substrate. Discard the punctured client AU reagents.
        Note: For loss of supply and calibration information, confirm that the instrument IP address is correct. Refer to the Changing AU IP Address procedure. If the supply and calibration information is still missing, then contact Systems Technical Support.
    • (Option 2) Load software into the client PC.
      Note: The client PC does not have a database to restore. The database is on the server PC and was not affected by servicing the client PC and AU.
      1. Restore all network connections, and power on all PCs and AUs in the work group.
      2. Ensure that the server PC is initialized to the Ready state.
      3. On the client PC, ping the server PC, the server AU, and the client AU.
        Note: The normal setup is server PC 192.168.2.3, server AU 2.4, and client AU 2.6. The client PC is 192.168.2.1 at this point and 2.5 or 2.7 after loading the software.
      4. Load the software into the client PC, entering the client AUs IP address when prompted. When finished, select the option to restart the PC.
      5. If after loading the software, the client PC user interface is stuck in a red state (no message, Not Ready, or Initializing), then:
        1. Reboot the client AU and PC.
        2. On the server PC, reorganize the database, and then reboot the client PC.
          Note: Refer to the Software: Database - Reorganizing Database procedure.
        3. On the client PC, clear the instrument critical messages. Press the Windows key, type restore, and select Restore Utility > Clear Instrument Critical Messages. Reboot the client AU. Load a new waste bag and new substrate. Discard the punctured reagent packs on the AU after clearing the critical events.
        Note: For loss of supply and calibration information, it is possible that the instrument IP address is incorrect. Contact Technical Support for assistance. After identifying the correct address, refer to the Changing AU IP Address procedure to correct the AU IP address.
    • (Option 3) If the client AU replies at 192.168.2.2 in the "Identifying the AU IP Address" section, then MFG Cleanup may have been run or the AU HDD may have been replaced. Perform these steps to recover. Contact Tech Support for assistance.
      Note: The client PC does not have a database to restore. The database is on the server PC and was not affected by servicing the client PC and AU.
      1. On the Server PC, follow the steps in the Edit Database section of the Clearing Jammed Critical Events procedure to identify the Client AUs previous IP address.
        Note:
        • Refer to the Database - Clearing Jammed Critical Events procedure.
        • When bptAccessAU is selected, the server is the first entry on the right side of the display and the client is the second entry.
        • The client AU serial number and IP address are listed in the same window as the LastCriticalEventID.
      2. On the server PC, follow the steps in the Changing AU IP Address procedure to:
        1. Edit the startup file located in C:\NexStep\PC\Backup\Drw\OS9000 to have the identified client IP address.
        2. FTP to the client AU at 192.168.2.2 (after reconnecting the server PC to the network hub / client AU).
        3. Put the edited startup file into the client AU SYS directory.
        Note: Refer to the Changing AU IP Address procedure.
        Note: Normally, the client AU IP address in the startup file is set to 192.168.2.6.
      3. Reboot the client AU to apply the IP address change.
      4. On the client PC, ping the server PC, the server AU, and the client AU.
        Note: The normal setup is server PC 192.168.2.3, server AU 2.4, and client AU 2.6. The client PC is 192.168.2.1 at this point and 2.5 or 2.7 after loading the software.
      5. Load the software into the client PC and AU, entering the client AU IP address when prompted.
      6. If after loading the software, the client PC user interface is stuck in a red state (no message, Not Ready, or Initializing), then:
        1. Reboot the client AU and PC.
        2. On the server PC, reorganize the database, and then reboot the client PC.
          Note: Refer to the Software: Database - Reorganizing Database procedure.
        3. On the client PC, press the Windows key, type restore, and select Restore Utility > Clear Instrument Critical Messages. Reboot the client AU. Load a new waste bag and new substrate. Discard the punctured reagent packs on the AU after clearing the critical events.
        Note: For loss of supply and calibration information, it is possible that the instrument IP address is incorrect. Refer to the Changing AU IP Address procedure to correct the AU IP address.
  4. Verify system performance.
    1. Configure these features in the user interface:
      • Printer
      • Language
      • Date and Time
      • LIS
      • Auto Delete
      • Backup Time
    2. Print a sample report to verify printer operation.
      Note: If reports do not print correctly, refer to the Peripherals: Installing LaserJet Printer (DxI and Access2) procedure.
    3. Re-enroll in PROService (if applicable). See the Remote Solutions Service Manual for more information.
    4. Confirm (supply, reagent, QC) status and perform QC (passing) or a System Check on each instrument in the server/client workgroup.
