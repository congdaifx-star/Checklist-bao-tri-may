Restoring Access 2 Instrument NVRAM

This procedure describes how to restore the Access 2 instrument nvsetup.csv file using the backup file on the instrument. The nvsetup.csv file in the instrument hard drive contains the serial number, alignment offset, and luminometer setup values. This procedure is for Access 2 systems only.

Perform this procedure when the user interface has any of these errors:
  • There was an error in communication between the PC and the instrument. Reboot the PC. when attempting to launch the user interface.
    Note: This error is a symptom of the user interface not being able to identify the instrument serial number stored in the nvsetup.csv file on the instrument.
  • Status Controller initialization error, statinit, posted at the end of initialization.
  • Error attempting to copy.. nexstep/drw/nvsetup.csv to ../drw/nvsetup.csv.bak
  • Error attempting to store ../drw/nvsetup.csv
    Note: These errors indicate that the instrument cannot save the alignments from the I/O PCB to nvsetup.csv file.
  1. Open a Telnet session to the Access 2 AU.
    1. At the Windows desktop,
      • Windows XP system, press the Windows key on the keyboard, and then select Start > Run.
      • Windows 8 system, press Windows key, type run and open the run application.
    2. In the text box, type telnet, and then press [Enter] to open the Telnet application.
    3. In the Telnet window, type Open 192.168.2.4 at the prompt in the Telnet window, and then press [Enter].
      Note:
      • The IP address entered depends on the IP address of the AU. The 192.168.2.4 address used in the example is the most common address.
      • In a workgroup, it is possible to Telnet to any AU from any PC. To ensure that the Telnet connection is made only to the AU that is being serviced, know the specific address of the AU or disconnect the other AUs from the network.
    4. At the login prompt, type super and press [Enter]. Type user and press [Enter].
      Note: There should be a login successful message.
  2. Restore a missing nvsetup.csv file using the nvsetup.csv.bak file.
    1. Type cd /nexstep/drw and press [Enter].
    2. Type dir -e and press [Enter] to list the directory contents.
      • If the nvsetup.csv.save file is listed, then type del nvsetup.csv.save and press [Enter] to delete the file.
      • [Enter] If the nvsetup.csv.tmp file is listed, then type del nvsetup.csv.tmp and press [Enter] to delete the file.
      Note:
      • Encountering a corrupt file using dir -e can lock-up the software. If additional typed commands produce errors, then it may be necessary to reboot the AU and log back in.
      • Sometimes the .save and .tmp files can interfere with the automatic NVRAM save process statinit.
    3. Type copy -r nvsetup.csv.bak nvsetup.csv and press [Enter] to restore the nvsetup file using the backup copy.
    4. If there is an error copying or deleting the files, and a typing or spelling error is not the cause, then there may be a corrupt file in the DRW directory.
      To remove a corrupt file from the DRW directory:
      1. Type cd /h0/nexstep and press [Enter] to move out of the corrupt directory.
      2. Type rename DRW DRWx and press [Enter] to rename the corrupt directory
      3. Type makdir DRW and press [Enter] to make a new DRW directory
      4. Type cd DRWx and press [Enter] to move to the corrupt directory.
      5. Type dsave -ievrs /h0/nexstep/drw and press [Enter] to copy the files from the renamed directory into the new DRW directory.
      6. Type break and press [Enter] to reboot the AU.
      Note:
      • If typed commands produce errors, then it may be necessary to reboot the AU and log back in. Encountering a corrupt file can lock-up the software.
      • If the DRW directory is not accessible, then rename the nexstep directory and use the steps in the AU Hard Drive Replacing Procedure (starting at the Extracting the AU Operating Files section) to reload the instrument software and restore the files. Refer to the Replacing Access 2 AU Hard Drive procedure.
  3. Verify the nvsetup.csv file is working.
    1. Open a Telnet session to the Access 2 AU.
    2. Type cd /nexstep/scriptutil and press [Enter].
    3. Type ram2disk.sh -d and press [Enter].
      Note:
      • The I/O PCB nvram is saved to the nvsetup.csv file on the hard drive.
      • If an error occurs, check for typing errors.
    4. Close the telnet window and initialize the AU from the user interface.
