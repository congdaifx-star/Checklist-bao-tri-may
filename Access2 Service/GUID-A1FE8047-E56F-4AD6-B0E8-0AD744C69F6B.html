Restoring PC Using Previous Backup

This procedure describes how to restore the database on the server PC using a backup which was not made immediately before servicing the PC.

Restore into a client PC only if it is being upgraded to a server and the shared database will be maintained.

Perform this procedure when an immediate backup is unavailable:
  • To swap a non-functioning server PC with a new PC.
  • To relocate the database from the server PC into a client PC, to promote the client to a server (server PC is down, separating networked instruments).
  • To restore the server following a failed software installation.
  • Because the current database is corrupt and cannot be fixed.
Note:
  • Using a previous backup to restore results in the loss of reagent status information. Punctured reagent packs may need to be discarded because information on tests remaining may be incorrect.
  • If restoring into a new PC, then load software before restoring.
  • If relocating the database and promoting the client to a server, record the instrument IP address or determine the instrument IP address by pinging.
  • If restoring the server, record the Console IP address or determine the instrument IP address by pinging.
  • For Systems with Windows 8 and Software 3.4.3 or above and Windows 10 and Software 3.7.0 or above, the Fast Object Server replaces the Poet Object Server.
  • Software 3.4.3 or above is compatible with Windows XP console PC. If software was installed on the Windows XP console PC, then follow the Windows XP section to launch Restore Utility application.
This procedure describes how to:
  1. Transfer the database backup from a flash drive to the PC.
  2. Transfer the database from the backup folder to the DRW folder.
  3. Transfer the database from the backup folder to the PC folder.
  4. Configure the IP addresses.
  5. Reconcile the supply counts.
  1. Load the backup media.
    1. In the Main Menu screen, press [Alt] + [F4], and then enter the password Access2Support to exit the user interface.
    2. Exit the Poet Object Server or Fast Object Server, if it is present:
      • Select the Poet Object Server or Fast Object Server icon at the bottom right corner of the display.
      • Select the X at the top right of the Poet or Fast window.
      • Select Yes to the shutdown Poet Object Server or Fast Object Server.
      • Close any error messages.
    3. Load the backup media.
      • If this PC uses a USB backup device, then insert the USB drive into a USB port on the PC.
  2. Load the backup files from a backup device into the PC hard drive.
    Note:
    • If the previous backup is being restored because the current database is corrupt, then select a backup from before when the corruption occurred.
    • The Backup folder on the PC hard drive always contains the most recent backup. If the backup folder exists, then copying the files from the USB backup drive into the PC may not be necessary.
    • If loading files from a USB device, there are up to five saved backups that can be selected.
    1. Perform these steps to load files from the USB drive.
      Note: Older Windows XP image is required for support of the USB drive. USB support must be enabled in the PC CMOS.
      1. Open Windows Explorer or File Explorer.
      2. Browse to and open the USB BACKUPDRIVE.
      3. Copy the most recently saved Backup folder found in the BACKUPDRIVE, and then Paste the Backup folder into the C:\NexStep\PC folder on the PC hard drive (replace existing files).
        Note: If the previous backup is being restored because the current database is corrupt, then select a backup file from before when the corruption occurred. When loading files from a USB device, there are up to five saved backups that can be selected in the C:\NexStep\PC\ directory.
      4. Exit Windows Explorer or File Explorer.
  3. Restore the database.
    Option 1: Restore the database by manually replacing the database folders.
    1. Open Windows Explorer or File Explorer.
    2. Browse to C:\Nexstep\PC folder and open the Backup folder.
      Note: Make sure the Backup folder was copied properly from the USB flash drive and has the latest data or information.
    3. Open DRW folder in the Backup folder and then Copy NexStepBase and EventBase folders.
    4. Browse back to C:\Nexstep\PC folder, open DRW folder, then Paste NexStepBase and EventBase folders to replace the existing folders.
    5. Exit Windows Explorer or File Explorer.
    Option 2: Restore the database using the Restore Utility.
    1. Open Restore Utility application.
      • For Windows XP and Software 3.4.2 or Below: Start > Programs > Access 2 > Restore Utility.
      • For Windows 8 and Software 3.4.3 or Above: Press Windows key and select Restore Utility.
      • For Windows 10 and Software 3.7.0 or Above: Press Windows key, type "restore" and select Restore Utility.
    2. In the Restore Utility window, select Restore Registry and Database > Yes.
      Note:
      • The Restore button is not available, if there is no database in the backup folder.
      • The Restore Utility transfers files from the backup directory into the DRW directory and the registry restoring the PC to the same state as when the backup was performed.
      • A check mark in the adjacent box indicates completion.
      • If there is an error copying files, then confirm the Poet Object Server or Fast Object Server has been exited and retry restoration.
  4. Check or modify IP addresses.
    1. Open Restore Utility application.
      • For Windows XP and Software 3.4.2 or Below: Start > Programs > Access 2 > Restore Utility.
      • For Windows 8 and Software 3.4.3 or Above: Press Windows key and select Restore Utility.
      • For Windows 10 and Software 3.7.0 or Above: Press Windows key, type "restore" and select Restore Utility.
    2. In the Restore Utility window, select Modify PC Specific Registry.
      A dialog is displayed containing the restored:
      • Current console IP address (address of the PC you are at).
      • Workgroup server IP address (address of the Server PC).
      • Instrument IP address (address of the AU connected to this PC).
      On a server PC: If the Current Console IP address does not match the Workgroup Server IP address, then modify the Current Console IP address:
      1. Select Enable Current PC IP Setting.
      2. Place the cursor to the right of the Current Console IP address (192.168.2.x).
      3. Back space over the last digit and change the address to match the Workgroup Server IP address.
        Note: The change takes effect at the next reboot of the PC.
        Note: When rebooting the Privacy & Security compliant Windows 8 or Windows 10 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

      When restoring to promote a client PC to a server: If the Current Console IP address does not match the Workgroup Server IP address, then modify the Workgroup Server IP address:
      1. Place the cursor to the right of the Workgroup Server IP address (192.168.2.x).
      2. Back space over the last digit and change the address to match the Current Console IP address.
    3. In the Modify PC Specific Registry window, change the Instrument IP address to match the IP address of the instrument connected to this PC.
    4. Select OK to return to the Restore Utilities window.
      Note: A check mark in the adjacent box indicates completion.
    5. Select Clear Instrument Critical Messages to clear any messages that are stored on the instrument and are waiting transmission to the database.
      Note:
      • A check mark in the adjacent box indicates completion.
      • The AU must be on and communicating for this step to complete.
    6. Select Exit to exit the Restore Utility.
      Note: The Database Maintenance function is not used in the restore from immediate backup process.
  5. Configure the client PCs to connect to a promoted server PC.
    1. If the restoration has been done to promote a client PC to a server, then start the Access 2 Restore Utility on each client PC in the network by selecting:
      • For Windows XP and Software 3.4.2 or Below : Start > Programs > Access 2 > Restore Utility.
      • For Windows 8 and Software 3.4.3 or Above: Press Windows key and select Restore Utility.
      • For Windows 10 and Software 3.7.0 or Above: Press Windows key, type "restore" and select Restore Utility.
    2. From the Restore Utility window, select Modify PC Specific Registry.
      A dialog is displayed containing:
      • Current Console IP address (address of the PC you are at)
      • Workgroup Server IP address (address of the Server PC)
      • Instrument IP address (address of the AU connected to this PC)
    3. If the Workgroup Server IP address is incorrect, then change the address:
      Caution: The Workgroup Server IP entry on each client PC must match the IP address of the server PC from the previous step.
      1. Place the cursor to the right of the Workgroup Server IP address (192.168.2.x).
      2. Back space over the last digit and change the address to match the IP address of the server PC from the previous step.
    4. Select OK to return to the Restore Utilities window.
    5. Select Clear Instrument Critical Messages to clear any messages stored on the instrument awaiting transmission to the database.
      Note:
      • A check mark in the adjacent box indicates completion.
      • The AU must be on and communicating for this step to complete.
    6. Select Exit to exit the Restore Utility on the client PC.
  6. Unload reagents from the instruments.
    Note: The database (restored from the previous backup) has reagent counts that might not match the present counts in the reagents onboard. All reagent packs must be physically removed from the reagent carousel of each AU in the workgroup and inspected. Punctured packs are discarded.
    1. Power down the instruments, then manually remove all sample racks and reagent packs.
    2. Perform a visual inspection of all the removed reagent packs. Discard all the packs that are punctured. Save any packs that have not been punctured. The unpunctured packs can be reloaded later.
    3. For any unpunctured reagent packs, record the reagent name, lot number, and serial number. This information is used during the Database Maintenance function.
  7. Delete punctured reagent packs that could have incorrect quantities of tests in the database.
    1. From the Restore Utilities window in the server PC, select Database Maintenance.
    2. In the Database Maintenance window, select Correct inconsistent records and unload packs/racks logically.
    3. Compare the list of unpunctured reagents that were physically removed from the instrument to the list of Possible Unpunctured Reagent Packs in the Database Maintenance window.
    4. Delete the reagent packs that are not unpunctured by highlighting the reagent pack and selecting Delete Selected Reagent.
    5. Select Close to the database maintenance function. Select Exit to the restore utility.
  8. Verify system performance.
    1. Reboot the Access 2 instruments and allow 30 seconds for the instruments to begin initialization.
      Note: If a crossover cable is used between the PC and AU (no network hub), then when the Windows desktop is displayed on the PC, power on the PC first and then power on the AU.
    2. Reboot the server PC and when the server PC has transitioned to Ready, reboot the client PCs. Allow all systems to transition to Ready.
      Note: When rebooting the Privacy & Security compliant Windows 8 or Windows 10 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

      Note:
      • If the user interface is stuck in a red state (no message, Not Ready, or Initializing) after restoration, then reboot the AU. If rebooting does not correct the problem, then clear jammed critical events. Refer to the Database - Clearing Jammed Critical Events procedure.
      • If there are no test results or calibrations present in the user interface, then confirm that the database was restored.
      • Exit the user interface, shut down the poet object server, and in the Restore Utility select the Restore Registry and Database button. Launch the user interface after restoring.
      • Confirm that the database in the backup folder is recent and that the serial number and IP address in the database match the connected instrument. Contact technical support for assistance.
    3. Confirm that the printer and LIS setups are correct and that both processes are functioning.
    4. Load a new substrate bottle and change the waste bag on each instrument.
      Note: The waste bag or substrate counts in the instrument memory and the information in the restored database might not match. This mismatch can cause an invisible supply wait condition and no samples will aspirate until the counts are reset by loading new supplies.
    5. Perform a QC or system check on each instrument to confirm that posting results to the restored database does not create any problems.
    6. Perform an immediate backup on the server PC to store a copy of the new database.
