Database - Checking Supply Counts

This procedure describes how to check the supply counts.

This procedure provides instructions for checking the supply counts (substrate or waste bag) on the instrument and modifying the counts in the database.

Use this procedure to check the substrate and waste bag supply counts or to adjust the supply counts in the database.

If the supply counts are mismatched between the analytical unit (AU) and the PC database, then the system will not aspirate or process samples. The instrument seems to be running forever and the displayed completion time continuously updates to a later time.

The most common causes for this issue are lost or cleared critical events, database restoration, or a defective I/O PCB.
  • Generally, the waste bag counts do not match after a database restoration or clearing of AU critical events. Changing the waste bag resets the counts to 300 on both the instrument and in the database. When the counts match, samples aspirate.
  • Rarer, but also possible, is having the substrate bottle counts mismatched between the instrument and the database. Changing the substrate resets the counts to 600 on both the instrument and in the database.
  • If the I/O PCB loses memory when powered down or when installing a new I/O PCB, the system initializes with an RV cleanout error. After homing the RV shuttle, incubator belt, and the wash carousel, the system automatically calibrates the incubator belt. Incubator belt calibrated events are a symptom of the I/O PCB losing memory. The substrate counts and waste bag counts stored in the I/O PCB NVRAM on the Dallas chip will be 0 and the supplies in the user interface will have different values. Load substrate and change the waste bag to reset the counts in the UI and the AU. Replace the I/O PCB, if memory loss is suspected.
  1. Open a Telnet session to the Access 2 AU.
    1. At the Windows desktop,
      • Windows XP system, press the Windows key on the keyboard, and then select Start > Run.
      • Windows 8 system, press Windows key, type run and open the run application.
    2. In the text box, type telnet, and then press [Enter] to open the Telnet application.
    3. In the Telnet window, type Open 192.168.2.4 at the prompt in the Telnet window, and then press [Enter].
      Note:
      • The IP address entered depends on the IP address of the AU. The 192.168.2.4 address used in the example is the most common address.
      • In a workgroup, it is possible to Telnet to any AU from any PC. To ensure that the Telnet connection is made only to the AU that is being serviced, know the specific address of the AU or disconnect the other AUs from the network.
    4. At the login prompt, type super and press [Enter]. Type user and press [Enter].
      Note: There should be a login successful message.
  2. Read the supply status from the instrument.
    1. At the (super) [/hØ/>] prompt, type cd /hØ/nexstep/utils, and then press [Enter].
    2. At the (super) [/hØ/nexstep/utils/>] prompt, type statread -U (Capital -U), and then press [Enter] to display the instrument internal supply counts.
      Note: Type statread, and then press [Enter] to display the options menu.
    3. Record the supply counts. If the supply counts do not match the counts displayed in the user interface, then
      • Change the waste bag to correct waste bag counts.
      • Change the substrate to correct the substrate counts.
      or, edit the database so the database matches the instrument counts.
  3. Edit the database when loading supplies to reset the supply counts is not possible.
    1. Create a local copy of the database.
      Note: Refer to the Software: Database - Creating Local Copy of Database (DxI and Access2) procedure.
    2. Launch the Poet or Fast database application.
      • For Windows XP system, select Start > Programs > Access 2 > Poet Administrator or Poet Developer.
      • For Windows 8, press Windows key and select Fast Administrator or Fast Developer.
      Note: If the Poet or Fast Administrator does not start because the Poet or Fast Object Server is not running, then start the Poet or Fast Object Server.
      • For Windows XP system, select Start > Run, type ptserv32.exe, and then press [Enter].
      • For Windows 8 system, press Windows key > type run > open the run application > type ptserv32.exe, and then press [Enter].
    3. In the Poet or Fast Administrator window, select File > Open Database.
    4. In the Hostname field, type LOCALHOST and in the Database field type NexStepBase with correct capitalization (case sensitive).
    5. In the Poet or Fast Administrator window, select Objects > Browse extent or objects.
    6. In the Extent browser window, navigate to and select BPtSubstrateReagent.


      Note: The right side of the Poet or Fast Browser window displays text for the substrate objects.
    7. Expand the Poet or Fast window and the Browser window so that the columns to the far right side of the Browser window are revealed.
    8. Use the scroll bar at the bottom right of the Browser window to move to the m_wSerialNumber column.
    9. Scan down the m_wSerialNumber column for the text row having the serial number of the loaded substrate.
    10. Select the serial number (identified text line) for the substrate to open the PtObjID window.
    11. Highlight m_dwTotalTestsLeft, right-click, and select Modify. Correct the counts and select OK.


    12. Highlight the BPtReagentWellInventory line to open the well inventory window for the selected substrate.


    13. Highlight m_wActualTestsLeft, right -click, and select Modify. Correct the counts and select OK.
    14. After the counts are corrected, highlight the top line of the left column of the PtObjID window, right-click, and select Store.
  4. Check the database.
    1. Exit the Poet or Fast Administrator.
    2. Run a database consistency check.
      Note: Refer to the Software: Database - Performing Database Consistency Check (DxI and Access2) procedure.
    3. Launch the user interface.
      • For Windows XP, select Start > Programs > Access 2 > Access 2 or NexStep. The UI transitions to Ready.
      • For Windows 8, double click on the NexStep Application shortcut on the desktop. The UI transitions to Ready.
    4. Use statread -U in the telnet connection to the AU to verify that the counts displayed in the UI Supplies window match the counts read from the instrument.
    5. Run a sample and ensure that the sample aspirates and completes.
