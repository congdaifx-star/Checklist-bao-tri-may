Tshoot: Access 2i (LXi/DxC600i)

Purpose

This document provides basic troubleshooting information for the Access 2i used in the LXi system.

Principles

This section provides information about the system that is helpful when troubleshooting.

Area Notes
Access 2i When troubleshooting the Access2i in the integrated system, think of the system as an Access2 with an automated operator (the CTA) attached to a LIS host (the DxC 600i /LX20 chemistry console).
  • An automated user (CTA through the CTA serial connection) automatically loads samples into the Access2, provides the sample ID for the samples, and then off-loads or discards the samples when finished. This process is a get/edit rack, sample ID entry, sample load, load rack command, and a LIS query. The samples are aliquotted, and then the CTA performs another get/edit rack operation and CTA sample unload to remove the AVs.
  • When there is no serial connection, the Access2 status on the chemistry console is line-down. A cross-over serial cable from the Access2 PC to the CTA provides communication between the CTA and Access2 for loading samples. The CTA communicates to the chemistry console through the network hub.
  • Manual racks used for maintenance or calibration have priority over automation racks. This priority can sometimes prevent automation samples from running even when the manual process has completed. It is best to unload all manual racks when the manual process is finished.
Software

The Integrated Access2 software (Vi5.9) is similar to the Access2 software but different. Symptoms of loading Access2 software into an integrated system include, network configuration errors, user interface failing to launch, and errors when moving the sample carousel to the CTA load position.

Caution: Do not load Access2 software into an integrated Access. The UI will not launch. Recovery steps are found in the "LXi, Access, Software Recovery" procedure in the LXi service manual. in the LXi 725 service manual.
AAF - APF
  • The Access2 software and APF are on separate disks.
  • When loading software into the integrated system, load the Access2 software first to eliminate an extra DxC 600i reboot.
  • The DxC 600i checks that the AAF version matches the Access APF version when it boots up. If the DxC 600i cannot communicate to the Access or the APF/AAF versions do not match, then an AAF revision error message displays on the DxC 600i console when it boots up. To help prevent APF/AAF version mismatch, the APF and AAF are now on the same CD.
  • If an error occurs when updating the Access APF, then delete unused QC lots, old calibrator lots, and expired off-board reagents. Exit the user interface, run the database consistency check to fix database problems, and then reload the APF.
User Interface
  • The DxC 600i console is the primary interface for the system.
  • Normally, the Access2 user interface display is used only for loading Access supplies and calibrating the Access.
System Status
  • The Standby/Standby/Standby (Access/CTA/DxC 600i) status shown at the top left of the DxC 600i console display is required whenever the system configuration must be changed on the DxC 600i console.
Enable Tests
  • The Access2 tests must be enabled and calibrated on the Access2 and enabled on the DxC 600i console or the DxC 600i will not program them onto samples.
  • The Access tests are listed after all the DxC 600i tests >99 in the test DxC 600i test setup menu.
CTA
  • The CTA boots up using a floppy disk.
  • The external CTA serial connection connects to a short serial cable inside the CTA card cage which can come unplugged in shipping.
  • All the motor controller PCBs in the CTA card cage are interchangeable.
  • CTA alignments are made by moving the devices to each position by hand. Refer to the "CTA to Access2 Alignments" and "CTA Alignments" procedure in the LXi 725 service manual. The devices cannot be aligned by stepping to position.
  • The CTA shuttle sometimes gives an over current / movement error when the alignment for pushing the sample rack into the CTA sample carousel is too tight. To correct this issue, perform the CTA alignment by pushing the rack/shuttle into the carousel tightly and then pulling it back out 1 or 2 motor steps before continuing. Refer to the "CTA Shuttle Assembly" procedure in the LXi 725 service manual.
CTA On-Line
  • To access the CTA on-line/off-line function, select the CTA icon on the upper right corner of the Access display.
  • The CTA must be set to off-line to enter diagnostics on the Access2.
  • The CTA control program runs in the background on the Access 2 PC. When launching the user interface, it appears as Lxiaut in the list of unknown processes.
  • The touch screen monitor can be used to identify serial ports and confirm serial port function. Connect the touch screen to the suspect port and use the MicroTouch Touchware program to detect the monitor on that port. Select Start > Programs > MicroTouch Touchware > MicroTouch Touchware.
  • COM 4 is the standard CTA port and the standard port speed is 9600 bps. Configure the COM port connection to the CTA by selecting Diagnostics > CTA.
  • The CTA window serial port setup allows selection of ports 1 through 4. If COM 4 is not working or not available, COM 1 can be used for the CTA connection. If the CTA is connected to COM 1, move the touch screen to a free port.

If the COM 4 serial port is not present or is incorrectly identified on the PC, then follow these steps to configure the port:

  • (No Dot XP upgrade)The Com 4 and Com 5 port connectors are reversed after upgrading to Windows XP. After upgrading the PC to windows XP, move the serial cable to the other serial port connector (4 or 5).
  • (No Dot NT) Select Start  > Settings > Control Panel > Cyberpci20x. Reassign the serial expansion card port numbers.
  • (Blue Dot / Orange Dot NT) Select Start  > Settings > Control Panel > System > Hardware > Device Manager > Ports (COM & LPT). Review the port numbers and modify a port greater than 4 to use the COM4 address. The internal modem uses COM3, so it is not listed.
  • (black Small Form Factor)
    1. Some early versions incorrectly assign the COM 4 connector to the COM 3 address that is used by the internal modem. Select Start > Settings > Control Panel > System > Hardware tab > Device Manager > Ports (COM & LPT). Right-click Communications Port (COM3), and then select Properties > Port Settings > Advanced. In the Port Number drop-down list, select COM4. Select OK > OK > OK to exit the port settings windows.
    2. Initial software installation on the small PC can set the CTA to use port 3. After confirming the connector address is set to COM4, change the port setting to COM 4. Select Diagnostics > CTA.
CTA Supplies
  • The CTA uses Access RVs. On the CTA, they are called aliquot vessels (AVs).
  • Loading RVs or autogloss supplies into the CTA is requested through the DxC 600i console.
LIS
  • The Access2 LIS connection (COM2) connects to the DxC 600i console (P0) through a serial crossover cable. If the multi-com serial connectors on the DXC console are labeled P1 to P4, then connect P1 to Access2 console COM2
  • For DXC 600i: Connection to the Access2 LIS the baud rate on the Access2 LIS Setup should be set to 9600 bps.
  • For LX20: Connection to the Access2 LIS the baud rate on the Access2 LIS Setup should be set to 19,200 bps.
Alignment CTA AV Loader

Align the CTA gripper to position 1 of a 1900 series rack loaded into the Access sample carousel at the Zero (Home ) position. Load the rack after homing the carousel in Diagnostics. Do not align to a rack loaded using the Sample Manager.

  • If the CTA transfers the vessel to an incorrect rack location, then the transfer position alignment may have been done with the automation rack loaded into position 1 of the Access sample carousel instead of position Zero (Home).
  • For LX20/Access2i, the CTA load position alignment offset is approximately 5000 steps. An offset of 0 steps corresponds with rack position 3 being under the AV in the Gripper.
  • For DxC 600i, the alignment offset for position 1 is approximately 0 steps instead of 5000.
Automation Run Not Started on Integrated Systems

In the absence of any hardware events, press the Run button on the UI display and the run may start.

System Operation

The CTA automates the same steps performed by the operator during the manual sample load process.

  1. Load a rack into the onload area of the chemistry analyzer, and press the green run button.
  2. The rack is pushed to the CTA bar code reader, where the rack ID and tube bar code labels are read.
  3. The bar code information is sent from the CTA to the DxC 600i console using the network cable connection.
    • If the CTA is jammed, not immediately reparable etc., and cannot scan racks, then turn off the CTA, remove the DxC 600i load area cover, and load LX sample racks.
    • When the CTA is off, manually load Access samples onto the Access.
  4. The DxC 600i either has manual programming for the rack or it queries the LIS for programming.
  5. The rack is loaded into the CTA sample carousel and waits for the DxC 600i to prioritize tests.
    • If there are Access tests requested, then the rack/sample is sent to the CTA cap piercer and CTA aliquot probe.
    • If there are no Access tests for the rack, then it is sent to the DxC 600i Onload area. The DxC 600i scans the rack Barcodes again and runs any chemistry tests. The DxC 600i bar code reader does not initiate a LIS query for tests when the CTA is booted up and communicating to the DxC 600i console. It assumes that the CTA already performed the query.
    • If the Access is offline (not communicating through the serial connection to the CTA) and Access Priority has been set to On in the DxC 600i, then the CTA holds any racks that have Access samples until the Access is online and communicating again.
    • If the Access is not working and the Access/DxC 600i samples must be run, then turn off the CTA and load the samples through the DxC 600i load area. The priority status cannot be changed until the system is at standby/standby/standby.
  6. The CTA prepositions some aliquot vessels (AVs) into the sample tray and washes the aliquot probe.
  7. An aliquot is taken from the sample tube and put into an AV on the CTA sample tray.
  8. The CTA uses the serial connection (Access COM4 to DxC P0) to request sample loading.
    • Onboard manual racks have priority and can prevent samples from being transferred from the CTA to the automation racks. If CTA samples do not transfer to the Access, unload and clear manual racks
    • The CTA will load AVs into the 1900 series racks only.
  9. The Access sample carousel moves a rack to the CTA AV transfer position.
  10. The CTA transfers the AV to the rack and gives the sample ID to the Access using the COM4 serial connection.
    • If the CTA transfers the vessel to an incorrect rack location, then the transfer position alignment may have been done with the automation rack loaded into position 1 of the sample carousel instead of position Zero (Home).
  11. The Access 2 accepts the sample, moves the rack to the Access bar code reader / tube detector, and queries the DxC 600i console for tests (COM2).
    • If the DxC 600i console is off, then there is no LIS communication from the Access because the DxC 600i console provides the Access LIS connection.
    • Manually loaded rack/samples also query the DxC 600i console for tests.
  12. The Access runs the tests.
    • If there is a QNS on a sample, then check the CTA sample aliquot volume first. The fitting on top of the CTA aliquot probe can come loose, or the sample syringe pump syringe can come loose or wear out. Then the CTA will short sample into the AV causing a QNS on the Access.
    • Each sample is listed in the Access test results display as onboard until the tests are complete, then the sample is shown as being off board even if the CTA has not removed the vessel. The AV stays on the sample rack and shows up as present in the rack visual display until the rack is manually off-loaded and cleared or the CTA removes the AV.
  13. The CTA will pick up and discard the AV sometime in the future.
  14. Results are sent to the DxC 600i using the Access COM2 serial connection to the DxC 600i console, and the DxC 600i console sends the results to the LIS (DxC 600i P3).

Test IDs And Datalink Codes

Use these steps to configure a Datalink to communicate to the LXi.

Note: The steps can vary depending on the system version.
  1. Enable the desired test in the Access2, load the reagents, and calibrate.
  2. In the Datalink interface, select Configuration  > Parameter Definition.
    1. For "param. code" and "abbreviation", enter the test name (example aTnI).
    2. For units, use ng/ml.
    3. For sample, use serum twice.
    4. Select [F2] to save.
    Note:
    • Refer to the "Configure a Parameter" procedure in the Datalink service manual for detailed instructions on configuring Datalink codes.
    • For a list of test ID numbers and Datalink codes for each assay, refer to the Assay Descriptions and Datalink Codes procedure in the Access service manual or the Access/Access2/DxI/LXi Chemistry Codes in the DL2000 Datalink service manual.
  3. Select Environment > Instrument Codes, then select the LXi instrument from the list.
    Note: For LXi, the Datalink needs the test code to be configured for two instrument entries, LXi and LX20H.
  4. In instrument setup, for the (example "aTnI") parameter under instrument code enter (example A84) and select [F2] to save.
  5. Set Environment > Priorities to 1 for the new test. From the main DL2000 screen, select Configuration > Save to save the changes.
  6. Repeat steps 3 through 5 for the LX20H instrument entry.
  7. Configure the new code (example A84) on the customers LIS.
