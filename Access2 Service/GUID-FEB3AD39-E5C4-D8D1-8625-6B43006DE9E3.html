Troubleshooting Network Errors Access 2

Purpose

This document provides basic network troubleshooting information.

Error Messages

Use this information to identify the causes for common communication error messages.

Error Cause Notes
Idle timer expired message in the event log. The AU has been powered down or disconnected from the network. If an Idle timer expired message is followed by a System Initialization message within a few minutes, then the AU was just rebooted.
Socket connect failed when the user interface tries to connect to the AU after a PC reboot. The AU was not on, the AU was at an unexpected IP address, or the AU network card did not initialize when the user interface attempted to launch. The AU network card may not initialize if it is not connected to an active network when the AU boots. Before performing other troubleshooting, reboot the AU with the PC on, wait 1 minute, then reboot the PC to launch the user interface.
Note: When rebooting the Privacy & Security compliant Windows 8 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

Workgroup Communication Error. Reboot the PC. The PC was unable to retrieve the nvsetup.csv file data from the AU replying at the expected IP address. There is a problem with the /hc1fmt/nexstep/drw/nvsetup.csv file on the AU Hard Drive. This error is not caused by network hardware or setup. For corrective actions, refer to the Restoring Instrument NVRAM (Access 2).

Troubleshooting Procedures

Procedure Steps
Rebooting the AU.

Perform these steps to reboot the AU.

  1. Power off the AU, and then power it up.
    Note:
    • Whenever there is a network error, it is always best to just reboot the Analytical Unit first before doing anything else, then either launch the user interface
      • Windows 8 system, double click on the NexStep Application icon on the desktop or press Windows key and open the NexStep Application program.
      • Windows XP system, select Start > Programs > Access2 > Access2 or NexStep

        or reboot the PC.

    • The AU needs to be connected to a powered-on network hub or to a booted-up PC to initialize its network card properly.
  2. Attempt to launch the user interface by selecting
    • Windows 8 system, double click on the NexStep Application icon on the desktop or press Windows key and open the NexStep Application program.
    • Windows XP system, select Start > Programs > Access2 > Access2 or NexStep

      or reboot the PC.

    If the UI launches, there is communication from the PC to the AU. Refer to the Clearing Jammed Critical Events procedure for details on correcting UI communication issues.

Inspecting the PC and network hub.

Perform these steps to inspect PC and network hub.

  1. Verify the network cable connection to the PC is to the connector near the mouse and keyboard connectors.
    Note:
    • This port is configured with the 192.168.2.x address.
    • Connection to one of the Dual NIC ports causes a communication failure to the AU because the ports are not in the same IP address range as the instrument.
    • If required for troubleshooting, one of the dual NIC ports can be configured with a 192.168.2.x IP address range. To prevent hardware conflicts, make sure no two ports on the PC or the network have the same address.
  2. On the network hub, verify that the link indicator LED is green for each connected port.
    Note: The hub has a switch labeled Normal / Uplink, this switch only applies to the port closest to the switch labeled "uplink". To avoid issues related to setting this switch, do not use the uplink port. The uplink port can allow a successful ping but still not communicate between PC and AU correctly.
  3. If one connected port LED is not green and the other LEDs are, then swap that cable connection with a green port cable. The LED status should swap also, confirming that the hub port is OK.
  4. Next, swap the cables between the AU and PC using the network hub LED status to confirm that the cables are OK.
  5. If the LED status confirms that the hub and cables are OK, then troubleshoot the AU or PC hardware and software configuration.
Pinging the PC.

Perform these steps to identify the PC IP address, test the PC network card, and ping to communicate with the PC address on the network.

Windows 8 System

  1. Press the Windows key, select Command Prompt icon or type command prompt and open the program.
  2. In the CMD dialog window, type ipconfig then press [Enter] to display the IP address of the PC.
    Note: For Windows 8, only the connected ports return an IP address for the ipconfig command. The dual NIC card ports are typically displayed as "not connected" without an IP address listed. If the network cable is in the wrong network port, then ipconfig may list a 172 or 134 address instead of the normal 192.
  3. Type ping 192.168.2.x (where x= the number returned by the ipconfig command previously), and then press [Enter] to check the PC address and network card.
    • If the test passes with a reply from 192.168.2.x, then continue to the next step.
    • If a Request timed out or Destination Host Unreachable message is received, then:
      • Check that the address was entered correctly.
      • Check that the network cable is not connected to one of the PC dual NIC ports.
      • Disconnect other devices from the network hub, reboot the PC, and then repeat the Pinging the PC section.
      Note: When rebooting the Privacy & Security compliant Windows 8 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

      Note:
      • The PC IP address is usually 192.168.2.3, but also try 2.1 through 2.10.
      • For Windows 8 consoles, a Destination Host Unreachable error message can happen when the PC is not connected to a network (hub or AU).
      • The LED near the connector on the PC lights up when connected to a network.

Windows XP System

  1. Press the Windows key and then select Start > Run.
  2. In the run dialog box, type cmd, and then press [Enter].
  3. In the CMD dialog window, type ipconfig then press [Enter] to display the IP address of the PC.
    Note: For Windows XP, only the connected ports return an IP address for the ipconfig command. The dual NIC card ports are typically displayed as "not connected" without an IP address listed. If the network cable is in the wrong network port, then ipconfig may list a 172 or 134 address instead of the normal 192.
  4. Type ping 192.168.2.x (where x= the number returned by the ipconfig command previously), and then press [Enter] to check the PC address and network card.
    • If the test passes with a reply from 192.168.2.x, then continue to the next step.
    • If a Request timed out or Destination Host Unreachable message is received, then:
      • Check that the address was entered correctly.
      • Check that the network cable is not connected to one of the PC dual NIC ports.
      • Disconnect other devices from the network hub, reboot the PC, and then repeat the Pinging the PC section.
      Note:
      • The PC IP address is usually 192.168.2.3, but also try 2.1 through 2.10.
      • For Windows XP consoles, a Destination Host Unreachable error message can happen when the PC is not connected to a network (hub or AU).
      • The LED near the connector on the PC lights up when connected to a network.
Identifying the AU IP address.

Perform these steps to identify the AU IP address that the PC has listed. The AU may be at another address, which will cause a connection failure.

Windows 8 System

  1. Press the Windows key, select Restore Utility icon or type restore utility and open the program.
  2. In the Restore Utility window, select Modify PC Specific Registry. A dialog displays containing:
    • Current console IP address (address of this PC).
    • Workgroup server IP address (address of the server PC).
    • Instrument IP address (address of the AU that the PC attempts to connect to).
  3. Record the instrument IP address, and then select OK.
    Note: The instrument IP address is the address that the PC expects the instrument to be at. The instrument may be at a different address, which causes a connection failure message when the PC looks for it at the listed address.
  4. Select Exit to exit the Restore Utility.

Windows XP System

  1. Press the Windows key and then select Start > Programs > Access2 > Restore Utility.
  2. In the Restore Utility window, select Modify PC Specific Registry. A dialog displays containing:
    • Current console IP address (address of this PC).
    • Workgroup server IP address (address of the server PC).
    • Instrument IP address (address of the AU that the PC attempts to connect to).
  3. Record the instrument IP address, and then select OK.
    Note: The instrument IP address is the address that the PC expects the instrument to be at. The instrument may be at a different address, which causes a connection failure message when the PC looks for it at the listed address.
  4. Select Exit to exit the Restore Utility.
Pinging the AU.

Perform these steps to ping the AU. The AU IP address may be at an address other than the identified address, which will cause a connection failure.

Windows 8 System

  1. Press the Windows key, select Command Prompt icon or type command prompt and open the program.
  2. In the CMD dialog window at the C:\> prompt, type ping 192.168.2.x (where x= the AU IP from the registry) and then press [Enter].
    • If a Reply is received, type ping -t -l 1350 192.168.2.x (it is -L), and then press [Enter] to ping the AU continuously. Press [Ctrl] + [c] to stop. Replies to continuous pings verifies the NIC is working correctly.
    • If a Request timed out or Host Unreachable message is received, check that the command was entered correctly.
    • If this ping continues to fail, then reboot the AU, and ping the AU while it is booting up.
    • If the ping continues to fail, then continue to the next step.
  3. At the C:\> prompt, type ping 192.168.2.2 and then press [Enter].
    • If a reply is received, then reset the AU IP address to the address listed in the Modify PC Specific Registry step in the previous troubleshooting procedure. The startup file on the AU could be corrupt. To reset the AU IP address, refer to the Changing AU IP Address procedure.
  4. If pings continue to fail, then an instrument hardware problem could be the cause:
    • Defective AU CPU PCB.
    • Defective AU hard drive.
    • Defective or incorrectly connected hard drive to CPU ribbon cable.
    • Loss of 5 V DC or 12 V DC power to the hard drive.
    • Shuttle or incubator not at home (an error may lock up the CPU). Move these devices to home.
    • Incorrect NIC driver version or defective NIC card.
    • I/O PCB issue.
    Note: Evidence of instrument boot up, such as homing the main pipettor, may rule out some possible failure areas.
  5. Close the CMD dialog box when finished.

Windows XP System

  1. Press the Windows key and then select Start > Run.
  2. In the run dialog box, type cmd, and then press [Enter].
  3. In the CMD dialog window at the C:\> prompt, type ping 192.168.2.x (where x= the AU IP from the registry) and then press [Enter].
    • If a Reply is received, type ping -t -l 1350 192.168.2.x (it is -L), and then press [Enter] to ping the AU continuously. Press [Ctrl] + [c] to stop. Replies to continuous pings verifies the NIC is working correctly.
    • If a Request timed out or Host Unreachable message is received, check that the command was entered correctly.
    • If this ping continues to fail, then reboot the AU, and ping the AU while it is booting up.
    • If the ping continues to fail, then continue to the next step.
  4. At the C:\> prompt, type ping 192.168.2.2 and then press [Enter].
    • If a reply is received, then reset the AU IP address to the address listed in the Modify PC Specific Registry step in the previous troubleshooting procedure. The startup file on the AU could be corrupt. To reset the AU IP address, refer to the Changing AU IP Address procedure.
  5. If pings continue to fail, then an instrument hardware problem could be the cause:
    • Defective AU CPU PCB.
    • Defective AU hard drive.
    • Defective or incorrectly connected hard drive to CPU ribbon cable.
    • Loss of 5 V DC or 12 V DC power to the hard drive.
    • Shuttle or incubator not at home (an error may lock up the CPU). Move these devices to home.
    • Incorrect NIC driver version or defective NIC card. Refer to the Updating NIC Driver procedure.
    • I/O PCB issue.
    Note: Evidence of instrument boot up, such as homing the main pipettor, may rule out some possible failure areas.
  6. Close the CMD dialog box when finished.
Inspecting the AU PCBs.

Perform these steps to inspect the AU PCBs for issues.

  1. Inspect the AU network card. If the Network Interface Card (NIC) or AU hard drive was replaced, then load the appropriate NIC driver software.

    Note:
    • Newer Access2 systems may not have a floppy drive. These systems have a newer NIC.
    • Replacement HDDs come loaded with the driver software for the newer NIC and include floppy disks for loading the older NIC software.
  2. Inspect the I/O PCB for a loose DALLAS chip.

    Note: A loose Dallas chip causes communication issues.
  3. Power off the AU and remove the I/O PCB. Power on the AU and return to the Ping the AU section.
    Note: Removing the I/O PCB stops the AU software from loading and allows communication where an AU hard drive problem is suspected. Refer to the Clearing Jammed Critical Events (Access 2) procedure for details.
