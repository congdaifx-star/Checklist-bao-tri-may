Changing AU IP Address

This procedure describes how to change or restore the Access 2 AU IP address.

Overview of the AU IP address assignment process for an individual server installation:
  • An unprogrammed or cleaned-up AU is set to communicate at IP address 192.168.2.2. After initial software load, the AU is still set for communications at 192.168.2.2 and a registry entry for the AU is created in the PC with address 192.168.2.2. After reboot of the PC, the AU and the registry entry are still set to 192.168.2.2. After PC connection to the AU at 192.168.2.2, the PC registry entry for the AU is updated to 192.168.2.4, and a startup file is sent to the AU that updates the AU IP address to 192.168.2.4 when it is rebooted. If the process is not done in the correct order or is not completed correctly, the AU might update to 192.168.2.4 while the PC registry entry for the AU is left at 192.168.2.2, or the PC registry entry for the AU might update to 192.168.2.4 while the AU is left at 192.168.2.2.
  • The AU IP address must match the address specified in the PC registry or a Network Communication Error occurs when the user interface attempts to start.
  • The database uses the IP address and instrument serial number together to recognize each instrument. If the instrument IP address has been changed, possibly by a cleanup and software reload, the instrument history (events, calibrations, QC setup, reagents) appears to be missing.
  • The NexStep database only communicates with an AU that is using the IP address that it was assigned when the database was originally created. An AU using an IP address that does not match the address stored in the database causes the area of the display where the Initializing or Ready status messages would normally be displayed to display red without a message.
Table 139: When to Perform (conditions that cause the instrument IP address to be or seem incorrect)
If Then
The AU is booted from the utility disk or master boot disk (AU replies at 192.168.2.2) Reboot the AU with the utility disk removed, and the AU replies at its correct address.
The AU was not rebooted following software installation (AU replies at 192.168.2.2). Reboot the AU and its IP address resets to its newly assigned address.
The AU was rebooted before software installation was completed (AU replies at 192.168.2.2). Use this procedure to set the AU IP address to its new value.
An installed client AU has been cleaned-up using MFG Cleanup. The database history must be retained following reinstallation of software, and the reinstallation must assign the AU an address other than its original address. Use this procedure to set the AU IP address to its original value after loading the software.
Caution: The database must be restored from backup to remove the incorrectly created AU from the database.
The AU startup file contents have been erased (AU replies at 192.168.2.2). Use this procedure to return the AU IP address to its original value.

Changing AU IP address on Windows 8 system Step 1
Changing AU IP address on Windows XP system Step 2
  1. Changing AU IP address on Windows 8 system.
    1. Identify the AU IP address in the system registry. The registry tells the PC what address to connect to for communicating with the AU.
      1. At the Windows desktop, press Windows key and select Restore Utility application icon.
      2. In the Restore Utility window, select Modify PC Specific Registry.
      3. Record the AU IP address that is shown.
      4. Select OK to exit the Modify PC Specific Registry function, and then select Exit to exit the Restore Utility.
    2. Start a cmd session to verify communications from the PC to the AU.
      1. At the Windows desktop, press Windows key and select Command Prompt application icon.
      2. In the cmd window at the C:\> prompt, type ping <the IP address identified from the registry> or ping 192.168.2.2.
        Note: An AU reply at 2.2, is the normal IP address of an unprogrammed AU.
      3. If the AU does not reply, check the following and ping again.
        • Check that the address is typed correctly.
        • Try other IP addresses.
        • Check network connections.
      4. Leave the cmd box open and proceed to the next step.
    3. Modify the AU IP address in the startup file on the PC.
      1. In the Windows desktop, press Windows key and select File Explorer.
      2. Navigate to C:\nexstep\pc\drw\OS9000.
      3. Select the startup file, and open the file using Notepad or Wordpad.
      4. In the startup file, scroll down to the line that starts with ifconfig enet0 192.168.2.x.

        Example:

        *

        * Override the default compiled addresses.

        *

        ifconfig enet0 192.168.2.4 broadcast 192.168.2.255 netmask 255.255.255.0

        setenv _sh -1

        mshell -elsp="@(OS9_w1)[%p/>] " <>>>/mterm1& auip

        Note: If the startup file is empty, or missing the ifconfig enet0 192.168.2.4 line, then check the copy in the C:\nexstep\pc\backup\drw\os9000 directory. If both copies of the startup file are incorrect, then detach the attached file, load the file into the PC, and edit the file. Save the attached file into the C:\nexstep\pc\drw\os9000 directory.

        startup

      5. Edit the ifconfig line of the startup file to change the IP address (192.168.2.4) to match the IP address identified from the PC registry.
      6. Save the file, and exit Notepad or Wordpad.
    4. Send the startup file from the PC to the AU hard drive.
      The startup file contains the AU IP address. The address does not take effect until after the AU is rebooted.
      1. At the Windows desktop, press Windows key and select Command Prompt application icon.
      2. In the CMD window at the C:> prompt, type ftp, and then press [Enter].
      3. At the ftp> prompt, type open 192.168.2.x, and then press [Enter] (x= the address of the AU).
        Note:
        • The most common AU IP address is 192.168.2.4. Client instruments or instruments with new AU hard drives can have different IP addresses.
        • If the IP address is unknown, then:
          1. Open Restore Utility application, press Windows key and select Restore Utility application icon.
          2. In the Restore Utility, select Modify PC Specific Registry.
          3. Record the AU IP address that is shown.
      4. At the ftp> prompt, type super, and then press [Enter]. For password, type user, and then press [Enter].
        Note: The password user is invisible when typed.
      5. At the ftp> prompt, type cd /h0/sys, and then press [Enter].
      6. At the ftp> prompt, type ascii, and then press [Enter].
      7. At the ftp> prompt, type mput c:\nexstep\pc\drw\os9000\startup, and then press [Enter].
        Note:
        • This copies the startup file from the PC into the AU. The startup file contains the AU IP address.
        • If there is an error copying the startup file, then check your typing or confirm that the startup file is present in the c:\nexstep\pc\drw\os9000 directory. Search the PC for extra copies of the startup file, if needed.
        • If there is an error copying the startup file, then type dir and press [Enter] for a listing of the sys directory contents. If the dir listing shows an error accessing the startup file, then the corrupt startup file must be removed. Type cd /h0. Press [Enter]. Type rename sys sysx. Press [Enter]. Type makdir SYS Press [Enter]. Type cd sysx Press [Enter]. Type dsave -ievrs /h0/sys. Press [Enter]. If all command entries produce an error, then reboot the AU and return to replacing the corrupt file. There will be an error copying startup and it will be skipped. Repeat the mput file transfer of the startup file from the PC.
      8. At the ftp> prompt, type quit.
      9. Close the cmd window.
    5. Reboot the AU, and start the user interface.
      1. Reboot the instrument. Wait at least 30 seconds for the AU to boot before continuing.
      2. Restart the user interface by rebooting the PC.
        Note: When rebooting the Privacy & Security compliant Windows 8 PC, you must enter security password "Access2Admin" when prompted to launch Windows.

        Note: In workgroups, always start the server first.
      3. If there is a network communications error while starting the user interface, troubleshoot the network.
        Note: Refer to Tshoot: Network Errors Access 2 procedure.
