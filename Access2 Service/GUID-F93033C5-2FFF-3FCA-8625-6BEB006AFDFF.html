Software Version 1.4

Access 2 Software Release Notes Version 1.4

Intended Use

For Internal Use Only - Sensitive data intended for use within BCI and normally shared with employees. There may be an occasional need to distribute this data outside the company with Management approval.

Scope

These release notes apply to upgrades from Version 1.3.1 software to Version 1.4 software. There were a number of significant changes made to the software in the 1.1 - 1.3.1 releases, which are described in the Version 1.1 - 1.3 release notes but are not further described here in the Version 1.4 release notes. Version 1.1-1.3 software had some bug fixes and those release notes should be reviewed as well.

New Features or enhancements to existing features

  • The software now allows the user to force the continuous sample report to be printed at any time and any completed samples will print immediately.
    • If no samples are completed the report will print with a notice stating that there is no data available.
    • Each sample tube will only be printed on one report.
  • The software now supports the ability to setup a reflex condition whereby an assay can reflex to a repeat of itself. The system will then suppress the repeated test from repeating to itself a second time.
  • The software now supports the ability to configure the LIS service to send results to the LIS Host based on either the completion of each test result or the completion of the sample container.
    • If the configuration is set to “by sample container” then one message is sent to LIS with all new calculated results after each sample container is done.
    • Each result will only automatically be sent to the LIS by the system once.
    • If the configuration is set to “by sample container” and a reflex test is generated on the last replicate of the sample tube the results of that tube will be held until the reflexed test is completed or the run completes.
    • If the configuration is set to “by sample container” and a customer orders an additional replicate on a sample tube following upload of the results to the LIS, only the additional replicate will be uploaded to the LIS when the tube completes.
    Note: Use of this feature may require updates to the customer’s LIS Host software. To ensure a smooth transition for the customer, the service engineer should determine the customers need for this feature during the installation and encourage them to contact their LIS Vendor and Beckman Technical Support (Dave Hillman) prior to enabling this feature.
  • A user configurable auto delete feature was added to the PC Administration screen. This feature will allow the user to configure the system to automatically delete patient and QC results after a set number of days. The user may choose to delete either Patient or QC results or both and define a different number of days for each.
    Note: This feature is an important part of the comprehensive changes made in this release to enhance system performance. This feature should be discussed with the customer at installation and configured to the customers desired settings during installation.
  • To maintain the integrity of the database a database recovery feature of POET will be used and is transparent to the user. This feature utilizes a forward recovery file to resynchronize any database transactions that were in progress when the system was shutdown. Essentially the system writes all the data for each database transaction to this file prior to storing this data in the database. If the system is shutdown prior to the database store being completed. The transaction is rewritten when the application is restarted.
    Caution: The new “forward recovery file” is integral part of the database. The exact version (date/time saved) of the recovery file MUST be available to open the database. The recovery file is located in the C:\NexStep\PC\DRW\Recovery directory. This file must saved along with the objects.dat and objects.idx file when backing up a database for administration or troubleshooting purposes.
    Caution: Customers must still be encouraged to follow existing shutdown procedures! Although this feature should greatly reduce database corruptions in the field it is not a guarantee of operating system (NT) integrity following an uncontrolled power down of the system.
  • Added fields to the test results copy to disk feature to include the sample type, priority, test ID, reagent pack lot, reagent pack serial number, dilution, calibrator level, sample comments, and sample load date time. This change ensures that the test results copy to disk feature contains all the fields that are present in the Access – Archive Results feature.
  • Improved Prime Fluidics screen that includes an estimated completion time as well as an improved interface that displays both cycles requested and cycles remaining.
  • The User Interface software now supports Spanish translations.
  • Improvements made to LIS Diagnostics include the ability to copy the captured transmissions to a floppy disk and the ability to leave the LIS Diagnostic screen and continue to capture transmissions that occur while you are not viewing the screen. Returning to the screen you will be able to view the activity that occurred while the screen was inactive. The screen now also captures all ASTM characters.
    • Capturing of transmissions is enabled when the screen is entered and will continue for next 30 minutes using a rolling buffer of the last 1000 lines of transmission.
    • Re-entering the screen will restart the 30-minute timer.
    • If the screen is not active when the timer expires the buffer is automatically cleared.
  • Added events to the event log for completion of the utility assay, enabling/disabling of the utility assay, completion of the daily system clean, and the completion of the special clean routine.
  • When requesting a calibrator from the test request screen the calibrator lots are now sorted by name first and expiration date second. Also the expiration dates will be displayed in the user selected date format.

Improved System Performance

  • Improved the query performance of the work pending screen. This improvement is significant since this query is run in the background to maintain the state of the work pending icon. Regardless if the user is utilizing the work pending screen, the system performance was impacted by this query and the impact multiplied the more instruments there were in the workgroup. The improved query performance affects Console Initialization, Reflex tests, Manual Re-Ordering of tests, and LIS broadcast downloads of tests.
  • Showing a wait cursor (hour glass) while one screen deactivates and a new screen activates enhances screen navigation by giving the user indication that the system is busy. The cursor is only displayed for screen-to-screen changes and not for pop-up dialogs.
  • QC compare charts and QC Chart and data screens were improved with the addition of a progress bar to show that there is a query in progress and the query can be canceled if the user chooses not to wait. The query itself will default to the past 31 days. If the user would like to see a larger date range the edit filter dialog is available.
  • Several additional improvements were made the QC Chart and data screen. Omitting points in the grid will no longer force a new query, instead the screen will update and the Mean, CV, and SD will be recalculated. The cursor will remain on the omitted row instead of moving back to the top row.
  • A new Database Management Service (DMS) is available to maintain the size of the database. The user will be able to configure the service to automatically delete old samples in the background. The user has the option of deleting patient samples or QC samples or both. The user can specify how many days to hold on to records before they will be deleted. Different values can be entered for QC and Patient samples.
    Note: The first time DMS is run there may be a noticeable impact on performance as several thousand results are deleted. This is a one time only episode.
  • DMS will automatically trim the database once it hits 50,000 patient samples or 40,000 QC samples regardless if the user enables the auto delete feature or not.
    Note: For optimal system performance it is recommended that the customer utilize the auto delete feature to maintain the database at a smaller size than these maximum limits.
  • A new database index management feature of the POET server will be utilized to improve performance of some store and delete functions. This feature requires that the POET software be updated as part of the installation and that the POET server not be running at all during the install process. The new indexing requires that the database be re-indexed. This will occur automatically the first time that the software is launched.
  • Added progress messages to the Splash screen (at startup) to track the progress of the database conversion, update, and re-index. Database update will be executed in phases and each phase will report its progress from 0-100 percent complete. It is unknown how many phases POET will require to complete the update but it typically requires 4 phases. The time it takes is dependent on the size of the database and the number of objects it contains.
    Caution: Client user interface cannot be started during the conversion, update, and reindex process.
  • In an LIS broadcast download scenario the work pending query will be only launched every 15 seconds to minimize impact on the database. This will improve the performance of the LIS download, and prevent the user from becoming trapped in Work Pending screen.
  • Modifications were made to improve the query performance of the test results filters. Only the standard “canned” filters were modified.
    Note: Selecting a filter that returns a very large number of test results may impact the performance of the system while the results are being sorted. Caution should be used to select filter criteria that returns the smallest number of results possible. Performance can be additionally improved by selecting completion time as the primary sort criteria.
  • The time it takes to delete a control lot is significantly improved and a progress bar was added to show the user the system is busy
  • Changes were made during the calculation of QC results to minimize the occurrence of a benign –2041-database error that would show up in the event log. The error can still occur under a heavy stress scenario but the frequency should be less. This error indicates that there was an attempt to access a database object by more than one process. Typically, the system will recover automatically from this error with no impact to the user.
  • Fixed several potential deadlocks that would leave the software in an unrecoverable state. A deadlock is identified as an application that has stopped responding as confirmed through task manager.

Sample ID Reuse

  • Changes were made to the system to better support sample id reuse.
  • Customers, who would like reuse sample IDs in <30 days but >1 day, may use the new auto delete feature to automatically remove samples from the database for sample ID reuse
  • Customers who would like to reuse sample IDs each day must manually delete results each day via the Test Results screen.
  • A problem was fixed that if the user deleted results for a given sample ID from the Test Results screen, the user may still be prevented from re-using the same sample ID.
  • The operators guide was updated to include a procedure for “Reusing Sample Id’s”.

Problems Corrected in this Release

  • Improvements were made to improve system performance. Please see section entitled “Improved System Performance “ in this document.
  • Updated foreign language help systems and minor changes to User Interface translations for consistency.
  • Fixed problem with continuous sample report, which under certain rare conditions could result in wrong flags being printed due to concurrent multithreaded access to static variables.
    Note: During installation this fix should be discussed with the customer, and the feature re-enabled if requested by the customer.
  • The calibration report and calibration review screens will now display results in the user-defined units and not the default units. If the value to be displayed is too large to fit in the column the value will be displayed using scientific notation.
  • Fixed problem where the LIS request would not override the sample priority if the sample already existed in the database. This issue typically affected systems that receive test requests from the LIS in broadcast mode. If the sample tube was loaded onto the system prior to receiving the LIS broadcast, the system ignored the sample priority in the LIS transmission.
    • The system now allows the LIS to upgrade a sample to STAT priority at any time.
    • The system will not allow a sample to be downgraded to routine priority once a test has been added to the tube.
    • The sample priority will only affect the scheduling priority for tests that are not currently running on the instrument.
  • Fixed problem where the LIS request would not override the default sample type if the sample already existed in the database. This problem typically affected systems that receive test requests from the LIS in broadcast mode.
    • The system now allows the LIS to change the default sample type when the first test is requested on the sample.
  • Fixed an “Unrecoverable Error” that could occur if one instrument starts a run and attempts to attach the tests from the LIS workpool to onboard racks at the same time as another instrument deletes the tests from Work Pending. The system would display an “unrecoverable error” message box followed by an MFC exception error.
  • Fixed potential database inconsistency problem that would be caused by 2 instruments trying to attach tests from the LIS workpool to onboard tubes simultaneously.
  • Fixed problem when running a calibrator with insufficient reagent supplies where the curve would be in progress forever. If the rack was unloaded and cleared, the calibrator levels left in the Supply Wait state would never be aborted at the end of the run. The user will get the following message when attempting to order another calibration: “Warning: The default reagent lot already has a curve in process or requested. Select another lot.”
  • Fixed problem where instrument would be running in “Ready” mode. This could happen if the user paused a run, left the instrument in pause mode until all tests completed, stopped the run, did a system initialization, and then started a new run. The visual indication would be the system in “Ready” mode with the blue background, followed by a FATAL System Software Error in the Event Log (Process = RunCtrl, line = ampmsgs.c, line 735). The instrument will continue to run, but the user will be unable to Load supplies on the fly, Pause, or Stop the system,
  • Fixed a problem where the Probe dirty event was not logged in some cases when the user stopped the system.
  • Fixed MFC Exception when adding a new control range to a control with a duplicate assay name, or when changing the assay name of an existing control range to a duplicate name.
  • Fixed problem in QC Chart Data screens where the Mean, SD and CV calculations could be incorrect depending on the number of points in the chart.
  • Fixed a problem where on rare occasions, the AU Communicator application could crash during a transmission to the instrument. This would cause the user interface to log an exception and crash when user subsequently attempted to load supplies or run the system.
  • Added additional error checking to the LIS to reject LIS requests that fail to send the patient record.
  • Fixed LIS problem where periodically LIS requested tests would be lost with no notification to the user requiring the user to re-request them. This could only for a request, which followed an LIS error (transmission or protocol violation).
  • Fixed LIS problem where the LIS Service would violate the ASTM frame layer protocol by sending ACK and ENQ characters at incorrect times. This problem affected the throughput of LIS Host systems, which broadcast test requests with minimal delay between requests.
  • Fixed problem where the pipettor did not home before some diagnostic operations (e.g. priming, volume checks). This prevents the possibility of damaging the probe or buffer being dispensed onto the base plate.
  • Fixed problem where the user would see the error “The system has detected and error which requires the devices in the instrument be reset” on every startup. After clicking OK there was a Communication Error. The error in the event log would show that the AccessSubstrateTask operation did not complete successfully.
  • Fixed several cosmetic issues with reports to improve formatting.
  • Corrected a problem with the rake/shuttle alignment software which allows rake step advance without first homing the rake (mimics Access).
  • Fixed crash in QC Chart and data screen where if a query was in progress and the user clicked on the area of the grid that contained the omit check box or comment buttons an MFC exception would be thrown.
  • Fixed potential crash scenarios when viewing the QC Compare charts or QC Chart and Data screens while results were being deleted.
  • A minor change made to text displayed in the luminometer screen. The new text reads: “The mean and %CV values are calculated based on the past 20 RLU readings”.
  • This release requires a more complex database upgrade and conversion process than previous releases. New database initialization software will track the update and conversion process of a database (used during a upgrade installation) and will now complete all phases of the update even if the update process was interrupted through software failure or by user intervention (like powering off or rebooting during the update).
