Software Version 1.3

These release notes apply to upgrades from version 1.2 software to version 1.3 software. There were a number of significant changes made to the software in the 1.2 release, which are described in the version 1.2 release notes but are not further described here in the version 1.3 release notes.

Confidential

Software release notes are to be considered Beckman Coulter, Inc. company confidential and treated as such.

Categories or Groupings

Since there are many issues that have been added or corrected in this version and these release notes contain much information, an effort was made to group the changes into similar categories. The main categories are Additions or Enhancements and Corrections, the corrections were further categorized into Lock up Conditions, UI Exit Conditions, Database Issues, Results or Printout Issues, and Workflow Issues.

Additions or Enhancements to this Release

  • The performance of the system is improved for the following user/systems actions: Run key, Supplies Required check, loading of supplies while the system is running (reagent packs, RV’s, or waste bag), overriding expirations, auto scheduling of reflex/LIS tests on a running system.
  • The Access 2 software is now translated in the following languages: French, German, and Italian.
  • NOTE: Languages should be changes only when the system is in the Ready mode.
  • The Access 2 software now supports the following assays: HIVabNew and HCVPlus.
  • Lines were added to Continuous Sample Report to improve the readability of the report.
  • If the Event Log is the active screen and the Event Log icon button turns red or yellow, clicking on this button moves the scroll bar to top or bottom of the screen according to the sort order set. (E.g. If sort order is ascending the scroll bar moves to bottom of the screen and if sort order is descending scroll bar moves to top of the screen).
  • In the Reagent Inventory screen, there is only one entry for multi-constituent packs with a single calibration curve. (E.g. There is only one entry for Total hCG, as there is only one calibration curve for both TBhCG and Dil-hCG.)
  • The Access 2 software now indicates in Supplies Required (and subsequently flags results if overridden) tests for which the substrate lot is expired.
  • When Sample Manager screen is activated, the cursor is set to the Rack ID field.
  • The Access 2 software now supports the manual rerunning of QC tests from the Test Results screen. The software can only rerun a QC test for which the original sample tube and rack is either off-board or still on-board the original instrument. If the original rack has been cleared or moved to another instrument, and the user selects the Manual Rerun function, a message box is displayed to indicate to the user the reason why the test cannot be rerun.
  • Additional fields are now included in the Diagnostic Copy to Disk report. Some obsolete fields and columns have been deleted, and other fields have been modified to report more appropriate data. The changes are as follows:
    1. A <Sample Serial> field is removed. (Previously, there were two redundant fields)
    2. The value of <Test ID> is modified from the assay name to the assay id.
    3. The field <Parent Test Serial#> is removed.
    4. The <read time> field is modified to indicate the correct value. The previous implementation always indicated the report request time.
    5. The following fields are added: <Test Name>,<Reagent Pack Number>,<Reagent Pack Lot #>,<Reagent Pack Serial #>,<Result Precision>,<Group Time>,<INS Flag Time>,<APF Rev>

Lock up Conditions

  • A problem was corrected that resulted in a lockup of the instrument software when processing some device errors. The software now correctly reports the device errors to the Event Log.
  • A problem was corrected that resulted in an application lock-up if the user used the Back global navigation button to enter the Test Request screen after deleting the last rack that was viewed in this screen. The software now detects if the last viewed rack was deleted and does not allow the user to enter the Test Request screen through the Back button. Normal entrance to the Test Request screen through the Sample Manager screen remains unchanged.
  • A problem was corrected that could cause the console application to crash if a software error occurred (e.g. Database error) while scanning a rack. The software will now report the software error in the Event Log and should only require the operator to re-attempt the rack loading operation.
  • A problem was corrected in the install that resulted in the failure to update the 'startup' file in the instrument software.
  • A problem was corrected when loading substrate that resulted in a discrepancy in the substrate supply between the console and the instrument if a communication error occurred. This problem could result in the system failing to run scheduled test and remaining in the Running mode until the user restarted the instrument and reloaded the substrate bottle.

User Interface Exit Conditions

  • A problem was corrected that resulted in an “MFC Exception logged at application top level.” error if the user attempted to use the Send to LIS function of the Test Results Screen after deleting a Test Result. The software now detects that Test Results have been deleted and instructs the user to refresh the Test Results screen.
  • A problem was corrected that resulted in an “MFC Exception logged at application top level.” error if the user attempted to use the Find function of the Test Results Screen after deleting a Test Result. The software now detects that Test Results have been deleted and instructs the user to refresh the Test Results screen.
  • A problem was corrected that could result in an “MFC Exception logged at application top level.” error in the Maintenance Request screen if the user used the Menu and Back global navigation buttons to switch to the Maintenance Request screen from Test Request screen and Sample Manager screens.
  • A problem was corrected in the Derived Results screen, which allowed the user to delete predefined derived result equations (e.g. FTI) after deletion of a user defined derived result. Deleting all derived result equations results in an “MFC Exception logged at application top level.” error, when entering the Derived Results screen.
  • A problem was corrected that could result in an “MFC Exception logged at application top level.” error in the Test Request screen when sample tubes were moved within a rack and the user clicked on different rows on the screen, while the rack was being reloaded.
  • A problem was corrected that could result in an “MFC Exception logged at application top level.” error in the Sample Manager screen, in the following scenario:
    • Load a rack that is not predefined from the Sample Manager screen.
    • Press Run.
    • Prior to the instrument entering Running mode, select the rack and attempt to enter Test Request or Maintenance Request.
  • A problem was corrected that resulted in inconsistencies in the contents of the database. Symptoms of the problem included test results missing from the continuous sample report, and an “MFC Exception logged at application top level.” error occurring when test results were deleted via the Test Results or Work Pending screens.
  • A problem was corrected that could result in the Console application crashing if the user manipulated the scroll bar with the touch screen and the mouse simultaneously.

Database Issues

  • A problem was corrected that resulted in the failure of the software to detect a "No RV In Pipetting Position 1 Or 2” error for some assays.
  • A problem was corrected that resulted in the inability to unload a reagent pack following a run (lock symbol permanently displayed next to the pack on the Supplies screen) in the following scenario:
    • The system detects a “No RV In Pipetting Position 1 Or 2” when attempting to dispense reagent for a two-step assay.
    • Prior to the completion of the first incubation period, the system enters “Not Ready” mode due to a fatal device error or the user selecting the Stop key.
  • A problem was corrected in the handling of the supply counts for RV’s, if an error occurred during system initialization and there are zero RV’s in the rake and less than a full row of RV’s in the shuttle. The problem prevented RV packs from being loaded and resulted in an unrecoverable “Critical Event Failure”.
  • A problem was corrected which resulted in the console application failing to fit the results for a calibration curve if the application crashed or was shutdown while the curve fit calculation was in process. This problem resulted in the inability to request subsequent calibrations against that calibration lot. The software now checks for any “Pending” curves at application startup and attempts to fit the results for the curve.
  • A problem was corrected, which resulted in application errors if the database contains more than four instruments for a workgroup (caused by add/change/retire instrument in the workgroup). The problem resulted in the LIS Server crashing at application startup, and in the incorrect Instrument Ids appearing in the Test Results and QC Filter dialogs. The LIS Server no longer crashes if the database contains more than four instruments. The filter dialogs now display only the four most recently run instruments. Note that any custom Test Result filters may need to be reprogrammed when instruments are added/retired from a workgroup.
  • The software was updated to terminate the application if the POET database server generates a fatal error after selecting the Run key. Previously the application continued to execute, which caused the application to crash at a future unpredictable time.

Result or Printout Issues

  • A problem was corrected that resulted in a failure to associate the Patient Identification string with a sample tube if the Access 2 Console received an LIS test request after the sample tube had been scanned and loaded. The software now checks if the sample tube does not have a Patient ID string, and if so, assigns the Patient ID string sent by the LIS to the sample tube when the LIS test requests are assigned to the sample tube from Work Pending. This corrects both the Test Request screen and the Continuous Sample Report not properly displaying the Patient Identification for affected sample tubes.
  • A problem was corrected in the QC Chart and Data screen and the Compare Charts screen, which resulted in the incorrect display of some points in red, if the point failed a Westgaard rule but the rule was not enabled for the displayed control range.
  • A problem was corrected that could result in the failure to print sample and patient information on the Continuous Sample Report. The problem occurred only when a sample tube was removed from a rack position and replaced with another sample tube during a run. In this scenario the Continuous Sample Report would fail to print the sample and patient information for the second sample tube if the results for both samples were printed on the same page.
  • A problem was corrected that resulted in truncation of the Value field in QC report if the units were S/CO.
  • An error was corrected that resulted in an incorrect value for the N field in the QC Chart and Data screen and Compare Charts screen when points were omitted.

Workflow Issues

  • The user no longer must select the Pause key followed by the Run key when changing the Liquid Waste and/or Wash Buffer bottles while the system is running. The system will automatically pause and re-send the test list to the instrument.
  • In the Supplies screen, only the tests enabled on that instrument are used to determine the background color in the Lot Number field of a reagent pack button displaying the status of a multi-constituent pack. Previous versions of the software used all tests of multi-constituent pack to determine background color of the Lot Number field.
  • An error was corrected in the substrate usage for the Volume Check diagnostic. The substrate usage now decrements by three for substrate Volume Check and by zero for all other Volume Checks (was decrement by (3 x the number of prime cycles) if a prime was done prior to the Volume Check).
  • A problem was corrected that resulted in patient and control requests being set to a status of Supply Wait, when they were ordered simultaneously with a calibrator with an expired curve. The software now detects that a run contains calibrator, patients and controls against a calibration with expired curve and allows the calibration, patient and controls to run.
  • A problem was corrected that caused some off board racks to disappear from view when the user loaded racks onto the system. The user was forced to exit and re-enter the Sample Manager screen to regain access to the racks.
  • A problem was corrected that could result in the display of incorrect values for the completion and aspiration times in the Sample Manager and Test Request screens, if multiple replicates of an assay were requested.
  • A problem was corrected which resulted in the Work Pending icon not reflecting the contents of the Work Pending screen in some infrequent user scenarios. The Work Pending icon now updates correctly.
  • A problem was corrected in Calibration Setup screens, which prevented the user from editing/deleting a calibrator lot from some consoles in a workgroup environment. Once a calibration lot was edited, the user could only edit/delete that lot from the console at which original editing was performed until the workgroup was restarted.
  • The Sample Manager screen now correctly displays sample tubes in red that have triggered a QNS error.
