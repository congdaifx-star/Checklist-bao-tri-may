Software 1.20 Known Bugs and Behaviors

A list of known bugs or behaviors and countermeasures for recovery for system software versions 1.20.

  • Bug/Behavior: Summary of the software bug or system behavior.
  • Details: Explanation of the bug/behavior and how it may impact the system/user.
  • Countermeasure: If applicable, countermeasure to resolve the condition inflicted by the bug/behavior.
Bug/Behavior Details Countermeasure
Rack Commit Failure when Ordering Multiple Racks Through Enhanced Test Order When a user attempts to order multiple tests racks through the Enhanced Test Order screen, only a few of the racks are committed while others are rejected, reporting "There are no tests ordered for the tube". Committing each rack individually allowed for all racks to be committed successfully. Note that the Enhanced Test Order screen should only be available for internal users. Users are not trained on Enhanced Test Order and it is only used with recommendation with BEC field service guidance. In this specific case, internal users used the Enhanced Test Order for a study on assay setup, not patient testing.
TnI 186 Version Not Updating Calibration Volumes When Multiple Lots Are Loaded or Unloaded From System For TnI test, the calibration edit order view may not show the calibrator volume in the load guide if multiple reagent lots are available. Customers should refer to the assay IFU. No countermeasure.
Consolidate Passengers When Gripper Does Not Detect a Tray After removing a pack of trays from the stocker, the system does not consolidate the removal and the counting of passengers becomes corrupted. The system must be reinitialized to resume normal operation.
Reagent Not Enough Error Displayed When Calibrating TnIhs When a calibration starts, the system checks if there is enough of the reagent available to run it. If not, a sample action is generated to notify the user. Currently, the system uses the assay code to look up reagents. However, the list of reagents needed to run the test is keyed by the test definition code. So for cases like TnIhs, where the test definition code is different from the assay code in certain regions, this lookup fails, causing the sample action to be created. This is separate from the actual scheduling of the test and reagents needed, so the calibration does actually run normally, using the correct reagent. No countermeasure.
An incorrect reagent serial number may be associated with calibration orders When you order a calibration from the reagent details screen and review it on the calibration order details view it appears that it will run on the specific pack. In fact, the system will only honor the lot, not the serial number. They system may run the curve on any available pack of that lot. No countermeasure.
The date range for Results to Disk files must be within the current year The Results to Disk date picker only allows you to pick the current calendar year. Users will not be able to export a date range that includes the prior year. No countermeasure.
When the Clean Routine maintenance task fails, the maintenance workflow may remain on the user interface indefinitely If the weekly clean routine fails, the maintenance wizard displays the text "Redirecting" instead of exiting the wizard or offering a next step. The user must close this tab and re-initialize. No countermeasure.
System Stops Scheduling New Tests after 25 days of Continuous Operation After 25 days of the system software being continuously active (system is powered on, but does not need to be running tests continuously), running tests, the system will fail to schedule new tests. The system can be rebooted to correct the problem. A system restart is required to force the system to restart scheduling.
Duplicate Test Order Send Result in Cancelled Tests The system may send in the test list to the instrument of a reflex add on order some orders from the primary request that have already been acknowledged and aspirated by the system. When the system receives these orders in the addon list it does not recognize that they are samples already running on the system and ends up cancelling them and reporting a sample action for Sample Not Onboard. These replicates do not receive a flag to indicate what the problem was. No countermeasure.
System Configuration Allows Sample-type Conflicts for Combo Tests The system will user to add a new sample type (e.g. plasma) to a combo parent, but not the constituents. This created problems later in test results processing. The system should enforce that a new sample type applies to all elements of a combo test. No countermeasure.
Tray Gripper: Action Contains Invalid Argument An invalid argument is passed when invoking gripper mechanical initialization. The error occurs only when unlocking the door from intrusive diagnostics and under specific conditions where gripper is not placed at a safe position on both Z and Y axes. The system is already in an offline mode if the user is using intrusive diagnostics, and can be corrected with a system initialization. No countermeasure.
SPU Pushes Racks to Offload Area Instead of Processing in Presentation Unit After interrupting the load process using the SPU load button, if a new rack is placed in the onload area and the door is closed while the last rack is being ejected from the presentation area, the newly loaded Rack will be ejected into the offload area. This only occurs within a very small time window and is difficult to reproduce. If it occurs, the user must reload the Rack again. User will need to reload the rack to begin processing the samples if this occurs.
Error Handling Events Do Not Match Instrument Status Red system events from some errors state that "The analyzer cannot process samples.", but for error handling conditions where the recovery is successful, the instrument returns to a running state and will accept new samples, but the red system event isn't dismissed. No countermeasure.
Losing a vessel in transit from the Incubate Pick and Place Causes an Unrelated Error The system may fail to properly recover when a vessel is lost during transfer from the reaction build carriage to the incubate wheel leading to a hard stop. No countermeasure.
Wash Wheel Auto-Alignment Exits Early When Slippage Is Detected Outside Window of Acceptable Alignment Values When wash wheel plate slippage occurs outside the window of acceptable alignment values* the auto-alignment routine exits. If this occurs during the first cycle, no motor values are saved to the list used to calculate the alignment value. See Troubleshooting Wash Wheel Plate Auto-Alignment Failures for more information.
SPU Auto-Recovery may Delay Unload From Presentation Area When recovering from an error (e.g. jam in sample load area), the system may not promptly unload racks from the presentation area. The issue can be fixed with a system initialization. No countermeasure.
Semi-Quantitative and Quantitative QC mean calculation is incorrect when units are changed The QC statistics values will not be calculated correctly if the data points use different units. The summary statistics on the control cannot be used if it contains values of mixed units. The user must create a new control if they want to change the unit.
Rerun/Reflex Test Ordered When Input Test Result is "No Result" When a rule uses the result value of a test as a condition for rule evaluation, and the result value of the test in processing is a non-numeric value (e.g.: "No Result" or null), the rule will parse that result as "0" and use "0" in the rule evaluation. No countermeasure.
Analytic Pick and Place to Wash Wheel Auto-alignment Uses Incorrect Offset for Z Alignment Point Calculation The auto-alignment procedure to align the Analytic PnP to the Wash Wheel plate uses a vertical offset for vessels instead of the plate. Service will need to manually confirm that the alignment position is not set too high relative to the plate. No countermeasure.
Unable to dismiss "No Pending Test" Sample Event Unable to dismiss "No Pending Test" Sample Event manually and automatically No countermeasure.
Host Query Race Condition Causes "Sample Not On Board" Event When the LIS host query responds at the same time as the system timeout there may be a confusing event displayed about the sample not being on-board the instrument. No countermeasure.
Exception Thrown When LIS Code is Missing for a Calculated Test The system will report an error if the user does not remember to assign an LIS Code when creating a new calculated result. This error message may be dismissed without consequence. No countermeasure.
QC Data Export Can Fail If Data Size Too Large The system will may fail to create the QC data export file if the dataset becomes too large (e.g. >15,000 results). User can restrict the data range to limit the size of the data file.
Calculated Results are Not Included in Results To Disk Calculated results are not included in the test results file export. This has never been implemented, but users may expect it. No countermeasure.
Calculated Test is not Generated when Constituents are Automatically Ordered via Automatic Rerun/Reflex Rule Given a calculated test that consists of one or more constituents, e.g. CalcTest = TestA + Test B, the calculated result CalcTest will correctly be produced when the user orders TestA and TestB on a sample. However, if the system automatically reorders TestA or TestB due to a rerun or reflex rule, the system will not also re-order the rerun for CalcTest and no calculated rerun result will be produced. The user can avoid this by creating a new order. No countermeasure.
Canceling Tests due to SWT Creates Conditions for Instrument Hard Stop In rare cases, the system can stop processing tests when a sample vessel which still has test requests is cancelled and flagged SWT (Sample Wheel Timeout). This only occurs if the timeout occurs during a small time window when the system attempts to prepare a reaction vessel for that sample just as the timeout is reached. A system initialization will correct the condition. No countermeasure.
Manual Dilute and Rerun Cannot Be Requested When the Sample Has a Cancelled Test If a sample contains any test result that has been cancelled, and the user attempts to order a dilute-and-rerun from the test result screen for a different result that was NOT cancelled, the system will erroneously display a dialog stating the order cannot be created on a cancelled test result. The user can still order the dilution manually via the normal test order entry screen, instructions for which are included in the error dialog text. No countermeasure.
Sample Search May Stop Functioning and Require a Restart In very rare cases, the sample search bar may stop responding to search input. The system must be restarted for the correct functionality to be restored if this happens. This has never been directly observed on a DxI 9000, but has been seen on other products using the same function. No countermeasure.
Reagent Pack is Not Available to Run after Calibration Initially Fails Due to System Error If a calibration fails due to a system error (e.g. SYS flag), the system will fail to make the affected reagent pack available for patient tests after re-running the calibration. The system will report a sample event "Reagent pack assigned for calibration only". This can be corrected by loading a new pack of the same lot, or restarting the system. This only occurs if there is only one pack of that lot onboard. No countermeasure.
Precision Sample Pipettor Volume Check Error Handler Improvement The systems may trigger a secondary error after an initial sample pipettor issue during a dilution build. After improving the error handling the secondary error may be preventable in some cases. No countermeasure.
Prototype Alignment - Wash wheel "Auto Align" Button does Not Reliably Execute All Auto-alignment Routines When using the top-level "Auto Align" button for wash wheel, service may expect this to align all four alignment points when in fact it only executes dispense arm alignment. A "Save Successful" popup is displayed after each of the four auto-alignments is completed. After the dispense arm alignment completes, user may not realize that only one auto-alignment was performed because they received the "Save Successful" popup. No countermeasure.
Incorrect Calibration Curve Soon to Expire Message for Combination Tests (cHIV) In certain circumstances after standard combo calibration can become due soon on the all/due calibrations screen when the curve actually isn't due soon. The correct calibration expiration date is displayed in the curve details screen. The due state can be reset by disabling the affect test in the system configuration and then reenabling it. It can also be recovered by restarting the console application. This does not affect MeMed or normal assays. User could be misled into thinking a calibration is required when it is actually not.
