Software 1.17/1.17.2 Known Bugs and Behaviors

A list of known bugs or behaviors for system software versions 1.17/1.17.2, and countermeasures for recovery.

  • Bug/Behavior: Summary of the software bug or system behavior.
  • Details: Explanation of the bug/behavior and how it may impact the system/user.
  • Countermeasure: If applicable, countermeasure to resolve the condition inflicted by the bug/behavior.
Bug/Behavior Details Countermeasure
Thousands of warning system events with no events displayed in log. Run-up System Events warnings with no data displayed in log: SQL Data-base needs to be updated. You can clear the events by updating the database by running script to set the active events to 0.

Shutdown Machine Control to ensure no new events are added.

  1. In Windows, open The SQL database connection.
  2. Copy, paste, and execute this script in SQL: update ice_db.dbo.events set active = 0
  3. Close the SQL database connection.
  4. Start Machine Control and verify it initializes or send us the log of new errors.
System Cannot Initialize Due To Logical Error in Event Reporting. The system can appear to initialize indefinitely when event DAC communication fails repeatedly.

Note that cache file reconciliation occurs at software startup, NOT initialization. So reinitializing without restarting the software will not help.

  1. Resolve the underlying DAC issue, perhaps by rebooting the instrument computer or freeing up disk space.

  2. If the issue continues, then delete the event cache file (PendingEvents.json) from D:\ProgramData\Beckman Coulter\Falcon

Passenger Consolidation Fails For RSM During Initialization After Software Upgrade. After software upgrade, the instrument failed to initialize during passenger reconciliation stage. While reagent packs were being restored from ReagentPack.data, a pack was unable to be placed in slot 0 because it appeared to already be occupied (in reality, gripper was empty, only logical passenger was present).

Use script in Service Application to remove invalid pack.

  1. Service app

  2. Scripting

  3. Go to Remove Invalid Pack

Unable to Store Alignment Data Error Display. System displays an error indicating that the analyzer cannot process samples and was unable to store configuration or alignment data, but the system indicates that it is ready to run. This alignment feature is used only by service technicians.

Close (if open) the prototype alignment page; re-open the prototype alignment page. This appears to reset the status of the alignment data.

Restarting Machine Control will also clear this condition.

System Stops With An Error After Canceling An In Progress ASD Request. System fails to cancel an Automated System Diagnostic test request when tasks are running in background. The system can be re-initialized to clear the issue. ASD tests are only performed by service engineers.

Reinitialize instrument to clear error.

Date and Time Do Not Appear in DxI 9000 CSV file When Viewed in Excel. When exporting results to csv, the date/time data are not correctly formatted to automatically be displayed correctly by excel. The data and time can still be viewed, but it requires the user to double click on each cell in Excel or manually format columns in Excel. This file is generally used by the Beckman Coulter applications teams. The data and time can still be viewed, but it requires the user to double click on each cell in Excel or manually format columns in Excel.
Empty Reagent Packs for Combination Tests are Not Discarded For combination style tests (HBsAg, HIVCombo), the system will retain a reagent pack onboard even after it has been depleted and no longer has enough for both constituents. The user can still manually discard or onload the pack.

Manually discard the depleted pack and load new packs.

No Reasons Provided for Not Running Tests when Reagent Storage Temperature is Out of Limits. User is not notified why tests are not running when system is in a temperature out of control condition in the reagent storage module. Check temperature for deviation if tests do not start.

Tests Will Not Start In Enhanced Test Order After RAPIDs Install via RSU (Remote Software Update). After a new APF is installed, the Enhanced test order screen will not work until the system is restarted. No countermeasure. Do not update RSU while tests are in progress.
Changing the User Interface (UI) Language May Not Refresh All UI Text. Due to the instrument software not changing languages when the user interface does, certain events may not be translated until the whole system is rebooted. No countermeasure.
Wash Wheel Error When Running ASD Tests. On some occasions, ASD tests may stop unexpectedly due to a wash wheel error. The user can recover by re-initializing and reordering the diagnostic. The user can recover by re-initializing and reordering the diagnostic.
Calibration Event Displays Wrong Rack ID. Failed calibration event displays incorrect rack ID when calibration is rerun using a different rack than the prior calibration failure event. No countermeasure.
Handling Incorrectly Persisted Data in the ".data" Files. After a severe system error during a system software upgrade attempt, the instrument passenger data can be out of date. This will result in "invalid passenger" messages that will not allow the instrument to initialize. Close machine control and close applications. Delete data files in d:\programdata\beckman coulter\Falcon. Restart the PC.
Single Disabled Reagent Pipettor Blocks Test Execution. The system will be unable to process tests if a pipettor is disabled and the system automatic substrate prime is due. The pipettor must be re-enabled to allow the system to complete priming before resuming operation.

Don’t prime or run diagnostics with pipettors disabled.

Reagent Pipettor Pressure Monitoring Fails with Non-English System Configuration. Communication between machine control and the model evaluator application is done via text strings. The decimal values passed back and forth are therefore subject to number-formatting localization. Since machine control always runs in English regardless of the system setting, but the evaluator runs in whatever language is selected, decimal values cannot be parsed on the other side for languages that are incompatible with English formatting (e.g. period vs comma separator). Set Windows language/region settings to US English.
SampleIntakeErrorHandler does not Unlock Sample Wheel. SampleIntakeErrorHandler does not unlock Sample Wheel if it was locked as a part of failed aliquot process. Reinitialize instrument.

Tests not aliquoted from sample vessels on Sample Wheel. Instrument not restarting after Lumi Drift Check (Red System Event) Re-Initialization.

There may be a delay to return the system into a running state if the ASD Luminometer Drift Check is completed sooner than expected. Wait 15 minutes after ASD completion.
SPU presentation action timeout after SPU load button was used. If the user attempts to load a rack while another rack in the presentation area, there is a short time window in which if the SPU door closes, a timeout error can occur. "The sample handler is jammed" system event is displayed and user is not able to load additional racks until the instrument is reinitialized. Do not close the cover when the rack is operating.
Single dark count read out of range during initialization should fail. If the instrument's luminometer reads a dark count value of greater than 300, the instrument should throw an error and prevent the user from running. The luminometer is compromised and needs to be cleaned before use.

Clean the luminometer, refer to Cleaning the Luminometer.

Slot occupied condition due to incorrect sample vessel cancelation during error handling. After some Incubate Pick and Place failures, a sample vessel may fail to be cleaned out from the reaction build carriage, resulting in "slot occupied" error. The instrument will need to be reinitialized in order for the sample vessel to be cleared.

Reinitialize instrument.

Weekly cleaning routine reports confusing software error message.

If there is a system error during the weekly clean routine (e.g. pipettor detects a leak) the system will report an ambiguous error message about a "Boolean Disposing Error" instead of the actual failure, making the issue difficult to troubleshoot for service. No countermeasure.

Add-on order accepted even though sample was already expired and offboard.

Add-on order accepted even though sample was already expired and offboard. The order cannot be processed and stuck in embedded memory until process restarts. This is shown in the service view, but not visible to the customer. No countermeasure.

TnI 186 version not updating calibration volumes when multiple lots are loaded or unloaded from system.

For TnI test, the calibration edit order view may not show the calibrator volume in the load guide if multiple reagent lots are available. Customers should refer to the assay IFU.

Customer should manually calculate the required volume(s) based on the reagent and calibrator IFU and add the dead volume based on the container type.

Consolidate passengers when gripper does not detect a tray.

After removing a pack of trays from stocker, the system does not consolidate the removal and counting of passengers is corrupted.

Reinitialize instrument and restart PC.

The tray exerciser processing is not aligned with tip supply controller state.

If an error occurs in the tray exerciser, the function is terminated without processing the rest of the tip supply handling controller state, resulting in an error that prevents it from starting the next time the exerciser is executed.

Refer to Troubleshooting DispoTip Stocker. Restart PC.

Subsystems motion error event information incorrect

If the reagent pipettor has a motion error, the detailed error information available to service does not correctly display the final position of the device, which can make trouble-shooting the error more difficult. This does not affect the correct behavior of the device itself.

No countermeasure.

Missing sample event for sample rack ID cannot be read in other languages and only invoked with single rack error

When the system cannot read a rack barcode the event about the missing/unreadable barcode does not display in non-English languages. For the test case with a rack ID without a barcode in a mix of racks, there is no event displayed at all. Machine Control log files do indicate what the issue is from a service troubleshooting standpoint, but the customer will have to rely on the sample list screen showing the sample requested is still pending rather than waiting for the event until this anomaly is fixed.

No countermeasure.

Erroneous QNS reported when there is enough sample to run base test but not add-ons if total volume requires multiple aliquots

A QNS event is reported when there is enough sample on board to run the base test but not the add-on tests if the total volume requires multiple aliquots. The aliquot for the base sample does not occur despite there being enough for the base test. The base test or primary test should always run if there is enough volume and should not be dependent on if there is enough sample volume for any add-on orders. This only applies if the total sample volume exceeds the amount that can be handled by a single disposable tip (250 microliters).

No countermeasure.

Sample mismatch error nullifying target vessel and provoking hard stop

When sample tubes got swapped during aliquot, a protection check detects the issue and raises an aliquot error. This will cancel all non completed aliquots including one being processed. When canceling aliquots, target vessels must be unlinked which causes target slots to be null. A system error occurs when a null slot is detected. Initialize system after a hard stop.

System displays a misleading reagent serial number on calibration orders created from reagent details screen

When you order a calibration from the reagent details screen and review it on the calibration order details view it appears that it will run on the specific pack. In fact, the system will only honor the lot, not the serial number. They system may run the curve on any available pack of that lot.

No countermeasure.

When multiple user create calculated result test are saved in configuration that prevents application from restarting

The system will only allow a maximum of one calculated result to be configured. If the user attempts to create more than one, the instrument software will not start the next time the system is rebooted. The user must then remove all but one calculated result to get the system to start up.

No countermeasure.

Results to disk limits access to current year

The Results to Disk date picker only allows you to pick the current calendar year. Users will not be able to export a date range that includes the prior year. Increase 'MinimumDaysBack' in falcon.settings and restart instrument.

LAS: an invalid GetTube is being sent in the sequence and interrupts sample processing

When the system is creating aliquots via an automation line track, "TubeBypass" may occur and the transfer may stop. This is due to an unnecessary "GetTube" message is being sent from the DxI 9000 system to the LAS track. This can result in the system failing to process additional tubes from the track without manual intervention. No countermeasure.

Rack "Stuck" in Instrument After SPU Presentation Jam

After the SPU error and following recovery, instrument needs to eject the sample rack, so SPU may be used again. Instead, the instrument keeps the sample pack inside, creating user confusion about further SPU usage.SPU would be operational again after user open/close the SPU cover. But user usually unaware of this and waits for rack being rejected. The user can recover by initializing the system.

Reinitialize instrument.

RSU (Remote Software Update) RAPID Update Clears Test Menu

When a system does a test menu update from version A (manifest generated with RDM 3.6) to version B (manifest also generated with RDM 3.6) the test menu of the system is cleared. In the short term, manifests should be manually wrapped to ensure version data are part of the .rapid file name in the package.

Luminometer Drift Scheduling Deadlock

In some conditions a deadlock can occur between the automated luminometer drift detection and sample processing that causes neither activity to be completed. Pause the instrument and run drift manually.

Not Restarting Test Processing after Aliquot Pipettor Error Automatic Recovery

Aliquot Pipettor error caused instrument to finish in progress tests. At the same time, the Aliquot Pipettor auto recovered. However new tests were not scheduled until an initialization was performed. Reinitialize instrument.

Reagent Pipettor Fluid Heater Temperature Data- Increase Sampling Frequency to Reduce TRP Overflagging

The software can produce excessive TRP flags when the reagent volumes for a test are high and system is running a lot of tests. No countermeasure.

Rack Commit Failure when Ordering Multiple Racks Through Enhanced Test Order

When a user attempts to order multiple tests racks through the Enhanced Test Order screen, only a few of the racks are committed while others are rejected, reporting"There are no tests ordered for the tube". Committing each rack individually allowed for all racks to be committed successfully. Note, that the Enhanced Test Order screen should only be available for internal users.

Apply the latest build.

Set the order only with "Test Order Info" without selecting the tube in the rack on the screen.

Result to Disk Throws Error When Only Start Date/Time is Edited

Users may see an error "Start data must be earlier than end data" when attempting to use the result to disk function even though the dates are valid. If the user enters a custom start date, they must also adjust the end date to avoid the erroneous error message. Need to manually change the end date time.

Imported Test Definitions Can Be Configured to Act as Calculated Results

The "Is Calculated Result" option is visible on the test definition details view for tests that are configured via the APF when it should not be an option since it is a "closed" definition and cannot be used as a calculated result name. Dont check the box to mark a test as calculated result

ASD Low Volume Reagent Pipetting Passed With Failing Results

Pass/Fail is overwritten each time the software evaluates an acceptance criteria, it overrides the pass/fail evaluation from the previous check, so if the last processed data (20μL) is Pass, it will appear to be Pass even if 10μL is Fail.

No countermeasure.

Error Sending Results for Tests using Diluent Packs to IntelliServe

System attempts to report a default DateTime value for the Dilution Pack Expiration field in the Normalized result. This results in an error in converting the date time for the expiration field when IntelliServe connected instruments attempt to send the associated result data resulting in failure to send the results. This only affects results for assays that use a dilution pack for the processing of that specific result. No known workaround for issue.

No countermeasure.

Customer-initiated Emergency Stop Recovery Requires Software Restart After a user-initiated emergency stop command from the user interface, the system cannot be returned to an operational state simply by re-initializing the system. Restart the Console PC.
System Fails to Reinitialization after Emergency Stop The system may fail to re-initialize after a user-initiated emergency stop. Restart the Console PC.
Secondary Error From Interlock Hard Stop Persists After Re-Initialization Opening and closing the instrument covers while the tray gripper is attempting to move can cause the instrument to get stuck in an error mode. Close the covers and perform a full initialization via the Diagnostics menu or restart the instrument and initialize.
Bad Reagent Storage Module Alignments Can Prevent Software From Starting If RSM gripper alignment in nest 37 and nest 50 are the same value, the RSM will fail and cause the software to stop accepting requests. When the software is restarted on the instrument, an error dialog showing "Failed to load Machine configuration" and the application will close. This closure of the application will prevent access to the alignments screen in the machine control database. No countermeasure.
The PnP Vessel Lost Condition is not Properly Handled, followed by Instrument Hard Stop The error handling is not performed correctly for cases when vessel is lost while on-route from one location to another. Reinitialize the system.
System Stops when Running at Maximum Capacity and Fills Incubate Wheel If the test volume is very high and running tests with long incubation times, the incubate may fill up. This can cause the system to stop processing tests and report a red event with an "IndexOutOfRange" error. The system must then be re-initialized to resume operation. This error has only occurred under during BEC verification testing conditions and not under normal operation conditions. Reinitialize the system.
Tests Not Aliquoted From SVs on Sample Wheel Not Restarting After Lumi Drift Check Missed (Red System Event) Re-initialization There may be a delay to return the system into a Running state if the ASD Luminometer Drift Check is completed sooner than expected. No countermeasure.
System Not Invalidating Reagent Packs for Tests with Pack Descriptor File Changes The instrument should invalidate reagent packs that were previously onboard if a Rapid Test (APF) Definition is updated with pack file changes. The reagent pack should be marked as unusable and discarded upon a test menu update. When testing this workflow, it was found that when loading a pack revision file the reagent pack was not marked as unusable. No countermeasure.
Calibrations in Result to Disk CSV Does Not Display "NaN" for Dose Values Below Zero When XML calibration file is reviewed from the results for replicates that display an "NaN" value for either one or both replicates, the "NaN" is not being transmitted to the CSV file export. No countermeasure.
Temperature Diagnostics Screen Highlights Reagents Storage Coolers For No Reason On the instrument's temperature diagnostic screen, there was an indication that there was an issue with the reagent storage coolers despite there actually not being any issue. No countermeasure.
Calibration Result File to Disk - Does Not Serialize CurveValidationOuputs Calibration result to disk is exporting the data type instead of data values. No countermeasure.
RV Supply Elevator Jam Recovery Early Exit When the instrument attempts to recover during a bulk feeder RV elevator jam, the recovery routine exits early if an index sensor is found regardless of whether encoder shows a motor slippage. The next pusher movement results in a hard stop. No countermeasure.
Substrate Lot Expired Event Requires Proper Description The event description for expired substrate barcode event states the substrate bottle is 'unknown', which is misleading and may cause customer confusion. No countermeasure.
Calibration Volume Not Displayed For All The Level And The Volume Differs Every Time Based On Other Test Which is Placed Together The volume required to perform calibration is not displayed until the page is refreshed however, there are times even after a page refresh some of the calibration levels do not display the volume required. No countermeasure.
Qualitative Tests and the Calibration Curve Details Page Due to an unimplemented feature, the calibration details page displays "0.00" in the expected column for assays that use a cutoff based math model. These should instead be displayed as N/A. No countermeasure.
Missing Translations for ASD Screens The user interface contains several untranslated strings, particularly on the automated system diagnostics pages. No countermeasure.
Test Order Errror through Enhanced Test Order Screen When Changing Sample's Test Orders While ordering through the Enhanced Test Order screen it is possible to receive a "No tests ordered for sample tube" error message after clicking Commit even though tests are requested for that Sample ID.

After registering a tube and selecting another one, error can be avoided by returning to the original tube and not adding any more tests.

Alternatively, when an update is needed, select the tube to update, create a new test order, and add it to the same container location.

Reagent Pipettor Pressure Monitor Does Not Clean Up Propertly on System Initialization After a primary unrelated failure occurs, the pressure monitoring software used by reagent pipettors did not fully reset when an error occurred during the evaluation step, resulting in subsequent initialization failures. The system must be rebooted to recover. Reboot the system.
Reagent Pipettor Fluid Heater Temperature Data - Increase Sampling Frequency to Reduce TRP Overflagging The software can produce excessive TRP flags when the reagent volumes for a test are high and system is running a lot of tests. No countermeasure.
Slot Occupied Condition Due To Incorrect SV Cancellation During Error Handling After some Incubate Pick and Place failures, a sample vessel may fail to be cleaned out from the reaction build carriage, resulting in "slot occupied" error. The instrument will need to be reinitialized in order for the sample vessel to be cleared. Reinitialize the system and perform Incubate Pick and Place alignments. Refer to Adjust/Align: Incubate PnP procedure.
Existing Troubleshooting Workflow Not Shown for "SPUNotSecured" System Error The system error that is generated when the SPU is not secured is not correctly attributed to the existing SPUNotInPlaceEvent troubleshooting wizard steps. Instead, the generic troubleshooting steps are shown which ask the user to initialize the instrument. Initialization would fail due to the SPU not being secured. No countermeasure.
A rack is stuck inside the analyzer After the SPU error and following recovery, instrument needs to eject the sample rack, so SPU may be used again. Instead, the instrument keeps the sample pack inside, creating user confusion about further SPU usage. SPU would be operational again after user open/close the SPU cover. But user usually unaware of this and waits for rack being rejected. The user can recover by initializing the system. Reinitialize the system.
Exception Thrown When {} Are Used in Sample Barcodes Currently the instrument cannot read barcodes that use "{" or "}" symbol. No countermeasure.
Sarstedt 10 mL tube may be misidentified as a Sarstedt 7.5 mL primpary tube The Sarstedt screw-top tube (product number 60.610.013) is mistakenly identified as Sarstedt 7.5 mL tube. These tubes have the same dimensions, so there is no risk of pipetting issues. No countermeasure.
Combo Replicates From The Same Sample Container Complete All At Once If multiple replicates of a combo test are ordered for a single sample container, then none of the replicates report results until they all complete. This is unlike non-combo tests where each individual replicate reports results as soon as it finishes. No countermeasure.
Combo Parent Test Not Included in Results to Disk The file discussed below is only for BEC Field Service Engineers. End users will not be looking at this file. When generating results using "Results to Disk", only the constituents are contained. cHIV parent result is not present. For cHIV the consistent results can be used to infer the parent result with knowledge of the basic logic, but this may not be valid for all combo tests in the future. There is no ability to export combo parent results for analysis without an LIS or middleware solution other than a manual transcription. No countermeasure.
APF Diagnostics Page is not Tracking with RAPIDS Folder When RAPIDS are Loaded Through RSU (Remote Software Update) Installing multiple RSU updates with add-on RAPID packages fails to update the test configuration correctly when the only changes are the RAPID packages' revision and tests have been removed compared to the previous add-on RAPID package. No countermeasure.
RAPID Version is Missing in Message to IntelliServe The RAPID revision is missing in the system data sent to IntelliServe. This data is only available to technical support for troubleshooting purposes. No countermeasure.
Incubate Pick and Place Pneumatics Failure Error Handling Does Not Start Pending Tests If the pneumatics supply becomes disconnected or otherwise compromised, the system will not be able to automatically recover from errors. A complete system initialization is required to detect the pneumatics issue as the source of the problem. Reinitialize the system.
Date and time must be specified for the start and end points when saving results to disk Users may see an error "Start data must be earlier than end data" when attempting to use the result to disk function even though the dates are valid. If the user enters a custom start date, they must also adjust the end date to avoid the erroneous error message. Need to manually change the end date time.
A Calculated Result checkbox is erroneously displayed when configuring tests The "Is Calculated Result" option is visible on the test definition details view for tests that are configured via the APF when it should not be an option since it is a "closed" definition and cannot be used as a calculated result name. Don't check the box to mark a test as calculated result.
Sample racks without a barcode label might not generate a sample event when the user interface is configured for a language other than English When the system cannot read a rack barcode the event about the missing/unreadable barcode does not display in non-english languages. For the test case with a rack ID without a barcode in a mix of racks, there is no event displayed at all. Machine Control log files do indicate what the issue is from a service troubleshooting standpoint, but the customer will have to rely on the sample list screen showing the sample requested is still pending rather than waiting for the event until this anomaly is fixed. No countermeasure.
QNS Event Description Incorrectly Identifies Number of Replicates for Each Assay QNS event description reports a replicate count that double counts the base test and includes the count of all potential rerun tests. No countermeasure.
Calibration Log Transform Curve Details Incorrect Any calibration that requires a Log Transform Offset (i.e. a Spline Fit Log10 Transform Model) cannot be calculated correctly. There are no tests currently using this parameter/math model. No countermeasure.
Precision Sample Pipettor Cannot Calculate Height for Negative Volume and Causes System Hard Stop Despite the QNS reported during sample aliquot, still empty SV was declared ready for test scheduling. The "negative volume" error was declared as Precision sample pipettor attempted to aspirate from empty SV. The system will not attempt to use the empty SV, but the system will stop processing. This issue has not been observed on any released assays. No countermeasure.
Reflex Test Does Not Complete When Prep Type of Reflexed Test Doesn't Match Prep Type of Original Test If a reflex rule specifies a test that has a prep type (neat or dilute) different from the reflex test ordered, the reflex test will not run. No countermeasure.
An incorrect reagent serial number may be associated with calibration orders When user orders a calibration from the reagent details screen and review it on the calibration order details view; it appears that it will run on the specific pack. In fact, the system will only honor the lot, not the serial number. The system may run the curve on any available pack of that lot. No countermeasure.
The analyzer will not return to a green Running state after a computer restart if the system configuration includes two or more calculated results The system will only allow a maximum of one calculated result to be configured. If the user attempts to create more than one, the instrument software will not start the next time the system is rebooted. The user must then remove all but one calculated result to get the system to start up. Remove the one calculated result or reboot the system.
The data range for Results to Disk files must be within the current year The Results to Disk date picker only allows you to pick the current calendar year. Users will not be able to export a date range that includes the prior year. Increase 'MinimumDaysBack' in falcon.settings and restart instrument.
When the Clean Routine maintenance task fails, the maintenance workflow may remain on the user interface indefinitely If the weekly clean routine fails, the maintenance wizard displays the text "Redirecting" instead of exiting the wizard or offering a next step. The user must close this tab and re-initialize. Reinitialize the system.
Test Menu Update With Same Package File Name Clears Test Menu When a system does a test menu update from version A (manifest generated with RDM 3.6) to version B (manifest also generated with RDM 3.6) the test menu of the system is cleared. This will only occur for APFs that do not have the version information appended in the *.rapid file name. In the short term, manifests should be manually wrapped to ensure version data are part of the .rapid file name in the package.
When Locking a Pipettor to a Specific Lot of Reagent, the Instrument Does Not Recognize the Presence of a Sample Diluent A Pack If a user attempts to use the Enhanced Test Order screen to direct the system to use a specific reagent lot for an onboard dilution area, the system will not process the request. Enhanced Test Order screen is for internal use only. No countermeasure.
Excessive Lumi Drift Events in Audit Log If the system is unable to perform the luminometer drift routine at the scheduled time, there will be an excessive number of events logged to the audit log about being unable to schedule this routine. This has no impact on the use of the system. No countermeasure.
Result Processing Error when Processing QC run as Patient Results may not get assigned on samples that are frequently repeated and/or have a high number of tests requested. Update settings file to set SampleIDReuse = -1 and restart the PC. This prevents aggregation of sample data so the data never grows past the 30MB size limit.
System Allows to Use the Same Rack ID Among Different Sample Types (Patient/DC/Calibrator) If the user swaps assigned rack IDs for pending calibration orders after they are initially assigned and saved, then the system does not prevent the user from programming patient samples or QC orders. If this rack is loaded, the system will attempt to process the patient or QC order on any unbarcoded tubes and the calibration order will remain in the ordered state. No countermeasure.
System Aliquoted Some Calibrator Levels Even Though All Containers Were Not Detected The system attempts to aliquot calibrator material even though tubes aren't detected in all positions. The situation is corrected when the user loads the missing calibrator levels. Make sure to use only known containers when building a rack. Ensure the SPU camera is calibrated correctly. Refer to Troubleshooting: Sample Container Detection procedure.
Wrong QC Order May Be Created After Calibration The system should create a QC order after a calibration is performed for any available pack for the calibrated analyte. Instead, it is assigning the QC order to a specific onboard pack. If that specific pack is not available when the system attempts to run the test, the QC test could be cancelled. Wait for the QC orders to expire and hope the patient samples can still be processed; or if available reload the missing pack(s).
Invalid Cast Error when System Attempts to Cancel Scheduling Cleanout Operation Instrument goes offline as a result of incorrect cast operation after errors with pick and place sensor verification. A system initialization will return the system to normal operation. Reinitialize the system.
System Stops Scheduling New Tests after 25 days of Continuous Operation After 25 days of the system software being continuously active (system is powered on, but does not need to be running tests continuously), running tests, the system will fail to schedule new tests. The system can be rebooted to correct the problem. Reboot the system.
Scheduler-Generated Calibration Event Not Translated in Set Console Language The event indicating that the scheduler needs a particular reagent pack to be loaded may be displayed in English instead of the user-configured language. No countermeasure.
Incorrect Pack Delivery Time Estimation Causes System Hard Stop The system estimates the time needed to transfer a reagent pack to the pipetting subsystems. The reagent pack exchange time is miscalculated, leading to incidents of 'Reagent pack is not at the pipettor nest' errors, which stop system processing. The system can be returned to operation with a system initialization. Reinitialize the system.
Calibration Mini Chart on Reagent Details Screen Displays in Default Unit Rather than User Unit The calibration mini chart on the reagent details screen is always shown in the assay's default unit, even if the user configured a different unit. The full calibration details screen always shows the curve in user unit, so this chart should be synchronized to match. This does not affect the calibration curve status in any way. No countermeasure.
Duplicate Test Order Send Result in Cancelled Tests The system may send in the test list to the instrument of a reflex add on order some orders from the primary request that have already been acknowledged and aspirated by the system. When the system receives these orders in the addon list it does not recognize that they are samples already running on the system and ends up cancelling them and reporting a sample action for Sample Not Onboard. No countermeasure.
"Calibration" Priority Text Not Localized on Samples List Page The priority text for "Calibration" is not localized on the samples list page for a calibration sample when the console application is changed to a different language from English. No countermeasure.
Wash Wheel Generic Failure (Boolean) On occasion, utility assays that do not do washing may stop unexpectedly due to a wash wheel error. This can occur when a service assay is requested directly, such as ASD substrate blank, or during a pre-run prime. In the latter case, the user requests normal assay(s), but the system queues up one or more substrate prime vessels to run before the normal assay(s). If the error occurs in this case, in-progress tests will be cancelled. The user can recover by re-initializing the system and attempting the same requests again.
