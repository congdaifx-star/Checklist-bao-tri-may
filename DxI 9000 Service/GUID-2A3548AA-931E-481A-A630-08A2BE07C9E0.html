Software 1.16/1.16.2 Known Bugs and Behavior

A list of known bugs or behaviors for system software versions 1.16/1.16.2, and countermeasures for recovery.

  • Bug/Behavior: Summary of the software bug or system behavior.
  • Details: Explanation of the bug/behavior and how it may impact the system/user.
  • Countermeasure: If applicable, countermeasure to resolve the condition inflicted by the bug/behavior.
Bug/Behavior Details Countermeasure
System Cannot Initialize Due To Logical Error in Event Reporting. The system can appear to initialize indefinitely when event DAC communication fails repeatedly.

Note that cache file reconciliation occurs at software startup, NOT initialization. So reinitializing without restarting the software will not help.

  1. Resolve the underlying DAC issue, perhaps by rebooting the instrument computer or freeing up disk space.

  2. If the issue continues, then delete the event cache file (PendingEvents.json) from D:\ProgramData\Beckman Coulter\Falcon

Passenger Consolidation Fails For RSM During Initialization After Software Upgrade. After software upgrade, the instrument failed to initialize during passenger reconciliation stage. While reagent packs were being restored from ReagentPack.data, a pack was unable to be placed in slot 0 because it appeared to already be occupied (in reality, gripper was empty, only logical passenger was present).

Use script in Service Application to remove invalid pack.

  1. Service app

  2. Scripting

  3. Go to Remove Invalid Pack

Unable to Store Alignment Data Error Display. System displays an error indicating that the analyzer cannot process samples and was unable to store configuration or alignment data, but the system indicates that it is ready to run. This alignment feature is used only by service technicians.

Close (if open) the prototype alignment page; re-open the prototype alignment page. This appears to reset the status of the alignment data.

Restarting Machine Control will also clear this condition.

Failed Calibrations May Remain In Progress. When a calibration failure is encountered after another error causes the instrument to stop during a calibration, there is a delay in reporting the samples for calibration are in progress to completed until fatal flags are applied. In the worst case up to 3 hours for SWT fatal flag. No Countermeasure. Bug will fix itself in three hours.
System Stops With An Error After Canceling An In Progress ASD Request. System fails to cancel an Automated System Diagnostic test request when tasks are running in background. The system can be re-initialized to clear the issue. ASD tests are only performed by service engineers.

Reinitialize instrument to clear error.

Date and Time Do Not Appear in DxI 9000 CSV file When Viewed in Excel. When exporting results to csv, the date/time data are not correctly formatted to automatically be displayed correctly by excel. The data and time can still be viewed, but it requires the user to double click on each cell in Excel or manually format columns in Excel. This file is generally used by the Beckman Coulter applications teams. The data and time can still be viewed, but it requires the user to double click on each cell in Excel or manually format columns in Excel.
Failures During System Clean Cause PC Resource Overuse. If there is an instrument failure during the system clean, the system will consume extra CPU cycles which can cause the system to become less responsive to user input or stop processing tests. The problem can be corrected by restarting the system. The problem can be corrected by restarting the system.
Automated System Diagnostic Running before Substrate Prime can Cause Hard Stop. ASD Wash Efficiency runs before Substrate Prime, which can cause the instrument to stop processing when substrate prime interval is exceeded. No countermeasure.
Empty Reagent Packs for Combination Tests are Not Discarded For combination style tests (HBsAg, HIVCombo), the system will retain a reagent pack onboard even after it has been depleted and no longer has enough for both constituents. The user can still manually discard or onload the pack.

Manually discard the depleted pack and load new packs.

No Reasons Provided for Not Running Tests when Reagent Storage Temperature is Out of Limits. User is not notified why tests are not running when system is in a temperature out of control condition in the reagent storage module. Check temperature for deviation if tests do not start.

Tests Will Not Start In Enhanced Test Order After RAPIDs Install via RSU. After a new APF is installed, the Enhanced test order screen will not work until the system is restarted. No countermeasure. Do not update RSU while tests are in progress.
Changing the User Interface (UI) Language May Not Refresh All UI Text. Due to the instrument software not changing languages when the user interface does, certain events may not be translated until the whole system is rebooted. No countermeasure.
Wash Wheel Error When Running ASD Tests. On some occasions, ASD tests may stop unexpectedly due to a wash wheel error. The user can recover by re-initializing and reordering the diagnostic. The user can recover by re-initializing and reordering the diagnostic.
Calibration Event Displays Wrong Rack ID. Failed calibration event displays incorrect rack ID when calibration is rerun using a different rack than the prior calibration failure event. No countermeasure.
Handling Incorrectly Persisted Data in the ".data" Files. After a severe system error during a system software upgrade attempt, the instrument passenger data can be out of date. This will result in "invalid passenger" messages that will not allow the instrument to initialize. Close machine control and close applications. Delete data files in d:\programdata\beckman coulter\Falcon. Restart the PC.
RSU RAPID Update Still Requires Application Restart to Complete.

When performing an RSU RAPID update, the instrument audit log shows that the installation completes. However, running a test with an updated version soon after the RSU update showed that the Test Order Entry screen is still using the previous (supposedly overwritten) version of the RAPIDs. This was remedied by restarting both Console and Machine Control, and a subsequent test correctly used the new version of the RAPID.

Intended behavior is that the system will use the new RAPIDs exclusively, without any additional steps.

Restart PC.
Single Disabled Reagent Pipettor Blocks Test Execution. The system will be unable to process tests if a pipettor is disabled and the system automatic substrate prime is due. The pipettor must be re-enabled to allow the system to complete priming before resuming operation.

Don’t prime or run diagnostics with pipettors disabled.

Overfilling 2 mL Sample Cups. When a Beckman 2 ml cup is filled too high (>1.9 ml), there is risk for process monitoring algorithm to misidentify the container as a Beckman 0.5 ml cup. Do not overfill 2 ml cups.
Reagent Pipettor Pressure Monitoring Fails with Non-English System Configuration. Communication between machine control and the model evaluator application is done via text strings. The decimal values passed back and forth are therefore subject to number-formatting localization. Since machine control always runs in English regardless of the system setting, but the evaluator runs in whatever language is selected, decimal values cannot be parsed on the other side for languages that are incompatible with English formatting (e.g. period vs comma separator). Set Windows language/region settings to US English.
ASD Low Volume Reagent Pipetting Passed With Failing Results. Pass/Fail is overwritten each time with the result of EvaluateCriteria. If the last processed data (20μL) is Pass, it will appear to be Pass even if 10μL is Fail. No countermeasure.
SampleIntakeErrorHandler does not Unlock Sample Wheel. SampleIntakeErrorHandler does not unlock Sample Wheel if it was locked as a part of failed aliquot process. Reinitialize instrument.

Tests not aliquoted from sample vessels on Sample Wheel. Instrument not restarting after Lumi Drift Check (Red System Event) Re-Initialization.

There may be a delay to return the system into a running state if the ASD Luminometer Drift Check is completed sooner than expected. Wait 15 minutes after ASD completion.
SPU presentation action timeout after SPU load button was used. If the user attempts to load a rack while another rack in the presentation area, there is a short time window in which if the SPU door closes, a timeout error can occur. "The sample handler is jammed" system event is displayed and user is not able to load additional racks until the instrument is reinitialized. Do not close the cover when the rack is operating.
Single dark count read out of range during initialization should fail. If the instrument's luminometer reads a dark count value of greater than 300, the instrument should throw an error and prevent the user from running. The luminometer is compromised and needs to be cleaned before use.

Clean the luminometer, refer to Cleaning the Luminometer.

Slot occupied condition due to incorrect sample vessel cancelation during error handling. After some Incubate Pick and Place failures, a sample vessel may fail to be cleaned out from the reaction build carriage, resulting in "slot occupied" error. The instrument will need to be reinitialized in order for the sample vessel to be cleared.

Reinitialize instrument.

Weekly cleaning routine reports confusing software error message.

If there is a system error during the weekly clean routine (e.g. pipettor detects a leak) the system will report an ambiguous error message about a "Boolean Disposing Error" instead of the actual failure, making the issue difficult to troubleshoot for service. No countermeasure.

Add-on order accepted even though sample was already expired and offboard.

Add-on order accepted even though sample was already expired and offboard. The order cannot be processed and stuck in embedded memory until process restarts. This is shown in the service view, but not visible to the customer. No countermeasure.

TnI 186 version not updating calibration volumes when multiple lots are loaded or unloaded from system.

For TnI test, the calibration edit order view may not show the calibrator volume in the load guide if multiple reagent lots are available. Customers should refer to the assay IFU.

Customer should manually calculate the required volume(s) based on the reagent and calibrator IFU and add the dead volume based on the container type.

Consolidate passengers when gripper does not detect a tray.

After removing a pack of trays from stocker, the system does not consolidate the removal and counting of passengers is corrupted.

Reinitialize instrument and restart PC.

The tray exerciser processing is not aligned with tip supply controller state.

If an error occurs in the tray exerciser, the function is terminated without processing the rest of the tip supply handling controller state, resulting in an error that prevents it from starting the next time the exerciser is executed.

Refer to Troubleshooting DispoTip Stocker. Restart PC.
