Software 1.15 Known Bugs and Behaviors

A list of known bugs or behaviors for system software versions 1.15, and countermeasures for recovery.

  • Bug/Behavior: Summary of the software bug or system behavior.
  • Details: Explanation of the bug/behavior and how it may impact the system/user.
  • Countermeasure: If applicable, countermeasure to resolve the condition inflicted by the bug/behavior.
Bug/Behavior Details Countermeasure
SPU Camera Calibration May Fail When Using Plastic Tubes If plastic tubes are used for the SPU Camera Calibration when it calls for 13 x 100 tubes, the camera may be unable to properly detect them/calibrate. Utilize glass 13 x 100 tubes to perform the calibration. These tubes are now available to order and also included in the install kit.
Certain Regional Languages May Cause Issues with the Interface:
  • Calibrator card could not be scanned and the calibrator setup screen would exit if the user interface language was changed to non-English.
  • The set QC mean values appear to be multiplied by values of 10 (10x, 100x, 1000x, etc) leading to QC failures.
Further details regarding regional language issues and instructions on how to resolve are included in Technical Bulletin SB_IA2023143. Perform the settings changes identified in Technical Bulletin SB_IA2023143. A long-term solution will be available in future SW versions.
Camera Calibration for Sample Tubes May Fail if Using Plastic Tubes During investigations of failing camera calibrations, it was observed that some plastic sample tubes may lead to calibration failures. Glass sample tubes will provide successful calibrations until the root cause can be resolved in future software versions. As a temporary countermeasure, a kit for glass sample tubes (qty. 1 per kit - order in multiples as needed) has been created for ordering under part number D01860.
System Cannot Initialize Due To Logical Error in Event Reporting In rare instances the system may get stuck in an infinite loop, failing to report stalled event. The system will not initialize even after a full reboot. Perform the following steps to clear the condition:
Caution: It is recommended to perform these steps with assistance from technical support to ensure the database is not corrupted.
  1. Shut down Machine Control and DxI 9000 applications.
  2. Navigate to D:\ProgramData\Beckman Coulter\Falcon.
  3. Delete all files that end in .data
  4. Restart the system. The system will fail auto-initialization upon first start-up.
  5. Initialize the system with all options selected (Force, Consolidation, Cleanout, and Remap).
Low Volume Reagent Pipettor Failure Wording Incorrect For cases where there is a low volume reagent pipettor failure and the median result is below the lower limit, the message reported in the diagnostic test message section is incorrect. The message should read as "Median is below the lower limit" but currently reads as "Median is over the lower limit". None - test pass/fail status is still correct, but wording is incorrect and will be fixed in future SW version.
Tests that share a reagent pack with other tests may not run when sufficient reagent is onboard the analyzer Packs that are shared by multiple tests that use different volumes have the potential to be affected, which is mostly impacting service assays using the ASD pack. System will not start tests even though reagent may appear to be sufficient. The user must unload the nearly-empty pack. Unload near-empty packs and load fresh packs to resume testing.
Passenger Consolidation Fails For RSM During Initialization After Software Upgrade After software upgrade, instrument failed to initialize during passenger reconciliation stage. Ensure all packs are unloaded prior to upgrading software (per Mod procedure).
Discard Of Non-Empty Tip Tray Causes System To Pause On system serial numbers 300001 - 300051, when the instrument discards a tip tray that still has tips within it, it can cause the system to enter a paused state. The instrument will report that there are no tips available and will be unable to schedule tests. Manually access the tip stocker and remove the trays and re-start the instrument.
System Does Not Start New Patient Test After Successfully Re-calibrating after Failed Calibration If an attempt to calibrate a reagent lot fails, and then a second calibration succeeds, patient tests on that reagent will not start. Unload and reload packs for that reagent lot in order to clear the condition and make the system resume scheduling tests for that reagent.
"Unable to Store Alignment Data" Error Display System displays an error indicating that the analyzer cannot process samples and was unable to store configuration or alignment data, but the system indicates that it is ready to run. This occurs Close and re-open the alignment page, this should clear the condition.
High RLU's Reported as Negative In some instances (typically during System Carryover ASD) a high RLU will be reported as negative. Repeat the test until it passes (RLU values non-negative).
Rack/Sample Container May Not Be Released Following Disposable Tip Errors In some instances if the sample pipettor fails to successfully pick up a tip, the system will not recover. A "Force Reinitialization" from the Diagnostics page is required to recover.
Initial Test Menu Update Can Silently Fail On a new system, loading RAPID files may fail without notice. This occurs due to a lack of the RAPID folder being present in D:\Program Data\Beckman Coulter\Falcon filepath. Create a folder named RAPID in the directory D:\Program Data\Beckman Coulter\Falcon and paste the RAPID file from the USB into it.
Result Interpretation For Qualitative Tests Is Not Provided On The Test Results Page Result interpretation is not displayed in the Patient Test Result page, but is displayed in the Sample Details screen. Review the Sample Details screen for qualitative results.
Unable to Calibrate Onboard Reagent Lots / Calibration Ordered for Reagent Lots No Longer Onboard Two items have been identified regarding calibration of specific reagent lots:
  • Inaccurate reagent lot availability with automatic calibration orders: Onboard reagent lots not recognized.
  • Inaccurate reagent lot availability with automatic calibration orders: Calibration ordered for reagent lots that are no longer onboard.
Further details are called out in the Release Notes for Version 1.14.1.
  • Manually calibrate the reagent lot, load a pack from another lot not already onboard and manually calibrate both, or load a new lot and unload the lot onboard when the error occurred and manually calibrate the new lot.
  • Load a pack of this lot if available, calibrate the test, or contact support for additional assistance if the issue persists.
Wash Buffer Displays as "In Use" Despite Stating Container is Empty In some cases, the wash buffer container may state "Empty" but remains "In Use". The system will continue to sue the "In Use" container until it detects bubbles in the line as the system does not observe the physical volume present in the container. No countermeasure - continue running until the containers switch.
Sample Search Result Does Not Show New Sample When Sample ID Reuse Is Set to Immediate When the Sample ID Reuse setting is set to "immediate" (value of -1), the software is unable to show the newly created sample in the sample search results. Sample ID reuse is off by default. No action needed, informational only. See Enabling the Reuse of Sample IDs for details on configuring Sample ID re-use.
Poor UI Performance When Ordering Large Numbers of Samples in Batch Order Entry When a user tries to place a batch order from the batch order entry screen by entering the number of samples and then the starting sample ID, the performance of the application is slow. Enter the starting sample ID first and then the number of samples.
An Error Message Is Not Shown When the User Loads an Existing Sample for Editing in Manual Test Order Entry and Changes the Sample ID An appropriate error message is not shown when the user loads an existing sample for editing in manual test order entry screen, and changes the sample ID. Avoid changing Sample ID in the test order entry screen - delete and create a new sample if the ID needs to be changed.
Tests Stuck In Progress when Instrument Reports Results after Result Timeout Triggered The system will 'time out' results if a completed result is not received from the system after a pre-configured unit of time. In rare cases where a test result takes more than three hours to complete, this timeout is triggered prematurely and the affected test result(s) will be stuck in an in-progress state. Users will need to reorder affected tests and re-present the sample.
High Number of Results Ordered on a Single Sample Causes System to Stop Processing When there are a large number (hundreds) of test replicates ordered on a single sample, the system software will struggle to process other requests as that sample is processing, which can cause the system to stop functioning or report unrelated errors. Avoid ordering more than 80 samples on a single sample container.
"WaitForInputIdle failed" Pop-Up Was Shown When Loading The On-Screen Keyboard If the On-Screen Keyboard is delayed when launched, an error message displaying "WaitForInputIdle failed" will pop up due to the application setting focus on the model dialog. Select "OK" and continue using the system.
Reflex Information List Is Null For HIV Combo Test For Combo tests, the reflex information is not set. So the instrument will be not be able to account for the reserve volume needed for reflex order that may be created because of a rule. Re-load the sample so the system can run the reflex test.
