Troubleshooting Issues Using Log Files

This topic includes information about how to troubleshoot issues using log files.

Troubleshooting Issues Using Log Files
Step 1: Sign in to Use the BeckmanAdmin Account
Step 2: Review System Events
Step 3: Obtain the Relevant Log File
Step 4: Find the Event in the Log File
(UTC) Coordinated Universal Time

Step 1: Sign in to Use the BeckmanAdmin Account

Be sure the instrument is not processing tests, and sign in to use the BeckmanAdmin account. See Signing In to Use the BeckmanAdmin Account for more information.

Step 2: Review System Events

Use the Console App to review system event indicators on the System Events page.

In the Console App, the SYSTEM event indicator will indicate the number of system events that require attention.

  1. Select the SYSTEM event indicator to open the System Events page. The page lists system events, and the list is continuously updated.

    Colors indicate the types of events that have occurred. Red and yellow indicate the analyzer needs attention now.
    • RED indicates an event that has stopped the analyzer from processing tests.
    • YELLOW indicates an event that has stopped the analyzer from processing at least one test, but the analyzer can continue to process other tests.
  2. Select an event indicator to open the event page.

    The event page indicates the system event code and lists the active events for that code. The list provides a description of the event and when the event occurred. For more information about event codes, see Troubleshooting SYS Flags.

    Note: If you do not see the system event with the time stamp, use the IntelliServe dashboard to find the time stamp of the event you are investigating.

Step 3: Obtain the Relevant Log File

Use the system event code to find the relevant log files. See Gathering the Right Information Before You Ask for Help for more information about log files and their locations.

Note: You may have to obtain the full day of log files, which will be contained in a .zip file named for the day when it was created.
Note: The system saves log files using (UTC) Coordinated Universal Time. See (UTC) Coordinated Universal Time for more information about converting UTC to local time.
Tip: Due to the complexity of the DxI 9000 system, a system event might indicate a symptom, but not the root cause. You may need to examine multiple log files to find the root cause.

Step 4: Find the Event in the Log File

  1. Open the log file in Notepad. The log file will contain multiple log entries.

    Log Entry (Example)
    2020-04-08 16:01:00.764|5|Info||Trace|StepperMotor.cs|MoveRelativeAsync|600|AliquotSamplePipettor.ZAxis.Motor|DeviceActionStart(MoveRelativeAsync):Data(-711,8):Phase(Passenger transfer phase):Cycle(20234):TimeInCycle(1263):Status(Ok)|2020-04-08 16:01:00.764830
    Table 8: Log Entry Details (with Example)
    Example Type Details
    2020-04-08 16:01:00.764 Date and Time The initial date and time stamp in the log entry is the date and time the log entry was added to the file.
    Info Severity Severity indicators include Info, Warning, Error, and Critical
    MoveRelativeAsync Command The command the instrument was attempting to execute.
    Data(-711,8) Data The motor was moved from position -711 to position 8.
    Phase(Passenger transfer phase) Phase The phase in the process when the event occurred.
    TimeInCycle (1263) Time in Cycle This happen at 1263 milliseconds during 8 seconds Instrument Cycle
    2020-04-08 16:01:00.764830 Date and Time The final date and time stamp in the log entry is the date and time the event occurred.

    Note: All processes have a start command and an end command, and commands are nested using the following hierarchy:
    • Subsystem
    • Assembly
    • Subassembly
    • Device

    For example:

    Subsystem AliquotSamplePipettor|SubsystemActionStart (RendezvousAndLockPosition):Data(0,TipSupply,82):Phase(Passenger transfer phase)
    Assembly AliquotSamplePipettor.Assembly|AssemblyActionStart ( PreMoveMotor ):Data( AliquotSamplePipettor.ZAxis,Give_Tip,ZAxisDown ):Phase(Passenger transfer phase)
    Device AliquotSamplePipettor.ZAxis.Motor|DeviceActionStart ( GetCurrentPosition ):Data():Phase(Sample Aliquot Action phase)
    Device AliquotSamplePipettor.ZAxis.Motor|DeviceActionEnd ( GetCurrentPosition ):Data(-428):Phase(Sample Aliquot Action phase)
    Device AliquotSamplePipettor.ZAxis.Encoder|DeviceActionStart ( GetRawPosition ):Data():Phase(Passenger transfer phase)
    Device AliquotSamplePipettor.ZAxis.Encoder|DeviceActionEnd ( GetRawPosition ):Data(31):Phase(Passenger transfer phase):Cycle(20234)
    Assembly AliquotSamplePipettor.Assembly|AssemblyActionEnd ( PreMoveMotor ):Data( AliquotSamplePipettor.ZAxis,Give_Tip,ZAxisDown ):Phase(Passenger transfer phase)
    Subsystem AliquotSamplePipettor|SubsystemActionEnd (RendezvousAndLockPosition):Data(0,TipSupply,82):Phase(Passenger transfer phase)

  2. Search the text of the log file for the relevant log entry.
  3. To find the root cause, review previous entries in the log file until you no longer see messages about error handling.

(Prev) and (Next) defined:
  • (Prev) indicates the previous day. For example, if it's 00:00 UTC and the corresponding time in PST is 16:00 (Prev), it means 16:00 on the previous day.
  • (Next) indicates the next day. For example, if it's 18:00 UTC and the corresponding time in AEDT is 05:00 (Next), it means 05:00 on the following day.
