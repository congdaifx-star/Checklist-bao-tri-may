Software 1.13 Known Bugs and Behaviors

A list of known bugs or behaviors for system software versions 1.13, and countermeasures for recovery.

  • Bug/Behavior: Summary of the software bug or system behavior.
  • Details: Explanation of the bug/behavior and how it may impact the system/user.
  • Countermeasure: If applicable, countermeasure to resolve the condition inflicted by the bug/behavior.
Bug/Behavior Details Countermeasure
Customer-Initiated Emergency Stop Recovery Requires Software Restart After a user-initiated emergency stop command from the user interface, the system cannot be returned to an operational state simply by re-initializing the system. Re-start the system PC to recover.
Expected Vessel Missing Before Move Makes Passenger Consolidation Fail Initialization fails if the system expects to find a vessel which is no longer physically present. This is only expected to occur if a user has physically removed vessels, or as a secondary failure mode after a mechanical error. Re-start the system PC to recover.
Performing Monthly Maintenance Causes System Error When Following Instructions With Interlocks Enabled After opening the analyzer cover and triggering the interlocks during routine maintenance, the analyzer returns "SmcSeekFail" errors that can only be resolved by rebooting the PC. Re-start the system PC to recover.
Diagnostic Backup/Restore Process Does Not Preserve the Luminometer Drift Data The diagnostic backup/restore process does not preserve the luminometer drift data. The luminometer must be reset after the database is restored. This typically only occurs at software updates and is built in to the software Mod procedure. Backup and restore Luminometer Drift data per latest software Mod procedure.
Reagent Storage Module Alignment: Incorrect Rotational Correction Incorrectly applied rotational alignment correction creates difficulties aligning the reagent storage module. Individual nest offsets are aligned during instrument manufacturing and can be updated in the field as needed. Adjust alignments of the individual reagent storage nests as needed.
Calibrations Fail When Running Wash Wheel Camera Dispense and Residual Calibration Together Unable to run residual volume and substrate dispense wash wheel camera calibrations together (both boxes checked). Perform camera calibrations independently (one at a time) to prevent failures or loss of time.
System Skips Aliquot With Unknown Tests The system won't aliquot samples that include an unknown test. The system should aliquot the known tests and skip the unknown tests. This applies only to test orders received via LIS. Check system test configurations (enabled/disabled) to ensure they match what is being requested by the LIS.
Tests Not Run as Pick-And-Place Is Reserved After Hard Stop Followed With Initialization Following a failed sample Pick-and-Place discard operation and subsequent hard stop, a successful system initialization does not clear reservations from the failed discard operation and leaves the sample Pick-And-Place in an indefinitely reserved state. Machine control must be restarted. Re-start the system PC to recover.
QC Does Not Complete Do to Result Processing Error If the final result processing step fails, affected QC results are stuck In-Progress. The rack used for QC can't be used for other tests. Perform ServiceApp Script to complete in-progress QC's.
The Period Between Idle Substrate Prime Operations Is Too Long The period between idle substrate prime operations is 24 minutes and 40 seconds, which exceeds the 24 minute time limit, which could cause up to 3 tests to be cancelled and flagged "STO". Repeat any tests which are cancelled.
SPU Camera Calibration Does Not Complete if Unable to Read Barcode on Rack In the event of a camera mechanical issue with the issue with the rack barcode itself, the SPU camera calibration fails with no indication of why the operation was unable to complete. If camera calibration fails with no root cause, inspect the camera lens for debris/obstruction, as well as the rack barcode label. Clean or replace as needed.
Cancelling ASD While Utilities Are in Progress Results in System Error While a probe wash utility is running on the system, cancelling ASD results in a system error rather than transitioning to a paused state. Re-initialize the system and repeat any tests as needed.
Tray Gripper Tries to Throw Away a Non-Existent Tray Causing System to Stop Processing During initialization, the system checks for a tray at the tray supply. When the system reaches a "Running" (green) state, it tries to throw away a tray that is not there, causing the system to stop processing tests. Re-initialize the system.
Dedicated Rack (None Sample ID) QC Results are Not Exported to CSV output (Results to Disk) If the QC order was not registered associating a sample ID, the results to disk routine won't output any result that does not have the sample ID. This scenario should be able to output does not have the sample ID data also. QC results should be manually recorded if the user chooses to utilize a dedicated rack with no Sample ID for QC.
Software Exception Prevents Service Diagnostic from Completing Service diagnostics which use ASD packs may fail to complete due to a software design error. Repeat any automated ASD tests if they fail.
Maintenance Due Notification is Removed Prematurely if Weekly Clean Routine Fails If there is an error starting the weekly clean routine task, the 'due now' notification for the task will be removed instead of remaining visible until the routine completes successfully. Repeat weekly clean if it fails.
ASD Packs/Sample Diluent A Consumable Tiles Incorrectly Displayed on Consumables Page There are three scenarios that are causing the ASD Packs and Sample Diluent A consumable tiles to display incorrectly on the UI for the Consumables page.
  • Sample Diluent A is showing multiple tiles instead of just one tile.
  • Sample Diluent A/ASD Packs should be empty if unloaded.
  • Sample Diluent A/ASD Packs availability does not refresh to empty in the consumable page when deleted.
This has no impact to system performance and should be ignored, as it will be resolved in a future software version.
Exception on Navigating to Curve Details from Completed QC and Patient Records for Assays with Shared Curves For FOLW & RBCW, there is an exception on navigating to the Calibration Curve Details page from a completed QC or Patient Result Details page. This error message may be dismissed with no further issue. Dismiss the error message and view calibration details from the calibration screen rather than through QC/patient result screen.
UTC Date/Time Not Consistently Used Software is not always using the UTC Date/Time for comparisons to check if a calibration is expired. It can be off by the difference between local time and Universal Time, which could be several hours. This affects the order completion time stamp but does not impact the performance of the instrument. No action needed, this does not impact system performance.
Duplicate Entries of Substrate Bottle in Materials Screen Materials page contains duplicate entries for substrate when substrate is Due Soon or Due Now. This only happens during initial installation in manufacturing or field installation. Loading new substrate bottles should clear this condition, so it may be ignored until substrate is replaced.
Console Application (DxI 9000) is Unable to Start In the event that the system is unable to interpret the configuration data on startup, the user interface application will fail to start. This will likely only occur during software update if there are issues. Review software update instructions (service Mod) and ensure system configuration is set/restored appropriately.
Report Is Not Printing to Network Printer in Windows 10 Reports are not printing when using a network printer in the Windows 10 OS environment. The report can still be saved to be printed from elsewhere or a local printer may be connected to the system. Network printer configurations are not yet supported by the system. Users should print to PDF and transfer to external PC for printing.
Poor UI Performance When Ordering Large Numbers of Samples in Batch Order Entry When a user tries to place a batch order from the batch order entry screen by entering the number of samples and then the starting sample ID, the performance of the application is slow. Reduce number of sample ordered through batch entry when possible.
An Error Message Is Not Shown When the User Loads an Existing Sample for Editing in Manual Test Order Entry and Changes the Sample ID When the user loads an existing sample for editing in the manual test order entry screen and changes the sample ID, an error message is not shown when the sample is not accepted. Avoid changing Sample ID of already entered samples.
No Information Displayed After User Attempts to Filter Test List After APF Update After importing the APF files using the import feature from the test configuration page, test information is not displayed when using search filtering test. Close and re-open the test config screen to refresh the search test filter.
Completed Orders Are Getting Updated After Modifying the QC Control Materials After a QC run is completed, updating the control material status from "In Use" to "Not Used" causes previously completed sample statuses to update from Pass/Fail to Unknown on the Sample List screen. QC results may be managed external to the system, or if possible, avoid modifying QC material.
System Reports Failed QC to IntelliServe When the Instrument Says It Passed When transmitting the QC telemetry data to IntelliServe, QC results are transmitted as failed when the instrument says it passed. There is no impact on users and results as IntelliServe is only used for remote diagnostics for Beckman Coulter service and support teams.
Tests Stuck In Progress when Instrument Reports Results after Result Timeout Triggered The system will 'time out' results if a completed result is not received from the system after a pre-configured unit of time. In rare cases where a test result takes more than three hours to complete, this timeout is triggered prematurely and the affected test result(s) will be stuck in an in-progress state. Re-order affected samples and repeat the tests.
