Software 1.14 Known Bugs and Behaviors

A list of known bugs or behaviors for system software versions 1.14, and countermeasures for recovery.

  • Bug/Behavior: Summary of the software bug or system behavior.
  • Details: Explanation of the bug/behavior and how it may impact the system/user.
  • Countermeasure: If applicable, countermeasure to resolve the condition inflicted by the bug/behavior.
Bug/Behavior Details Countermeasure
Exception on Navigating to Curve Details from Completed QC and Patient Records for Assays with Shared Curves For FOLW & RBCW, there is an exception on navigating to the Calibration Curve Details page from a completed QC or Patient Result Details page. This error message may be dismissed with no further issue.
Inaccurate reagent lot availability with automatic calibration orders System inaccurately displays that there are no "Active" reagent lots on board despite packs physically being present. At this time the resolution si to load a different lot of reagent. A countermeasure to resolve with service intervention is being investigated and will be released as soon as available.
Tests that share a reagent pack with other tests may not run when sufficient reagent is onboard the analyzer Tests that utilize the same reagent packs but may consume different volumes (this is most commonly found in ASD/service diagnostic tests) may display sufficient reagent but not allow tests to start. Un-load the partially used reagent pack and repeat the testing.
SPU Camera Calibration Does Not Complete if Unable to Read Barcode on Rack without Message In the event of a camera mechanical issue with the rack barcode itself, the field service engineer is unable to complete the SPU camera calibration with no indication of why the operation was unable to complete. A message will post in the Sample Events menu, but not the System Events. Check the Sample Events menu and review any events posted here. Inspect the rack/try a different rack and repeat the calibration.
Initial Test Menu Update Can Silently Fail On a new system, loading RAPID files may fail without notice. This occurs due to a lack of the RAPID folder being present in D:\Program Data\Beckman Coulter\Falcon filepath. Create a folder named RAPID in the directory D:\Program Data\Beckman Coulter\Falcon and paste the RAPID file from the USB into it.
Cancelling ASD While Utilities Are in Progress Results in System Error Cancelling an ASD routine and attempting to re-start before it has fully recovered will result in error. Re-initialize the instrument and re-start the ASD routine.
Tray Gripper Tries to Throw Away a Non-Existent Tray Causing System to Stop Processing The system expects to see an empty tip tray after completing initialization, but when the tray is not found the system enters an error state. Avoid removing empty trays by hand as this will cause an error with the tip stocker. If the errors are observed, reinitialize/reboot.
Maintenance Due Notification is Removed Prematurely if Weekly Clean Routine Fails If there is an error that prevents the clean routine from running the "due now" notification will clear despite not successfully completing the clean routine. Open the maintenance log and request the routine to run it again.
Errors during the Clean Routine may strand the sample rack inside the analyzer If an error occurs during the clean routine, the clean rack may not be ejected from the SPU presentation and will appear "stuck". For customer resolution, have the user power off the system, open the covers, and manually retrieve the rack. Service may also consider using alignment commands to home the SPU and retrieve the rack.
Substrate lot expiration may lock the substrate door and prevent bottle replacement The user is unable to load substrate bottles when the system starts with two invalid bottles. The workaround is for a service user or customer (with remote assistance from Beckman support) to use the alignments access to open the door and then force an initialization.
Reagent Pipettor Auto-alignment Procedure Throws Exception at some Alignment Values The RP auto-alignment procedure throws the exception and terminates the procedure without notifying the user at certain alignment values. Attempt repeating the alignment. Consider inspecting/adjusting the home sensor. Alignment can be accomplished manually as a workaround.
Reflex tests may not complete when additional tests are added to a sample that has already started processing In the event that the system rejects an add-on test for a sample due to insufficient reserve volume, any subsequent reflex tests triggered on that same sample will not run to completion. Re-load the sample and manually request the tests which would be ordered by the reflex condition.
System Cannot Initialize Due To Logical Error in Event Reporting In rare instances the system may get stuck in an infinite loop, failing to report stalled event. The system will not initialize even after a full reboot. Perform the following steps to clear the condition:
Caution: It is recommended to perform these steps with assistance from technical support to ensure the database is not corrupted.
  1. Shut down Machine Control and DxI 9000 applications.
  2. Navigate to D:\ProgramData\Beckman Coulter\Falcon.
  3. Delete all files that end in .data
  4. Restart the system. The system will fail auto-initialization upon first start-up.
  5. Initialize the system with all options selected (Force, Consolidation, Cleanout, and Remap).
Low Volume Reagent Pipettor (ASD) Failure Wording Incorrect When the median result is below the lower limit, the message that is reported in the diagnostic test message is "Median is over the lower limit". It should say "Median is below the lower limit". No action needed, informational only.
Sample Container May Not Be Released to Automation after Errors with Tips If the system connected to an automation line fails to pick up a tip and does not recover, the sample tube at the aspiration point will not be released to the automation track, potentially causing a queue of samples awaiting aspiration. Re-initializing the system will clear the error and release the "stuck" sample tube.
Service Log In Locks Console If PHI Is Open When Logging In If any tabs with PHI (i.e. patient results) are open when logging in to Service Login, the system will "lock" with error message(s). DxI 9000 Console Application must be force closed via Windows Task Manager and re-launched (or system rebooted) to clear the condition. Suggest users close any tabs containing potential PHI prior to attempting Service Login.
High Number of Results Ordered on a Single Sample Causes System to Stop Processing This typically occurs on low-volume service assay (i.e. AP5) when requesting a large amount of replicates on the same sample tube (i.e. 400) in an attempt to "stress test" the system for troubleshooting. Avoid ordering severely high quantities of replicates on a single sample container (suggestion: do not exceed 150 replicates per container). If intending to "stress test" the system, see the Stress Testing the System procedure.
Tests Stuck In Progress when Instrument Reports Results after Result Timeout Triggered The system will 'time out' results if a completed result is not received from the system after a pre-configured unit of time. In rare cases where a test result takes more than three hours to complete, this timeout is triggered prematurely and the affected test result(s) will be stuck in an in-progress state. Users will need to reorder affected tests and re-present the sample.
Report Destination Text Box in Detailed Report Settings Screen Only Works when Clicked on By Mouse In the Detailed Report Settings screen, the user cannot select the "Report Destination" field by using the touch screen. Utilize the "virtual mouse" built in to Windows or a physical mouse if connected via USB.
Report Is Not Printing to Network Printer in Windows 10 Reports are not printing when using a network printer in the Windows 10 OS environment. Network printers have not yet been validated for use with the system. Suggest printing to PDF and exporting via external storage device for printing from another PC.
Sample Search Result Does Not Show New Sample When Sample ID Reuse Is Set to Immediate When the Sample ID Reuse setting is set to "immediate" (value of -1), the software is unable to show the newly created sample in the sample search results. Sample ID reuse is off by default. No action needed, informational only. See Enabling the Reuse of Sample IDs for details on configuring Sample ID re-use.
Poor UI Performance When Ordering Large Numbers of Samples in Batch Order Entry When user tries to place a batch order from the batch order entry screen by entering the number of samples and then the starting sample ID, the performance of the application is slow. As a workaround, suggest the user can enter the starting sample ID first and then the number of samples.
An Error Message Is Not Shown When the User Loads an Existing Sample for Editing in Manual Test Order Entry and Changes the Sample ID An appropriate error message is not shown when the user loads an existing sample for editing in manual test order entry screen, and changes the sample ID. Load the sample using the same rack number and position, and/or suggest user avoid using duplicate RackID for multiple requests.
"WaitForInputIdle failed" Pop-Up Was Shown When Loading The On-Screen Keyboard In rare instances "WaitForInputIdle" error may show on screen when the system is trying to load the on-screen-keyboard. User can select "OK" to the error and resume normal operation.
Unable to Calibrate Onboard Reagent Lots / Calibration Ordered for Reagent Lots No Longer Onboard Two items have been identified regarding calibration of specific reagent lots:
  • Inaccurate reagent lot availability with automatic calibration orders: Onboard reagent lots not recognized.
  • Inaccurate reagent lot availability with automatic calibration orders: Calibration ordered for reagent lots that are no longer onboard.
Further details are called out in the Release Notes for Version 1.14.1.
  • Manually calibrate the reagent lot, load a pack from another lot not already onboard and manually calibrate both, or load a new lot and unload the lot onboard when the error occurred and manually calibrate the new lot.
  • Load a pack of this lot if available, calibrate the test, or contact support for additional assistance if the issue persists.
