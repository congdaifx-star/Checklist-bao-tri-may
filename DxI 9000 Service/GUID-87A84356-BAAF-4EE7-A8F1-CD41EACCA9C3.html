Software 1.24 Known Bugs and Behaviors

A list of known bugs or behaviors and countermeasures for recovery for system software version 1.24.

  • Bug/Behavior: Summary of the software bug or system behavior.
  • Details: Explanation of the bug/behavior and how it may impact the system/user.
  • Countermeasure: If applicable, countermeasure to resolve the condition inflicted by the bug/behavior.
Bug/Behavior Details Countermeasure
When Logged In as LabUser, Some Overlays in Machine Control May Be Improperly Displayed with Red Text The Machine Control application contains a view of installed overlays, and is supposed to show unreleased overlays in a red color to warn service if the system is out of configuration. When logged into the LabUser account, some valid overlays will be erroneously shown in red. They are displayed correctly in the Administrator Account. Machine Control application is hidden by default unless enabled by a service engineer. No impact. No countermeasure.
An incorrect reagent serial number may be associated with calibration orders When you order a calibration from the reagent details screen and review it on the calibration order details view it appears that it will run on the specific pack. In fact, the system will only honor the lot, not the serial number. They system may run the curve on any available pack of that lot. No impact. No countermeasure.
Error Handling Events Do Not Match Instrument Status Red system events from some errors state that "The analyzer cannot process samples.", but for error handling conditions where the recovery is successful, the instrument returns to a running state and will accept new samples, but the red system event isn't dismissed. No impact. No countermeasure.
Semi-Quantitative and Quantitative QC mean calculation is incorrect when units are changed The QC statistics values will not be calculated correctly if the data points use different units. The summary statistics on the control cannot be used if it contains values of mixed units. The user must create a new control if they want to change the unit.
Default Save Directory Errors When Exporting Data Files When there are errors trying to export data for offline review to the pre-configured export destination the messages reported to the user are unhelpful in resolving the issue. No impact. No countermeasure.
LIS code and Test Code Mismatch Causes Test to not Show on Enhanced Test Order Screen If LIS code is configured to be different from default test code, Enhanced Test Order screen will not display the test. No impact. This screen is for internal users only. Customers are not directed to use this screen.
User Unable to Save Changes to On-board QC Orders Intermittently Sometimes when trying to manually order QC or cancel QC the user is unable to save the changes and is shown an error dialog that says "An unexpected error occurred." The user must attempt to save the order multiple times or modify the order in multiple smaller steps for the update to be saved successfully. This occurs mostly on high volume systems that run a lot of controls across their workday. No countermeasure. The order can still eventually be saved.
Results Stuck in Transmitting State if LIS Configuration is Changed or Software is Restarted While they are Waiting to Send Some results in the "Transmitting" state may not get transmitted if the LIS Configuration is changed or the software is restarted. When this happens, then only 10-20 samples are transmitted when the LIS connection is re-established. The rest stay in the "Transmitting" state. There are only two types of results transmission scenarios where this is occurring: * The results were reruns * The results were requested for re-transmission by clicking the "Resend to LIS" button on the result review page This scenario would likely only occur if the LIS connection is being setup for the first time or the lab is experiencing LIS connectivity issues that requires a configuration change or a software restart. To recover and have the remaining transmitted, either the LIS Configuration can be changed again or the console software can be restarted again and the next approximately 10 samples will be sent. Repeat this process until all samples are sent.
Calibration Auto Order Placed for MeMed Child Assays with Active Curve from Edit Order Screen When reagent lots are loaded for all MeMed child assays and calibrated with an active curve, then new reagent lot is loaded only for one of the tests, e.g. the CRP child assay, an auto order is placed for the newly loaded lot. However, after navigating back to the Edit Order screen, snoozing the order, and then unsnoozing it, calibration orders are placed for the other two child assays, Trail and IP10, which already have active curves, along with the newly loaded CRP reagent lot. This only applies to the MeMed assay due to it's unique design. The system could over-use calibrator and reagents since technically only one of the calibrations due and this will re-calibrate all constituents. No countermeasure.
Calibration Time Until Due Incorrectly Displayed as N/A When an assay has a valid calibration and a new calibration is run, the Calibration Time Until Due is Incorrectly Displayed as "N/A" instead of the "Days" or "Hours" left on the valid calibration. This occurs on the Calibration Impact tiles on the user interface in the Calibration Due Now -> All Calibrations Page. The remaining calibration time for the valid calibration is not shown while the new calibration is in progress. Users can see the actual calibration curve expiration date by selecting the "Details" view from the "All Calibrations" page.
Hourly cyclic interval of QC not work after you changing from 24 to 8 and change back to 24 again before expected due time Hourly cyclic interval of QC does not auto order at daily start time, after user changing from 24 to 8 and change back to 24 again before expected due time. In an unlikely scenario where the user changes the QC auto due frequency multiple times before the daily start time, the QC becomes auto due at incorrect time (there is no issue in the frequency only issue with the due time). No impact. No countermeasure.
Lumi LED Voltage Search for RLU Targets (Stitching RLUs) Failed but No Message to Retry LED Voltage Search and Reschedule LumiDrift An unexpected failure mode was found on an internal instrument and prevented the Luminometer drift check diagnostic from completing. Due to the unexpected failure, the performance of the instrument was not verified. However, the failure was not correctly handled and the instrument continued to run samples without fully notifying the user of the problem. The instrument ran samples with a luminometer calibration that was not verified to be within the expected performance range. No countermeasure.
RSU package download hangs due to intermittent connection When the RSU package is sent from IntelliServe, it may not arrive at the system and the download hangs. No impact. No countermeasure. Currently installations are only performed by field service.
New test can begin while Software Installation is going via RSU If a sample starts processing in the very small window after the installer checks, but before the installer shuts down the applications, a test could start. No impact. No countermeasure. Currently installations are only performed by field service and they will not begin until tests are completed.
Substrate Unload Workflow Error when Unloading Both Bottles An unexpected error was reported to the user when attempting to unload both bottles of substrate without a replacement. The user was able to restore instrument operation with basic troubleshooting and loading new bottles of substrate. User can recover by either restarting software or pausing and unpausing system.
System Initialize Race Condition Leaves Instrument in Paused Mode - Trouble Shooting Wizard(s) There is a small opportunity for the system to become stuck in a paused state while a troubleshooting wizard workflow is in progress. The user should avoid pushing the buttons in rapid succession if possible. If this occurs, the user will need to restart the system.
Patient Sample Loaded and not Processed for Non-Barcoded Samples In rare cases, the test order for a non-barcoded tube may not be processed when loaded even though there is a pending manual order. No sample will be aspirated and the order will remain pending. User will be confused why the sample was not processed. The user can cancel the test, reorder and re-present the sample.
Tests Can Become Stuck in Progress if LIS Sends Test Orders Using Multiple "O" Order Records If the LIS sends a host-query response for a sample that contains multiple order records, a software deadlock can occur that results in the sample remaining stuck in progress. The tests will eventually be cancelled after the 5-hour limit expires. This does not affect Remisol-connected systems, as Remisol always communicates multiple test requests within a single order record. As a workaround, if possible the customer LIS should be configured to send multiple orders within a single order record. Samples can be stuck in progress for up to 5 hours and flagged NRT. As a countermeasure, if possible the customer LIS should be configured to send multiple orders within a single order record.
Calibration Orders Screen Showing Orders for Inactive Calibration Lots When a new calibration lot is set active, the system removes any existing order for the current calibration lot and places an order for the new lot. When this bug occurs, there is an order for the newly active calibration lot, and the previous (now inactive) lot. No impact. The customer may modify the auto-ordered calibrations.
Old Completed QC Sample Stuck in Result Processing Step, Delaying the Processing of New Results The control test result may remain in running status after the projected completion time, not reporting results until minutes later. While this test result is being processed, other new results (patients, controls, calibrators) may also have prolonged processing time. User is unable to immediately review test results until the prolonged processing is completed. Service can also correct with a script. See Executing Scripts Using the Service App for more information.
Opening DxS IntelliServe Configuration Screen Freezes UI for up to 1 minute The IntelliServe Connection page takes an unusually long time to load (approximately 1 minute). No action is needed, the service engineer simply needs to wait longer. No countermeasure.
Substrate Loader Mechanical Initialize Timeout System initialization could fail if the system is unable to retrieve supply information from the database within a time limit. This has only been observed in software automated testing, and is unlikely to occur on real systems. User may need to repeat initialization.
Disabled Pipettors Prevent Probe Cleaning and Test Scheduling If pipettors have been disabled by service and support, probe cleaning cannot occur and new tests will not start and there is not a clear indication on the user interface why that is the case. No impact. Users are directed in the IFU to use this screen only under supervision of technical support.
  1. Ensure all pipettors are enabled
  2. Initialize the instrument
  3. Either allow the system to automatically run priming, or manually trigger the priming
  4. After priming completion, disable pipettors are needed to prevent hard stops
Events Show Incorrect Reagent Pack Position After Barcode Reading Failure When an issue occurs loading a reagent pack, an event is created and the position is shown on screen to facilitate troubleshooting. The slot number displayed is off-by-one. They are labeled 1-4 but software considers these positions 0-3. No countermeasure. The user can identify the problem pack by loading them one at a time.
SPU Auto-Recovery: Critical Event and Red Light Bar Remain On After a successful SPU auto-recovery from an error, the system status will remain red until the user initializes the system. Initialize the instrument.
'Time Remaining' Display Issue At The Bottom Of The Screen For 'Lumi Drift' diagnostics No 'Time Remaining' is shown in the user interface task bar for 'Lumi Drift' diagnostic. It may be hard to predict for the user when the instrument will be available again for normal use. No countermeasure. User will not be able to predict how long until the luminometer drift diagnostic is going to take to finish. System will return to normal operation as soon as the diagnostic is completed.
Unintended Multiple Aliquots for Tests in Pending State When Rack is Represented The system incorrectly performs duplicate aliquots when a previously introduced sample is re-presented while its associated tests remain in the 'Queued' state. In this scenario, Falcon's logic misinterprets the re-presentation as a need for additional sample volume, leading to redundant aliquoting. This behavior deviates from the expected single-aliquot process and contrasts with the correct handling of re-presented samples when tests are in the 'Scheduled' state, where no further aliquoting occurs. No countermeasure. The system may aliquot more sample than is required. Tests will be run normally.
If Reflex and Rerun Rule are Both Triggered, Only One Is Ordered Successfully When multiple rule actions are configured for the same rule condition for example: * If the test is A, Rerun A. * If the test is A, Reflex B. And when a calculated test is configured (the calculated test expression should contain the tests that are being ordered as part of the rule actions) for example: CalTest = A+B Then sometimes due to a race condition, the rule action to create the reflex test may fail. As a workaround, user can create a single rule that reflexes test A & test B to achieve the same outcome. For example: If the test is A, reflex A & Reflex B with suppress checkbox uncheck. Rerun and Reflex actions should not be used together in the same rule. Only use the Reflex rule action with the Suppress option disabled if both Rerun and Reflex tests are needed for a single rule.
Reserve Volume Not Aliquoted for Combo tests when Default Reserve is Enabled for Parent Test but Not Constituent Tests The new reserve volume setup screen does not group combo test constituents (e.g. HIVCombo = HIVAg & HIVAb), which allows users to enable default reserve for the parent test without also enabling the constituent tests. If not enabled for all constituents, reserve volume will not be drawn. The user must individually check all test components when configuring reserve volume.
Manual Dilution Factor Not Applied to Addon Test When Ordered Before All Tests on Tube Complete Result processing is applying the manual dilution factor listed on the tube order instead of the dilution factor listed on each of the test order requests. This can be encountered when an additional order is placed for the same sample ID before all tests on the sample have been completed. In this situation, it allows the user to order a new test request with their configured dilution factor, but does not actually apply this dilution factor to the calculated result, although it will still show a label indicate a dilution factor was applied. Potential exists for the wrong dilution factor to be applied. Only the dilute and rerun button should be used for rerunning samples.
'Finish In Progress Tests' During Error Handling Preventing Instrument Pause In rare cases, the system may be stuck in Paused mode after a hardware error. No impact, system is already disabled by hardware error. User can recover with routine troubleshooting (reboot).
Hard Stop during Cancelation of Already Started Aliquot from Automation If the aliquot sample pipettor fails to rendezvous with the track to the sample wheel during sample dispense, the system handles this error poorly and causes the system to stop processing. The user must re-initialize the system to resume operation.
Don't Cancel Already Started Aliquot on AutomationTubeReleaseTimer Timeout If a system is completely out of tips, but then tips are loaded just before the automation tube timeout occurs, the aliquot can fail and the system will hard stop. User must reinitialize the system. Proactively add more tip trays before the system runs out completely.
Duplicate Menu Plugin Registration Leads to Fatal Startup Error Occasionally after switching PC users, the Console app fails to startup with a fatal error popup with the message "Menu is already registered". This appears to be due to an issue in the console code where duplicate menu plugins could potentially be registered. This only affects service users who may be performing tasks in the administrator profile. Restarting the PC can resolve the issue.
Test Requests Stack Indefinitely in Queued State after Vessel Manual Removal Under some conditions when a vessel is unexpectedly removed from the system (e.g. by a service engineer performing a recovery), or falls out of a pick and place, the system is unable to recover and schedule new tests. User must reinitialize the system.
Precision Sample Pipettor Reserved Indefinitely after PnP Error, Preventing Running Further Tests After one of APnP failures, system recovers to the green Running state, but stopped running any samples. The investigation showed that Precision SP was indefinitely reserved, preventing running any tests. System may not recover optimally after a pick and place error. User can re-initialize the system to restore normal operation.
Instrument in Indefinite Pausing while WW Rotating and Washing Indefinitely After APnP error, the Wash Wheel rotated indefinitely, preventing running any tests. After operator pushed the Paused button, the instrument stack in "Pausing" state. System may not recover optimally after a pick and place error. User can re-initialize the system to restore normal operation.
Samples Not Released at Track Direct Track Sampling (DTS) queue In rare cases, the DxI 9000 may fail to send a "Get Tube" to the track system, causing in samples to remain at the DTS location without notifying the user. Samples will remain queued at the DxI 9000 until a user notifies the problem and manually resets the queue.
Add-on Tests Don't Release the Rack when using Reserve Volume A sample rack can become locked to a specific sample after an add-on order is created when using reserve volume. The user can load and unload the problem rack to clear the issue.
LIS Download Status is not Reset to Pending when a Custom Reserve Add On is Canceled When the instrument is configured to use a Custom Reserve volume and receives add-on orders for a sample with insufficient volume to process the order, the instrument sends a cancellation message for part or all of the order. However, this message may not be understood by all LIS systems and the LIS may show the order as incomplete. This may cause user confusion. No countermeasure.
Not Able to Perform Service Login After Midnight UTC The service authentication tool cannot be used after UTC midnight, affecting ability to perform certain tasks protected by service password at certain times of day depending on system location. No countermeasure.
Audit Log Does Not Show All Entries Some software update log entries are not displayed on the audit log screen, but are still included in the audit log export. Export can be used to display the missing entries.
Set Calibration Inactive Fails to Update Disabled Combo Tests The luminometer service procedure may fail to fully update all assay calibrations after service. This could be detected by controls performed by Service or by the lab; but it may be missed and allow the lab to run samples on the system without recalibrating the assays. No impact. Activity can only be performed by service. Resetting Dift Targets procedure requires recalibration of all assays.
RSU Allows Arbitrary Version Install on First Update Post-Standalone The initial remote software update (RSU) of system software update on an instrument, after a standalone install in manufacturing, is allowed to be any version. This means it is possible to initiate an update for a previous software version. This only impacts the first install after the standalone install, since all RSU updates are tracked in the RSU database and downgrades are not allowed. An RSU installation is any installation that uses the ".bec" version of the installer. No impact. After leaving manufacturing, system must still be installed at customer site, during which the installation team will have control of the initial software version of the system.
Message Frequency Text Value Displayed is Not Updated Dynamically After User Changes It On the LIS configuration screen, clicking on the text box for the message frequency will pop open an input field and the on-screen keyboard. When the user changes the value in the pop up field and presses the 'Done' button, the main text box does not update even though the new value is saved. The correct new value is displayed properly if you close and re-open the configuration screen. No impact. Close and reopen the configuration screen after changing this value.
Tests not Started after Pick and Place Error Followed by Successful Recovery After some pick and place failures, the system recovers to the green Running state but stops running any samples. The software is not clearing the reservations on the subsystems, which causes scheduling of new tests to be blocked. Tests will not resume processing after an error recovery is attempted after pick and place errors. If this occurs, the system must be stopped and re-initialized to resume normal operations.
